# Sleep Cloud 视觉系统

## Brand & Style

一个**安静的、克制的、深夜色调的**睡眠大厅。视觉系统的唯一目标是：**让人在凌晨三点看着它的时候不觉得被刺激。**

- **气质**：安静、低刺激、有陪伴感。不是游戏，不是效率工具。
- **受众**：睡不着的人。他们在深夜使用，屏幕往往是周围唯一的光源。
- **情绪目标**：看到「有人和我一样醒着」；看到「有人在睡」。**不追求热闹、不追求成就、不追求效率。**
- **表现手法**：**单色线稿**为主，点缀极少量的暖色光。界面**只有一套配色**——夜晚色。**没有昼夜切换**：用户白天起床之后没有任何场景可做，明暗换挡只会破坏「深夜陪伴」的语义。
- **层级**：世界（画布）与界面（DOM）是两套渲染，但共用同一套令牌。

## Colors

只有夜晚一组。

- **Primary（`primary`）**：深蓝黑，整个大厅的夜空底色。不纯黑——纯黑会让线稿显得刺眼，也更容易暴露 OLED 屏的色阶断层。
- **Primary Dim（`primary-dim`）**：比底色更暗一档，**只用于「氛围光照」的最暗端**（见「明暗的边界」）。它不参与任何语义表达，只是地板底色在困倦度变化时能去的另一个端点。
- **Room（`room`）**：**房间地面**——每张床所在那一间的地。比走道亮一档，让「一格一间」在视觉上读得出来。
- **Rug（`rug`）**：**预留位**（每间房留给装饰物的那块空地）暂时按地毯画，再亮一档。
- **这两个都是「地」，不是语义通道**：它们与 `primary` / `paper` 一起构成一条**地面梯次**（见下），只表达「这块地和那块地不一样」；有主/无主、有人/没人一律靠轮廓与床号。
- **Secondary（`secondary`）**：比底色亮一档，用于浮在夜空上的界面（聊天面板、输入框、提示条、气泡底），**以及厅外那块底**——厅外与界面同底，读起来是「厅是一块放在底板上的房间」。厅外底色**不跟困倦度缓动**（它不是厅里的地板）。
- **Paper（`paper`）**：**世界材质色**——素材里「白色填充」映射成的颜色（床板、小人的白身体）。对底色约 **1.53:1**：足够看出「这里有一块有厚度的东西」，又不至于把线稿变成色块。**必须 ≤ 2:1**，否则线稿气质丢失。
- **Tertiary（`tertiary`）**：暖灯黄。**全系统唯一允许出现的暖色**，只用于**「这是我的床」的小标记**（自己的床角 + 自己小人脚下）。**不得用于整张床的轮廓**：它在冷底上比亮线更抢眼，会把「谁的床」排到「有人在睡」前面。
- **Neutral（`neutral`）**：接近白的冷灰。线稿的墨色与正文。
- **Neutral Muted（`neutral-muted`）**：次要文字、HUD、别人说的话、**世界里的床号**。
- **Line（`line`）**：床上**有活人**的轮廓、场景结构线。轮廓梯次里最强的一档。
- **Trace（`trace`）**：**睡痕**的轮廓与名字。明显低于活人一档——睡痕是「留在这里的痕迹」，不是「在场的活人」。
- **Claimed（`claimed`）**：**床空着**（有主与无主都用这一档）。轮廓梯次里最弱的一档。

**轮廓梯次必须单调且可辨**（WCAG 1.4.11 对图形对象要求 3:1）。在底色 `#0E1526` 上的实测对比度：

| 档 | token | 值 | 对比度 |
| :--- | :--- | :--- | :--- |
| 床上有人 | `line` | `#C9D2E6` | 12.0:1 |
| 睡痕 | `trace` | `#6E7996` | 4.2:1 |
| 空床（有主/无主） | `claimed` | `#5A6480` | 3.1:1 |
| 床板填充 | `paper` | `#313747` | 1.53:1（**不作为语义通道**） |

> 这三个数字用 WCAG 相对亮度公式算出，**未经目视校准**；真机低亮度下的可辨性属实测项。

**地面梯次**（同一套公式算出，同样未经目视校准）：

| 档 | token | 值 | 对比度 |
| :--- | :--- | :--- | :--- |
| 走道地板 | `primary` | `#0E1526` | 1.00（随困倦度暗到 `primary-dim`） |
| 房间地面 | `room` | `#182137` | 1.14:1 |
| 预留位（地毯） | `rug` | `#212C44` | 1.31:1 |
| 床板填充 | `paper` | `#313747` | 1.53:1（**不作为语义通道**） |

相邻两档的比值都在 1.14~1.17 之间（均匀），四档全部远低于 3:1——所以它读成「地上的深浅」，不会读成「另一类东西」。**房间地面与地毯是固定色**（不跟困倦度缓动）：随厅里的光变的只有**走道地板**，因为「厅里的光在变」，而 `room` / `rug` / `paper` 都是「材料」。

> 历史坑：最早的 `claimed` 取 `#3E4760`（1.97:1），设计意图是「最弱的一档」，但实际在夜里几乎看不见。**弱不等于不可见。**

状态色：

- **Alert（`alert`）**：可恢复错误的提示色。刻意选偏暖的低饱和红，避免在深夜里变成红色警报灯。
- **Live（`live`）**：表示「有人在线」的正向状态，只用于极小面积的点缀。

**配色纪律**：暖色总面积应小于屏幕的 5%。点睛色一旦变多，深夜的克制感立刻消失。

**明暗的边界（取代原「昼夜的边界」）**：

- 明暗**不由时钟驱动**，而由**全厅困倦度**驱动：`困倦度 = (睡着 + 睡痕) / (在线 + 睡痕)`。
- 它**只改走道地板的底色**（`primary` ⇄ `primary-dim`，约 1.5 秒缓动），**床与小人的墨色与纸色不变**（`room` / `rug` / `paper` 都是材料，一律不动）——这样「谁在睡、谁醒着」的可读性与暗色程度无关，不会出现「暗到看不清人」。
- **空厅兜底最亮档**（分母为 0 时不做变暗）。
- 幅度刻意小：宁愿「几乎察觉不到」，也不要「切换感」——任何随时间周期变化的明暗都会被读成昼夜替身。

## Typography

- 中文优先的系统字体栈。**不引入外部字体文件**——深夜加载字体造成的闪烁与延迟与产品气质相悖，且中文字体体积成本极高。
- `title`：入场层标题。
- `body`：面板与说明文字。
- `label`：按钮与控件标签、**世界里的气泡文字 / 名字 / 表情短标签**。
- `caption`：HUD 的辅助信息与**世界里的床号**——床号刻意比名字与气泡小一档：它是导航线索、一屏十几个。
- `numeric`：数字类信息（在线人数、床位号）。用等宽字体避免数字跳动。

**世界里的文字只有两档**（世界像素 = CSS 像素，别混）：**气泡文字、气泡上的名字行、表情短标签、人物名字**用 `label`（**13px**）；**床号**用 `caption`（**12px**）。消息只在世界里出现，所以**气泡文字就是本产品的内容文字，不得降到 `caption` 档**；反过来 `body`（15px）及以上也不进世界——气泡宽 200 世界像素，字号每大一档，两行能装的字就少一档。

面板与说明文字不低于 15px，深夜里不能太小。

## Layout & Spacing

**移动端优先。** 先在竖屏窄幅下定稿，再向上适配桌面——而不是先做桌面然后“适配手机”。主场景是一个人躺在床上、单手拿手机、竖屏、可能弱网、随时会锁屏。

断点（三个阶段就够，不要更多）：

| 阶段 | 宽度 | 主要形态 |
| :--- | :--- | :--- |
| 窄（主战场） | < 640px | 竖屏手机。世界全屏；聊天面板贴底常驻；HUD 收到顶部两角 |
| 中 | 640–1024px | 手机横屏 / 平板。聊天仍贴底，但宽度受限不被拉伸到全宽 |
| 宽 | > 1024px | 桌面。聊天靠右或靠下，世界居中，视野变宽 |

布局规则：

- **世界是全屏的**：画布铺满视口，界面浮在它之上。
- **界面占据边缘，不占据中心**：聊天在底部，HUD 在角上。**视野中央永远留给大厅本身**。
- **聊天是常驻的**，不是弹出层、不是二级菜单：常驻的是**输入行 + 表情行 + 床上动作行**（窄屏也不收进菜单）。**消息本身不进面板**——它只在世界里以气泡出现（8 秒），列表里的“历史”会变成全厅广播式的噪声，也分不清谁在跟谁说话。
- **面板高度只跟“控件行”有关**（输入行 + 表情行 + 私聊目标行 + 床上动作行），与消息条数无关。iPhone 16 竖屏下实测面板总高约 236px（≈28% 屏高）——**删掉消息列表后它会变矮，可用视口变大**（相机取景/夹取/死区都按可用视口算，见下面「可用视口」），所以改动后要复验一次取景而不是照抄旧数字。
- 间距用 4 的倍数：`xs` 4px、`sm` 8px、`md` 12px、`lg` 16px。
- 触摸目标不小于 `touch-target-min`（44×44px）。主要操作与输入框高度用 44px。
- 考虑安全区：刘海屏顶部与手势条底部需要内边距。
- 输入框聚焦时不得被软键盘遮挡（面板整体上移，而不是缩小世界）。

移动端的三个硬约束：

1. **输入框字号不得小于 16px**（故单独定义了 `input` 字号）。窄屏浏览器会在聚焦字号偏小的输入框时**自动缩放整个页面**，缩放后页面位置错乱且不会自动恢复。
2. **不做 hover 依赖**。手机没有鼠标悬停；任何“悬停才显示”的信息在手机上等于不存在。
3. **不禁止用户缩放页面**（禁用缩放是无障碍反问）。靠字号与布局避免误触缩放，而不是靠禁用它。

### 响应式基线与验证规格

**先按手机实现、先在手机上验收，再向上适配。** 基准设备固定为 **iPhone 16**，它是本项目的唯一验收规格：

| 项 | 值 |
| :--- | :--- |
| 基准设备 | iPhone 16 |
| 视口（CSS 像素） | **393 × 852** |
| 设备像素比 | 3（画布 DPR 上限 **3**，与设备像素 1:1） |
| 方向 | **竖屏优先**；横屏只要求不崩、不重排版 |
| 输入 | 触摸（单指拖拽、轻点） |
| **世界比例** | **固定 `ART_SCALE = 0.5`（素材像素 × 0.5 = 世界像素 = CSS 像素）** |

规则：

- **实现顺序**：先在 393×852 竖屏下把世界与界面的形态定下来，再向上适配中档与宽档。宽档只做「不退化」检查，不参与形态决策。
- **验证必须用手机视口**（393×852 / DPR 3 / 触摸）：轻点命中、拖拽平移、软键盘遮挡输入框、安全区。**桌面浏览器缩窄窗口不算通过。**
- **一屏内必须看得见自己周围的地面与相邻床位**：格 173×156（每格一间房、一张床）→ 手机一屏约 **2.3 格 × 4.6 行 ≈ 10 张床**（世界可见高约 572px）。同屏床数从 ≈17 降到 ≈10 是「不压抑」的直接代价。
- **床号必须一屏可读**（`caption` 档）：没有缩放，床号是世界里唯一的导航线索。
- 界面占据边缘、不占据中心：竖屏下顶部 HUD 与底部聊天面板之外，视野中央必须留给大厅本身。

### 世界相机

**没有缩放。** 世界与屏幕之间是一个固定比例：`ART_SCALE = 0.5`（素材像素 → 世界像素），1 世界像素 = 1 CSS 像素，画布按 DPR（上限 3，基准设备与设备像素 1:1）放大。

**世界里的文字按画布 DPR 栅格化**（`Text.setResolution`，床号 / 名字 / 气泡文字一律如此）：文字的绘制路径是「离屏 canvas 贴图 → 相机 zoom 放大」，栅格密度停在 1× 时会被放大采样而发虚——**气泡看着糊就是这一条**。气泡底、墙、床勾勒是几何绘制（顶点提交），不受影响。

| 项 | 决定 |
| :--- | :--- |
| 缩放 | **不存在**。没有捏合、没有滚轮、没有双击缩放；相机只有一个位置，没有 scale |
| 平移 | **单指拖拽平移**（轻点 = 意图，拖拽 = 看别处）。阈值：位移 < 8px 且时长 < 350ms 判为轻点 |
| 跟随 | 自己**正在走动**且走出屏幕中央区时温和跟随：**每帧按 `CAMERA_FOLLOW_PX_PER_S = 500` 与帧间隔 dt 匀速靠近**（约 0.5 秒追上 250px；**帧率无关**，单帧步进 = 500 × dt，60fps 下约 8.3px）；**停下即停**；拖拽期间不跟随。**不得用“逐帧固定比例”的 lerp**：那会让首帧按距离比例跳 20~33px（实测），且帧率一变速度就变 |
| 回中 | **点自己 = 相机对准自己**（一次性，不含走动）；**首次进厅**对准**我的床**（还没有床时对准出生点）；**断线重连后**对准**我的小人**（宽限恢复会把我放回原位，我的人可能在厅的另一头） |
| 瞬移落位 | 服务端把位置一步改到位时（「回我的床」，见 `../api/20-api-ws.md` §3）**直接落位、不插值**：单次位移 > 400px 的更新跳过插值窗口（否则会在 100 ms 内拉出一道横贯大厅的模糊线）。这是唯一的例外，常规位置一切照旧按 `ts` 插值 |
| 夹取 | 相机不越出**取景范围**（`scrollRegionOf` = 地板区 + 墙带 + 墙外一圈 56，见 `../design/20-layout.md` §3.2）：推到边缘时看见「**墙外的一圈底 + 墙带 + 地板**」——这才让墙读成一个实体边界（只夹到地板区的话，墙带会整条落在屏幕外；只夹到墙外沿的话，墙又永远贴着屏幕最外圈、只像一条细线）。可见区大于取景范围时居中。**竖屏下的垂直夹取按「可用视口」算**（见下），否则最底一行永远在聊天面板之下——走不到也点不到 |
| 尺寸变化 | 旋屏 / 地址栏收放后只重算死区与夹取，**不重算比例**（比例是常量） |
| 裁剪 | **可视窗口 + 对象池**：每帧由 `camera.worldView` 算出可见的床号范围（±1 行/列缓冲），把池里的对象绑到这些床上。**同屏约 10 张床（+ 小人与床号标签），与厅规模（117 ~ 9558）无关** |

为什么不做缩放：一般 2D 角色扮演游戏也不缩放界面；而缩放会立刻带出「默认比例取多少、夹取怎么算、旋屏怎么重算、双指与单指如何分工」一整串问题，且**在手机上放大到 0.35 倍也看不清整厅**——它的价值远大于代价。取而代之的是：**床号常显 + 我的床标记 + 点自己回中**。

**「可用视口」是相机的取景基准**：世界层只**读** DOM 的实际高度（顶部 HUD 与底部聊天面板，用 `getBoundingClientRect` + `ResizeObserver`），可用视口 = 视口 − 顶 − 底（393×852 竖屏下约 **723px** 高）。取景中心、夹取范围、死区都按它算：

- 垂直夹取按可用高度 → **最底一行能滚到面板之上**，点得到也走得到；
- 死区按可用区居中 → 跟随时人物留在看得见的那条带里；
- **不要硬编码高度**：面板高度随消息条数与窄/宽档变化。

**「不跳」的验收口径**（写清楚，避免测量口径之争）：

| 对象 | 判据 |
| :--- | :--- |
| 小人的**绘制位置**（世界坐标） | 单帧位移不得 ≥10px（正常帧为 `WALK_SPEED_PX_PER_S × dt`） |
| **相机**（屏幕滚动量） | 单帧步进 ≤ `CAMERA_FOLLOW_PX_PER_S × dt`（60fps 下约 8.3px） |

只按「屏幕像素」量会把相机自身的滑动算成「小人跳」——两者必须分开量（小人按世界坐标、相机按滚动量）。

## Elevation & Depth

**不制造深度感。** 这是一片平铺的夜色，不是有层次的界面。

- 不用阴影表达层级。层级用**亮度差**（`primary` 与 `secondary`）和**边框**表达。
- 浮层（错误提示）用底色加边框，不用投影。
- 世界本身没有阴影：床位、小人、墙都是平铺线稿，靠**绘制顺序（按 y 排序）**解决遮挡，不靠阴影或加粗描边。

## Shapes

- **线稿是等宽的**：小人、床用同一线宽（素材本身自带的线宽，构建期不再改），靠形态区分，不靠粗细。**墙除外**：它是 `WALL_WIDTH = 3px` 的墙带（画在墙矩形之外）——1.5px 的细线在手机上几乎看不见，而「走到边缘要看得见墙」是硬要求（见「世界相机」与 `../design/20-layout.md` §2）。
- 圆角只出现在界面控件上：`sm` 用于小标记，`md` 用于面板与输入框，`lg` 用于入场层，`full` 用于主要操作按钮。HUD 是贴顶的通栏，不画圆角。
- **小人造型来自素材**（`WheatCloudSleep` 的 `Boy` / `Girl`：大头、点眼、简化四肢）。**不做逐帧行走动画**——走动靠极轻微的缩放摆动（呼吸感）表达，与参考实现一致：幅度 3%、频率 **4.5 Hz**。这是整套视觉里辨识度最高的一笔，不要改。
- 躺姿是**素材里的一张整图**（床 + 被子 + 只露的脸），不是「把人画在床图上」：因此「空床 / 有人（男）/ 有人（女）」是三个独立贴图，而不是三层叠加。
- **睁眼躺姿暂时靠代码叠两个点**（素材只有闭眼的那一张）；补画后替换为贴图（见 `../design/backlog.md`）。

**构建期要产出的变体**（5 张母图 → 8 张贴图：两色渐变映射 + 裁到墨迹 bbox + 打进一张图集）：

| 贴图 | 源 | 白填充映射为 | 黑线映射为 |
| :--- | :--- | :--- | :--- |
| `bed_empty_hollow` | `bedEmpty` | **透明**（空芯） | `claimed` |
| `bed_empty_owned` | `bedEmpty` | `paper` | `claimed` |
| `bed_boy` / `bed_girl` | `bedBoy` / `bedGirl` | `paper` | `line` |
| `bed_boy_trace` / `bed_girl_trace` | 同上 | `paper` | `trace` |
| `boy_stand` / `girl_stand` | `Boy` / `Girl` | `paper` | `neutral` |

睡痕的两张在运行时再乘一个不透明度（不是单独的贴图变体）。**素材本身是 2 色 + 抗锯齿灰**，所以映射必须按亮度插值（渐变映射），不能只替换两个色值——否则边缘会烂成锯齿。素材许可与出处见 `README.md`。

**气泡不走素材**（历史教训）：上游那两张气泡图是小尺寸的界面素材（36×30 与 23×27，竖直描边只有 1–2px 且带抗锯齿）。为了跟文字宽度对齐而**横向拉伸**它，会把那 1–2px 的竖直描边拉成 5–10px 的半透明带 —— 实测左右两边发虚（上下边只做纵向缩放，所以看起来正常）。所以气泡改成**程序化绘制**：一个圆角矩形（`setRounded`）+ 一个三角尾巴，1px 描边、位置取整，任何尺寸都不糊；这与「几何是程序化生成的」是同一条思路（床与人用素材，是因为它们有手绘造型）。

**管线顺带产出一份 `public/sprites/frames.css`**（每帧一条 `background-position`）：入场层的形象预览要拿图集里的 `boy_stand` / `girl_stand` 当图片用，而图集坐标只能有**一个**来源（管线），不能在 CSS 里再拄一份。

## Components

| 组件 | 要点 |
| :--- | :--- |
| `world` / `world-ambience` | 世界画布。铺满视口，只画场景、床位、小人，以及**贴在世界对象上的文字**（床号、名字、气泡——聊天也在世界里）——**不画任何界面控件**（按钮 / 面板 / 列表）。**地板分三层**：走道是 `primary`（在 `primary` ⇄ `primary-dim` 之间按困倦度缓动）、每间房的地是 `room`、预留位是 `rug`（后两层固定色）；墙是 3px 墙带（沿地板区边界画在外侧）；**墙外那圈用 `secondary`** 与厅内区分 —— 相机可以滚到墙外一圈，所以**手机上推到边缘就能看见它** |
| `world-material` | 素材里「白色填充」的映射目标（`paper`）：床板与小人的白身体。对底色 1.53:1，**不是语义通道** |
| `bed-number` | **每张床常显的床号**：`neutral-muted`，`caption` 档，画在床的角落。它是没有缩放之后唯一的导航线索。**显示值 = 内部床号 + 1**（内部从 0 起，只在这里换算，见 `../design/00-master-design.md` §3） |
| `bed-occupied` / `bed-claimed` / `bed-trace` | **轮廓只回答「床上有人吗」**（完整真值表见下）。`bed-empty-hint` 是「可躺的空床」被点中时的瞬时反馈色 |
| `marker-own` | **属于我的标记**：自己的小人脚下、自己的床位角落共用（一处概念、两处落地）。它与轮廓正交——所以暖灯色不需要参与轮廓梯次排序 |

**床位轮廓真值表**（不得把两个维度合并成一个「床位状态」）：

| 情形 | 轮廓（占用） | 填充（归属） | `marker-own` | 床号 | 名字 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| 无主空床 | `claimed` | **空芯**（只有线，没有纸） | 无 | 画 | 不画 |
| 别人的床，空着 | `claimed` | `paper` | 无 | 画 | 不画 |
| 我的床，空着（我在厅里走动） | `claimed` | `paper` | **有** | 画 | 不画 |
| 别人的床，有人在睡 | `line` | `paper` | 无 | 画 | 画 |
| 别人的床，睡痕 | `trace` | `paper`（整张图降低不透明度） | 无 | 画 | 画，更暗 |
| 我的床（我自己躺着） | `line` | `paper` | **有** | 画 | **不画**（我知道我是谁） |

**谁能躺**：**任何无主空床都能躺**（躺下即认领）；自己的床任何时候都能躺。**我已有别的床时再点一张无主空床 = 换床**（旧床当场释放，距上次认领不足 10 秒会被拒：`3008`，可见提示）；**在床上点别的空床 = 自动起身后过去**（一条命令，同「点地面」）；点**别人的**床被拒（`3003`）；点自己正躺着的那张床什么都不做（`3004`，静默）。每张床都常显床号 + 我的床有暖标记，正是为了让你能回到自己那张。

**为什么「有主 / 无主」走填充而不走第四档颜色**：颜色梯次只能容纳三档。夜色下 `line` 12.0:1 > `trace` 4.2:1 > `claimed` 3.1:1 已经把「弱到还看得见」用尽——再插一档要么低于 3:1（重犯当初 `claimed` = 1.97:1 的历史坑），要么与相邻档分不开。

**为什么不是线型**（原设计用的是「无主虚线 / 有主实线」）：那是「轮廓由代码画」时代的方案。现在床是**素材里的一整张图**（黑线与白填充一起被渐变映射），线型没法只替换线条——要么在图上再叠一个虚线框（会和素材自带的床头、侧栅打架），要么在素材里做两套轮廓。**改用填充**：无主空床的白色填充映射成**透明**（空芯，地板直接透出来），有主床映射成 `paper`。这条通道的优势是**面积**——整个床内区域都在变，而 1.53:1 的细线差是弱通道；大面积的亮度差在低对比度下依然可辨。

配套约束：

- **睡痕整张图降低不透明度**（床与小人都降，不能只改轮廓与名字，否则「睡痕」与「睡着」只差颜色）
- **空芯变体必须是「白 → 透明」而不是「白 → `primary`」**：地板底色会随困倦度缓动，写死底色会在暗档时露出一块补丁
- **轮廓与填充都不影响可点击性**：命中区域是床的占位区，与画法无关
- **`marker-own` 有最小屏幕尺寸下限**：不得消失，否则「找不到我的床」
- **可躺（空芯）是一条弱通道**：它靠 1.53:1 的面积差。真机上若判「看不出来」，补救顺序是 ① 加大 `paper` 与底色的差；② 在无主空床的床角加一个 `claimed` 色的小标记（**不动几何**）。实测项记在 `../design/backlog.md`

### 名字什么时候出现

名字是身份信息，不是陪伴信息。**「看到有人和我一样醒着」靠的是看到人本身。**

| 对象 | 名字 | 理由 |
| :--- | :--- | :--- |
| 躺在床上的人（含睡痕） | **始终显示**（裸标签）；被选中时改成气泡样式，**不额外叠第二个** | 床的位置稳定，标签不会飘；而「这是谁的位置」本身就是产品要表达的 |
| 漫游中的人（站着/走动） | **默认不显示**；被选中时显示唯一一个名字气泡 | 几十个人就是几十个随风飘的标签，画面会立刻变吵 |
| 自己 | **一律不画**（地上与床上都不画），靠 `marker-own` 识别 | 我知道我是谁。而且地上不画、床上却画是不对称的 |

**床号与名字的关系**：床号是**位置信息**，每张床都画；名字是**身份信息**，只在床上有占用者时画。两者都不是「界面」，都画在世界里。

**选中态是一个概念、服务两件事**：点中某个小人（或床上的人）→ 他成为选中对象 **且** 成为私聊目标。同一时刻只有一个选中对象（因此只有一个气泡），点地面则取消选中并走动。

**头顶只有一个槽位**（不是三个各管各的气泡）：**聊天 > 表情 > 选中名字**——聊天/私聊出现时占着它，到点回落给表情，再回落给名字。床上的人名字常显在下方那一条，不跟着抢占槽位；比对到自己的名字永远不画。
- **选中即私聊目标**：面板上方出现「私聊 阿夜 ×」；点 × 取消选中。目标离开大厅时**自动取消选中**。
- **表情是常驻一行的按钮**（一次点击即发出，不进二级菜单），表现是**世界内的气泡**（与聊天气泡同一套画法与槽位，`EMOTE_MS` 后消失）。气泡里显示与按钮一致的中文短标签。
- **聊天与私聊也是气泡**（`CHAT_BUBBLE_MS` = 8 秒）：同一个人后来的消息**覆盖**前一条并重置计时（不排队、不堆叠）；宽度上封顶 `CHAT_BUBBLE_MAX_PX`（200 世界像素），最多两行、超出截断加 `…`；私聊只在收发双方头上出现，并加一个「悄悄话」前缀（**不另开一档颜色**：少一个语义通道就少一处要记住的规则）。

**床上动作只在床上出现**：「起身 / 睡了」两个按钮仅在自己躺在床上时占位，不躺着的时候它们是空的——界面上不留没有对象的按钮。

## Do's and Don'ts

**Do**

- 把视野中央留给大厅本身，界面只占边缘。
- 用亮度差与边框表达层级，不用阴影。
- 睡痕必须一眼可辨——它比在线者暗得多，这是「这里曾有人睡过」的全部表达。
- 把床位的**归属**与**占用**当成两个独立维度推导，不要合并成一个「床位状态」。
- 无主空床必须画出来（`claimed` 线 + **空芯**）：它是「这里还没人认领」的唯一提示，也是新人找不到床时的唯一依据。
- 占用用颜色、归属用填充。不要为归属新开一档颜色。
- 空芯变体必须把白色映射成**透明**，不能写死成地板底色（地板会随困倦度缓动）。
- **每张床都画床号**（`neutral-muted`）：没有缩放之后它是唯一的导航线索。
- **「是我的」靠一个独立的小标记**，不要用轮廓颜色表达。
- 有主但空的床只画轮廓与床号、**不写名字**；名字只出现在床上有人的时候。
- 暖色只用在「这是我的床」的标记上。
- 世界渲染用**可视窗口 + 对象池**：只给相机视野内的那几十张床建对象。
- 地板的底色可以随困倦度微微变化，但**床与小人的墨色不要跟着变**。
- **房间地面与预留位用固定色**（`room` / `rug`）：它们和床板（`paper`）一样是「材料」，不跟着厅里的光变。

**Don't**

- 不要用高饱和像素风或鲜艳渐变。那会让一个失眠大厅变吵闹。
- 不要用红色警报类配色做错误提示。
- 不要把聊天藏进弹出层或二级菜单。
- 不要把表情藏进二级菜单：它是一行常驻按钮，点一下就该发出去。
- 不要让地上的小人常显名字（几十个飘动的标签会把大厅变成名单）。
- 不要在渲染聊天消息时临时去查人名（对方离开后那行名字会变空）——追加时就固化。
- 不要把暖灯色用于整张床的轮廓（它在冷底上比亮线更抢眼，会颠倒「有人睡 > 谁的床」的优先级）。
- 不要让轮廓梯次的相邻两档靠得太近（弱不等于不可见，也不等于分不清）。
- 不要把无主空床画成「不画」：那样新人进厅只看到空地板，「看见床位 → 挑一张躺下」这条核心循环就没有入口。
- 不要用「更暗的第四档颜色」表达归属：深底上做不出既单调又都 ≥3:1 的四档。
- 不要在床图上叠虚线框来做「无主」标记：素材自带床头与侧栅，叠上去会打架。归属走填充（空芯 / `paper`）。
- 不要让 `paper` 填充超过 2:1：再亮就把线稿变成色块。
- 不要给睡着的人做逐帧呼吸动画——用整体透明度的低频变化代替（几百个睡着的人逐帧动画会吃掉手机 CPU）。
- 不要引入外部字体文件。
- 不要把**界面控件**（按钮 / 面板 / 列表）画进画布，也不要在 DOM 里重画世界：床号、名字、气泡都是**贴在世界对象上的文字**（跟人走、跟床走），不是界面。
- 不要给每张床都写名字（那是名单，不是大厅）。
- 不要先做桌面再“适配”手机。
- 不要把重要信息做成“悬停才显示”——手机上不存在悬停。
- 不要让输入框字号低于 16px（会触发窄屏浏览器的页面自动缩放）。
- 不要禁用用户缩放页面。
- 不要按设备像素比 1 渲染画布（窄屏高密度屏上会糊），也不要无上限地按比值渲染（低端机扛不住）。
- **不要让世界里的文字停在 1× 栅格密度**：相机 zoom = 画布 DPR（>1），床号 / 名字 / 气泡文字都会被放大采样而发虚；按 DPR 栅格化，与画布同一个比值。
- 不要用桌面浏览器缩窄窗口代替手机视口验收（393×852 / DPR 3 / 触摸）。
- **不要引入缩放**（捏合 / 滚轮 / 双击归一）：找床靠床号与标记，不靠缩小看全厅。
- **不要用 `Tilemap`**：几何是程序生成的，没有 Tiled 数据、没有地形类型、碰撞在服务端。
- **不要给床或小人开 `setInteractive`**：命中判定走「屏幕 → 世界 → 槽位」的纯函数（可单测）。
- **不要启用物理引擎**：位置是服务端权威 + 客户端插值。
- **不要让明暗随时间周期变化**：那会被读成昼夜替身。
- **不要让 `room` / `rug` 跟着困倦度缓动**：地板变暗而房间不变，那两块贴片会「浮」在夜色上。
