# Sleep Cloud 视觉系统

## Brand & Style

一个**安静的、克制的、明色调的**睡眠大厅。视觉系统的唯一目标是：**让人在睡不着的时候看着它不觉得被刺激。**

- **气质**：安静、低刺激、有陪伴感。不是游戏，不是效率工具。
- **受众**：睡不着的人。他们的**心理时间**不由时钟决定——可能是凌晨三点，也可能是午睡前的白天——所以**配色不读时钟**。
- **情绪目标**：看到「有人和我一样醒着」；看到「有人在睡」。**不追求热闹、不追求成就、不追求效率。**
- **表现手法**：**单色线稿**为主，点缀极少量的暖色。界面**只有一套配色**——明色调基底；明暗由**用户自己的行为**（漫游 / 躺下 / 睡下）驱动三档（见「三档色调」）。**没有昼夜**：任何按时间周期变化的明暗都会被读成昼夜替身。
- **层级**：世界（画布）与界面（DOM）是两套渲染，但共用同一套令牌。

## Colors

只有明色调一组：**低饱和冷灰**（色相 ≈215°、饱和 ≈10%）。**换色相时必须保持每个令牌的相对亮度**，否则下面那三张地面梯次表与轮廓梯次表全部作废。**地面梯次只抬亮度轴、不改相对关系**（走道 < 房间 < 预留位 < 床填充），所以「一格一间」的读法不随配色变。

- **Primary（`primary`）**：冷浅灰，走道地板、HUD 底与输入框底。**不取近白**——纯白底会把线稿冲成色块，也会让整屏成为手机上最大的光源。
- **Room（`room`）**：**房间地面**——每张床所在那一间的地。比走道亮一档，让「一格一间」在视觉上读得出来。
- **Rug（`rug`）**：**预留位**（每间房留给装饰物的那块空地）暂时按地毯画，再亮一档。
- **这三个是「地」，不是语义通道**：它们与 `paper` 一起构成一条**地面梯次**（见下），只表达「这块地和那块地不一样」；有主/无主、有人/没人一律靠轮廓与床号。
- **Secondary（`secondary`）**：比地板亮一档的**界面面**（聊天面板、输入框、提示条、气泡底、设置浮层）。**刻意不是全场最亮的面**：它常驻、全宽，做成纸白就成了手机上最大的一块亮面。
- **Outside（`outside`）**：**厅外的台面**——相机背景色，也是入场层的满屏底。**它不是第四档地**，比地板暗一档：厅读起来是「被照亮的一块地放在较暗的台面上」，相机推到边缘时也不会出现一圈比厅更亮的光。
- **Paper（`paper`）**：**世界材质色**——素材里「白色填充」映射成的颜色（床板、小人的白身体）。对地板约 **1.33:1**：能看出「这里有一块有厚度的东西」，又不至于把线稿变成色块。**必须 ≤ 2:1**。
- **Tertiary（`tertiary`）**：**深赭**。**全系统唯一允许出现的暖色**，只用于**「这是我的床」的小标记**（自己的床角 + 自己小人脚下）。亮底上不能沿用暖黄（暖黄衬地板只有 2.55:1，看不见）；**不得用于整张床的轮廓**：它会比墨线更抢眼，把「谁的床」排到「有人在睡」前面。
- **Neutral（`neutral`）**：深冷墨。线稿的墨色与正文。
- **Neutral Muted（`neutral-muted`）**：次要文字、HUD、别人说的话、**世界里的床号**。它要在最暗档仍过 12px 的 4.5:1，所以比「看起来该有的弱」更深一档。
- **Line（`line`）**：床上**有活人**的轮廓、场景结构线、墙。轮廓梯次里最强的一档。
- **Trace（`trace`）**：**睡痕**的轮廓与名字。明显低于活人一档——睡痕是「留在这里的痕迹」，不是「在场的活人」。**注意**：整图再乘 0.45 不透明度之后有效对比度只有 1.75:1（见下表「有效值」列）；这是「睡痕要退后」的代价，修法记在 `../design/backlog.md`。
- **Claimed（`claimed`）**：**床空着**（有主与无主都用这一档），以及界面控件的描边。轮廓梯次里最弱的一档。

**轮廓梯次必须单调且可辨**（WCAG 1.4.11 对图形对象要求 3:1）。墨同时压在**地板**与**床填充**上，所以每一档要分别过两个底：

| 档 | token | 值 | 衬地板 | 衬床填充 `paper` | 有效值（睡痕 ×0.45） |
| :--- | :--- | :--- | :--- | :--- | :--- |
| 床上有人 | `line` | `#31353C` | 8.42:1 | 11.18:1 | — |
| 睡痕 | `trace` | `#5B636F` | 4.13:1 | 5.48:1 | **1.75:1** |
| 空床（有主/无主） | `claimed` | `#6C7785` | 3.12:1 | 4.14:1 | — |
| 床板填充 | `paper` | `#F4F4F6` | 1.33:1（**不作为语义通道**） | — | — |

> 数字用 WCAG 相对亮度公式算出，**未经目视校准**；真机低亮度下的可辨性属实测项。**两列都必须 ≥3:1**——只验证「衬地板」会漏掉描边压在自己填充上的那一半。

**地面梯次**（同一套公式算出，同样未经目视校准）：

| 档 | token | 值 | 对比度 |
| :--- | :--- | :--- | :--- |
| 走道地板（HUD 底） | `primary` | `#D3D6DB` | 1.00 |
| 界面面 | `secondary` | `#E2E4E7` | 1.14:1 |
| 房间地面 | `room` | `#DCDEE2` | 1.09:1 |
| 预留位（地毯） | `rug` | `#E5E7E9` | 1.17:1 |
| 床板填充 | `paper` | `#F4F4F6` | 1.33:1（**不作为语义通道**） |
| 厅外台面 | `outside` | `#C2C7CD` | 1.17:1（**不是地**） |

相邻两档的比值都在 1.09~1.33 之间（明底比暗底压缩），整列远低于 3:1——所以它读成「地上的深浅」，不会读成「另一类东西」。**`room` / `rug` / `paper` 与地板一起被三档整体减光**（一层覆盖整屏），不为它们单独留第二套色值。

**弱不等于不可见**：轮廓梯次里最弱的一档仍需 ≥3:1；「看起来该弱」不能成为低于门槛的理由。

状态色：

- **Alert（`alert`）**：可恢复错误的提示色。偏暗的低饱和红，衬面板 5.00:1。
- **Live（`live`）**：表示「有人在线」的正向状态，只用于极小面积的点缀（衬面板 4.73:1）。

**配色纪律**：暖色总面积应小于屏幕的 5%。点睛色一旦变多，克制感立刻消失。

**三档色调**（由用户自己的行为驱动，不读时钟）：

- 档 = **我的显示态**：`roaming`（站立/漫游）→ `0`、`lying`（睁眼躺着）→ `0.12`、`asleep`（睡着）→ `0.22`。
- 落地是**一层全屏叠加**（中性黑、`opacity` 跟随档位、约 0.9 秒过渡）：**界面也一起暗**，因为界面也是亮面；画布内滤镜盖不到 DOM，三套令牌又要重设每一个世界文字对象，所以只有这一种同源做法。
- **不设「基础减光」**：令牌值就等于最亮档的屏上值，之后所有对比度算式只多一个 α。
- **入场层不参与**（它不属于厅里的档）；首帧与重连**不缓动**（直接落档，避免「从最亮渐暗」的假动画）。
- **α 的上限由最小的字决定**：`neutral-muted` 在 α=0.22 时衬地板 4.57:1（12px 的 AA 门槛 4.5），α=0.25 掉到 4.40 → 除非同时把 `neutral-muted` 再压深，否则不许超过 0.22。
- 为什么不是「全厅困倦度」：那会变成两条光轴——一条是我自己的、可预期的，一条是别人的、随人进出抖动；**一条视觉通道只能有一个驱动**。「大家都睡下了」由画面里的睡着者与睡痕本身表达，不靠亮度。
- **任何随时间周期变化的明暗都不许出现**：那会被读成昼夜替身。

## Typography

- 中文优先的系统字体栈。**不引入外部字体文件**——低亮度下加载字体造成的闪烁与延迟与产品气质相悖，且中文字体体积成本极高。
- `title`：入场层标题。
- `body`：面板与说明文字。
- `label`：按钮与控件标签、**世界里的气泡文字 / 名字**。
- `caption`：HUD 的辅助信息与**世界里的床号**——床号刻意比名字与气泡小一档：它是导航线索、一屏十几个。
- `numeric`：数字类信息（在线人数、床位号）。用等宽字体避免数字跳动。

**世界里的文字只有两档**（世界像素 = CSS 像素，别混）：**气泡文字、气泡上的名字行、人物名字**用 `label`（**13px**）；**床号**用 `caption`（**12px**）。消息只在世界里出现，所以**气泡文字就是本产品的内容文字，不得降到 `caption` 档**；反过来 `body`（15px）及以上也不进世界——气泡宽 200 世界像素，字号每大一档，两行能装的字就少一档。

面板与说明文字不低于 15px，低亮度下不能太小。

## Layout & Spacing

**移动端优先。** 先在竖屏窄幅下定稿，再向上适配桌面——而不是先做桌面然后“适配手机”。主场景是一个人躺在床上、单手拿手机、竖屏、可能弱网、随时会锁屏。

断点（三个阶段就够，不要更多）：

| 阶段 | 宽度 | 主要形态 |
| :--- | :--- | :--- |
| 窄（主战场） | < 640px | 竖屏手机。世界全屏；聊天面板贴底常驻；HUD 收到顶部两角 |
| 中 | 640–1024px | 手机横屏 / 平板。聊天仍贴底，但宽度受限不被拉伸到全宽 |
| 宽 | > 1024px | 桌面。聊天靠右或靠下，世界居中，视野变宽 |

布局规则：

- **世界是全屏的**：画布铺满视口，界面浮在它之上。
- **界面占据边缘，不占据中心**：聊天在底部，HUD 在角上。**视野中央永远留给大厅本身**。
- **聊天是常驻的**，不是弹出层、不是二级菜单：常驻的是**动作行（床号 / GO / 缩放档位 / 齿轮）+ 输入行（含表情切换键）+ 床上动作行**（窄屏也不收进菜单）。表情行**与输入行共用同一行位置**——点切换键时输入行原地换成 emoji 行，再点一下换回来。消息本身不进面板：它只在世界里以气泡出现（8 秒），列表里的“历史”会变成全厅广播式的噪声，也分不清谁在跟谁说话。
- **面板高度只跟“控件行”有关**（输入行 / 表情行**共用一行** + 动作行 + 私聊目标行 + 床上动作行），与消息条数无关。表情面板展开 / 收起**不改面板高度**，所以切换时世界不会抖。数字：视口 **393×852** 下**站立、连接正常时约 121px**（不含安全区）= 1px 上边框 + 12px 内边距 + 44px 动作行 + 8px 间隙 + 44px 输入行 + 12px 内边距（**动作行搬进面板后必须重测**）；躺下多一行动作 + 52px，断连提示条再 +52px，`GO` 输入行 / 换床提示行再 +52px——**改了控件行就要重测并复验取景**（相机取景 / 夹取 / 死区都按可用视口算，见下面「可用视口」），不要照抄数字。
- 间距用 4 的倍数：`xs` 4px、`sm` 8px、`md` 12px、`lg` 16px。
- 触摸目标不小于 `touch-target-min`（44×44px）。主要操作与输入框高度用 44px。
- 考虑安全区：刘海屏顶部与手势条底部需要内边距。
- 输入框聚焦时不得被软键盘遮挡：**整个底部组合（聊天面板 + 插槽面板）挪到 HUD 下方**，而不是抬到键盘上沿——顶部与键盘天然不重叠，所以**界面不需要知道键盘多高**（这一点很关键：部分内核里键盘高根本测不出来）。世界不跟着缩、也不跟着动。代价是**打字时输入框在屏幕顶部**，眼睛要在顶部与键盘之间移动；换来的是整条键盘链路消失，包括画布闪烁与“内核缩不缩视口”那类问题（`../design/60-interaction-shell.md` §2、§5）。**触发这一切的是「输入会话状态」，不是焦点本身**，且打字态右端常驻一枚 44px「收起」胶囊作为出口。

移动端的三个硬约束：

1. **输入框字号不得小于 16px**（故单独定义了 `input` 字号）。窄屏浏览器会在聚焦字号偏小的输入框时**自动缩放整个页面**，缩放后页面位置错乱且不会自动恢复。
2. **不做 hover 依赖**。手机没有鼠标悬停；任何“悬停才显示”的信息在手机上等于不存在。
3. **不禁止用户缩放页面**（禁用缩放是无障碍反问）。靠字号与布局避免误触缩放，而不是靠禁用它。

### 响应式基线与验证规格

**先按手机实现、先在手机上验收，再向上适配。** 基准设备固定为 **iPhone 16**，它是本项目的唯一验收规格：

| 项 | 值 |
| :--- | :--- |
| 基准设备 | iPhone 16 |
| 视口（CSS 像素） | **393 × 852** |
| 设备像素比 | 3（画布 DPR 上限 **3**，与设备像素 1:1） |
| 方向 | **竖屏优先**；横屏只要求不崩、不重排版 |
| 输入 | 触摸（单指拖拽、轻点） |
| **世界比例** | **固定 `ART_SCALE = 0.5`（素材像素 × 0.5 = 世界像素 = CSS 像素）**；相机在此之上可以**拉远**到 `ZOOM_MIN = 0.175`（**只缩不放，上限 1×**） |

规则：

- **实现顺序**：先在 393×852 竖屏下把世界与界面的形态定下来，再向上适配中档与宽档。宽档只做「不退化」检查，不参与形态决策。
- **验证必须用手机视口**（393×852 / DPR 3 / 触摸）：轻点命中、拖拽平移、软键盘（遮挡、人还在不在视野里、收起后是否跳）、安全区。**默认在宿主 Android 模拟器里验（其余画面见 `../design/test.md` §2）；桌面浏览器缩窄窗口不算通过。**
- **一屏内必须看得见自己周围的地面与相邻床位**：格 173×156（每格一间房、一张床）→ 手机一屏约 **2.3 格 × 4.6 行 ≈ 10 张床**（世界可见高约 572px）。同屏床数从 ≈17 降到 ≈10 是「不压抑」的直接代价。**拉远到下限（0.175）时一屏约 190 个床位**：同屏床数只取决于相机比例、与厅规模无关。
- **床号必须一屏可读**（`caption` 档）：1× 下床号是世界里主要的导航线索（拉远后文字退役，见「世界相机」）。
- 界面占据边缘、不占据中心：竖屏下顶部 HUD 与底部聊天面板之外，视野中央必须留给大厅本身。

### 世界相机

**世界只缩不放。** 世界与屏幕之间是一个固定比例：`ART_SCALE = 0.5`（素材像素 → 世界像素），1 世界像素 = 1 CSS 像素，画布按 DPR（上限 3，基准设备与设备像素 1:1）放大；相机在这之上可以**拉远**（相机 zoom = DPR × Z，`Z ∈ [0.175, 1]`）。**上限就是 1×**：不放大，所以画布位图永远不会被放大采样（捏合缩放不改变 `devicePixelRatio`，放大必然发虚——只缩不放从根上避开它）。

**世界里的文字按画布 DPR 栅格化**（`Text.setResolution`，床号 / 名字 / 气泡文字一律如此）：文字的绘制路径是「离屏 canvas 贴图 → 相机 zoom 放大」，栅格密度停在 1× 时会被放大采样而发虚——**气泡看着糊就是这一条**。气泡底、墙、床勾勒是几何绘制（顶点提交），不受影响。

| 项 | 决定 |
| :--- | :--- |
| 缩放 | **只缩不放，上限恒为 1×**。两种模式（`store.zoomMode`，客户端本地状态；**显式锁定的档持久化在本地存储**，整页重载后恢复，见 `../design/40-client-storage.md`）：**自由缩放** = 双指捏合连续缩放（锚在两指中点），区间 `Z ∈ [ZOOM_MIN = 0.175, 1]`；**固定档** = 比例**锁死在那一档**，捏合不改比例（捏合产生的平移与锚点补偿照旧）。档位表 `ZOOM_TIERS`（见 `../design/config.md` §3）：`全厅 0.175` / `0.5×` / `0.75×` / `1×`；入口是动作行那颗胶囊（文案 = 当前档位，点开是门控行里的选项，见 `action-row` / `zoom-picker`）。**没有放大、没有滚轮、没有双击归一**（双击要等 300ms 才能确认不是单击，会把每一次「点地面走路」都拖慢） |
| 固定档的下限 | 档位表里最小的一档是 **0.5×**，它正好是文字退役阈值 `ZOOM_TEXT_MIN`——**固定档永远不会把文字画没**；再往下只有「全厅」（0.175，那里本来就不画文字，用户不会以为是缩小把字弄没的）。**0.5× 的代价是文字半尺寸**（气泡 6.5px、床号 6px：画得出来、读不出来），这是用户显式选档的结果，不是回退机制漏画。**想「缩小后气泡仍读得清」是另一套机制**（气泡与名字在缩小档保持屏幕尺寸恒定），不做，记在 `../design/backlog.md` |
| 拉远后的退役 | `Z < ZOOM_TEXT_MIN = 0.5` 时**世界文字与小细节退役**：床号、名字、聊天气泡、睁眼两点都不画（12px 的床号在 0.5 倍下只剩 6px，本来就读不出）。**回退只有这一档、没有第二级**：床位贴图、房间地面与预留位（**它们就是「厅的大致样式」**）、小人贴图永远画，两颗暖标记永远**恒定屏幕尺寸**。档位表里的固定档全在阈值之上 → 只有「自由缩放」与「全厅」会走到退役这一支 |
| 标记的屏幕尺寸 | **不随拉远变小**：半径按 `MARKER_RADIUS / Z` 换算，任何 Z 下都是同一个屏幕尺寸（拉到 0.175 时 5 世界像素只有 0.9px，等于消失——而「我在哪、我的床在哪」正是拉远档唯一必须保住的信息） |
| 缩放与命中 | **命中判定不按 Z 补偿**（半径仍是世界像素）：补偿的话 0.175 倍下 22px 的「点人」半径在世界里是 126px ≈ 0.7 格，会抢走「点床 / 点地面」。拉远档的用途是**看**，精确操作前先捏合放大——捏合以两指中点为锚，所以「缩小看到目标 → 在那处放大」本身就是定位 |
| 手势分工 | 一根手指 = 平移（不变）；两根手指 = 缩放（锚在两指中点，同时吃两指中点的位移）；**本次手势出现过第二根手指就不算轻点**（否则捏合收尾会误发一次走路）；从两指降回一指时以该手指当前位置重置跟踪点（不跳） |
| 缩放与跟随 | 跟随速度按 `1/Z` 换算（**屏幕观感恒定**）；死区仍按可用视口算（insets 也按 `1/Z` 换成世界像素） |
| 平移 | **单指拖拽平移**（轻点 = 意图，拖拽 = 看别处）。阈值：位移 < 8px 且时长 < 350ms 判为轻点 |
| 跟随 | 自己**正在走动**且走出屏幕中央区时温和跟随：**每帧按 `CAMERA_FOLLOW_PX_PER_S = 500` 与帧间隔 dt 匀速靠近**（约 0.5 秒追上 250px；**帧率无关**，单帧步进 = 500 × dt，60fps 下约 8.3px）；**停下即停**；拖拽期间不跟随。**不得用“逐帧固定比例”的 lerp**：那会让首帧按距离比例跳 20~33px（实测），且帧率一变速度就变 |
| 回中 | **点自己 = 相机对准自己**（一次性，不含走动）；**首次进厅**对准**我的床**（还没有床时对准出生点）；**断线重连后**对准**我的小人**（宽限恢复会把我放回原位，我的人可能在厅的另一头） |
| 瞬移落位 | 服务端把位置一步改到位时（「回我的床」，见 `../api/20-api-ws.md` §3）**直接落位、不插值**：单次位移 > 400px 的更新跳过插值窗口（否则会在 100 ms 内拉出一道横贯大厅的模糊线）。这是唯一的例外，常规位置一切照旧按 `ts` 插值 |
| 夹取 | 相机不越出**取景范围**（`scrollRegionOf` = 地板区 + 墙带 + 墙外一圈 56，见 `../design/20-layout.md` §3.2）：推到边缘时看见「**墙外的一圈底 + 墙带 + 地板**」——这才让墙读成一个实体边界（只夹到地板区的话，墙带会整条落在屏幕外；只夹到墙外沿的话，墙又永远贴着屏幕最外圈、只像一条细线）。可见区大于取景范围时居中。**竖屏下的垂直夹取按「可用视口」算**（见下），否则最底一行永远在聊天面板之下——走不到也点不到 |
| 尺寸变化 | 旋屏 / 地址栏收放后只重算死区与夹取，**保持用户当前的缩放值**（比例本身仍是常量） |
| 软键盘 | 见下「软键盘」：界面**不再读键盘高度**（输入框聚焦时整个底部组合挪到 HUD 下方，见 `../design/50-slot-panel.md` §2），相机与画布不归键盘管 |
| 裁剪 | **可视窗口 + 对象池**：每帧由 `camera.worldView` 算出可见的床号范围（±1 行/列缓冲），把池里的对象绑到这些床上。**同屏床数只取决于相机比例，与厅规模（117 ~ 9558）无关**：1× 约 10 张床，`Z = 0.175` 约 190 个床位（这时世界文字已退役，每床只剩贴图与两块贴片） |

#### 软键盘

**界面侧只留一件事：不让自己被键盘盖住。** 做成的方式不是“抬到键盘上沿”（那要求知道键盘多高），而是**输入会话进入打字态时把整个底部组合挪到 HUD 下方**——顶部与键盘天然不重叠。这样整条链路**不需要读 `visualViewport.height`**。

为什么不能读键盘高度：部分内核里键盘“弹没弹”根本测不出来——布局视口与视觉视口都不缩，或两者一起缩导致差值归零。只要界面依赖那个量，就总有一类内核会错。所以 `index.html` 不需要 `interactive-widget`（它会改变布局视口语义，而我们不再依赖任何一方）。

`visualViewport.offsetTop` 仍要读：iOS 聚焦时会把 visual viewport 往下 pan（`offsetTop > 0`），`.app-shell` 靠 `transform: translateY(offsetTop)` 把自己拉回屏幕。**这条只动 transform、不改尺寸**，因此不会引起画布重建。

**画布在编辑会话期间冻结像素尺寸**：键入期间只允许「宽度不变、高度变小」这类变化被跳过（那是键盘的指纹），宽度 / DPR / 旋屏照常立即重算；退出打字后再算一次。这样「键盘绝不能让画布重建」是代码里绕不过去的门，而不是一条口头约定（`../design/60-interaction-shell.md` §5）。

**为什么从「不做缩放」改成「只缩不放」**：原来的三条理由逐条变了——①「一般 2D 角色扮演游戏也不缩放界面」：那些游戏有小地图，而这里一屏只有 10 张床、厅宽是屏幕的 **6 ~ 52 倍**；②「在手机上放大到 0.35 倍也看不清整厅」：现在有数了——第 1 级整厅装进屏宽需要 **0.175**，15 档的厅需要 **0.019**（那时一张床只有 1.2px）：**小厅可行、大厅只能看纹理**，所以下限固定 0.175，大厅的边界写进已知代价；③「会带出默认比例 / 夹取 / 旋屏 / 双指分工一整串问题」：确实带出，但全部落在**缩放比例这一层**（可用视口的 insets 换算、跟随速度、标记尺寸、文字退役阈值），都可以在纯函数里单测。**床号仍是主要导航**（`GO` + 「回我的床」+ 方位字形一个都没动），拉远是「看一眼整体」，不是导航手段。

**「可用视口」是相机的取景基准**：世界层只**读** DOM 的**布局值**（顶部 HUD 与底部聊天面板，`offsetTop` 累加 + `offsetHeight`，配 `ResizeObserver` 听变化），可用视口 = 视口 − 顶 − 底（393×852 竖屏、站立、连接正常下约 **706px** 高，动作行进面板后重算）。**键盘与它无关**：打字态只是把面板挪到顶部（网格换行），可用视口不吃键盘高度。取景中心、夹取范围、死区都按它算：

- 垂直夹取按可用高度 → **最底一行能滚到面板之上**，点得到也走得到；
- 死区按可用区居中 → 跟随时人物留在看得见的那条带里；
- **不要硬编码高度**：面板高度随消息条数与窄/宽档变化。

**「不跳」的验收口径**（写清楚，避免测量口径之争）：

| 对象 | 判据 |
| :--- | :--- |
| 小人的**绘制位置**（世界坐标） | 单帧位移不得 ≥10px（正常帧为 `WALK_SPEED_PX_PER_S × dt`） |
| **相机**（屏幕滚动量） | 单帧步进 ≤ `CAMERA_FOLLOW_PX_PER_S × dt`（60fps 下约 8.3px） |
| **插槽面板打开 / 关闭**（相机与画布） | 打开期间滚屏值与画布像素尺寸**一位都不变**（键盘动画逐帧触发也照样不变）；关闭后滚屏值必须**精确等于**打开前的值 |

只按「屏幕像素」量会把相机自身的滑动算成「小人跳」——两者必须分开量（小人按世界坐标、相机按滚动量）。

## Elevation & Depth

**不制造深度感。** 这是一片平铺的地面，不是有层次的界面。

- 不用阴影表达层级。层级用**亮度差**（`primary` 与 `secondary`）和**边框**表达。
- 浮层（错误提示）用底色加边框，不用投影。
- 世界本身没有阴影：床位、小人、墙都是平铺线稿，靠**绘制顺序（按 y 排序）**解决遮挡，不靠阴影或加粗描边。

## Shapes

- **线稿是等宽的**：小人、床用同一线宽（素材本身自带的线宽，构建期不再改），靠形态区分，不靠粗细。**墙除外**：它是 `WALL_WIDTH = 3px` 的墙带（画在墙矩形之外）——1.5px 的细线在手机上几乎看不见，而「走到边缘要看得见墙」是硬要求（见「世界相机」与 `../design/20-layout.md` §2）。
- 圆角只出现在界面控件上：`sm` 用于小标记，`md` 用于面板与输入框，`lg` 用于入场层，`full` 用于主要操作按钮。HUD 是贴顶的通栏，不画圆角。
- **小人造型来自素材**（`WheatCloudSleep` 的 `Boy` / `Girl`：大头、点眼、简化四肢）。**不做逐帧行走动画**——走动靠极轻微的缩放摆动（呼吸感）表达，与参考实现一致：幅度 3%、频率 **4.5 Hz**。这是整套视觉里辨识度最高的一笔，不要改。
- 躺姿是**素材里的一张整图**（床 + 被子 + 只露的脸），不是「把人画在床图上」：因此「空床 / 有人（男）/ 有人（女）」是三个独立贴图，而不是三层叠加。
- **睁眼躺姿暂时靠代码叠两个点**（素材只有闭眼的那一张）；补画后替换为贴图（见 `../design/backlog.md`）。

**构建期要产出的变体**（5 张母图 → 8 张贴图：两色渐变映射 + 裁到墨迹 bbox + 打进一张图集）：

| 贴图 | 源 | 白填充映射为 | 黑线映射为 |
| :--- | :--- | :--- | :--- |
| `bed_empty_hollow` | `bedEmpty` | **透明**（空芯） | `claimed` |
| `bed_empty_owned` | `bedEmpty` | `paper` | `claimed` |
| `bed_boy` / `bed_girl` | `bedBoy` / `bedGirl` | `paper` | `line` |
| `bed_boy_trace` / `bed_girl_trace` | 同上 | `paper` | `trace` |
| `boy_stand` / `girl_stand` | `Boy` / `Girl` | `paper` | `neutral` |

睡痕的两张在运行时再乘一个不透明度（不是单独的贴图变体）。**素材本身是 2 色 + 抗锯齿灰**，所以映射必须按亮度插值（渐变映射），不能只替换两个色值——否则边缘会烂成锯齿。素材许可与出处见 `README.md`。

**气泡不走素材**（历史教训）：上游那两张气泡图是小尺寸的界面素材（36×30 与 23×27，竖直描边只有 1–2px 且带抗锯齿）。为了跟文字宽度对齐而**横向拉伸**它，会把那 1–2px 的竖直描边拉成 5–10px 的半透明带 —— 实测左右两边发虚（上下边只做纵向缩放，所以看起来正常）。所以气泡改成**程序化绘制**：一个圆角矩形（`setRounded`）+ 一个三角尾巴，1px 描边、位置取整，任何尺寸都不糊；这与「几何是程序化生成的」是同一条思路（床与人用素材，是因为它们有手绘造型）。

**管线顺带产出一份 `public/sprites/frames.css`**（每帧一条 `background-position`）：入场层的形象预览要拿图集里的 `boy_stand` / `girl_stand` 当图片用，而图集坐标只能有**一个**来源（管线），不能在 CSS 里再拄一份。

| 我的床（我自己躺着） | `line` | `paper` | **有** | 画 | **不画**（我知道我是谁） |

**谁能躺**：**任何无主空床都能躺**（躺下即认领）；自己的床任何时候都能躺。**我还没有床时，点无主空床直接躺下**（新人第一步不加门槛）；**我已有别的床时，点无主空床不换床**——只给一句提示「已经有一张床 · 换床在设置里」（换床的代价是**旧床归属当场释放**，别人可以立刻捡走，不能由一次误点承担）；换床走**显式的模式**：「更换床位」模式内点一张无主空床 = 换床（旧床当场释放，距上次认领不足 10 秒会被拒：`3008`，可见提示）；点自己那张床（不在床上）= 走回去躺下（模式内外一致）；**在床上点别的空床 = 自动起身后过去**（一条命令，同「点地面」）。

**躺不了的那几下分三类，都在客户端拦下、都不发上行，文案与服务端同码逐字一致**（服务端保留同样的判定，供缓存里的老 bundle 兜底）：床上有人（含**未过期的睡痕**）→「这张床有人了」（同 `3002`）；**别人的**有主空床 →「这是别人的床」（同 `3003`）；无主空床但我已有别的床 →「已经有一张床 · 换床在设置里」（本地文案；服务端没有对应的码，`3007` 已删）。点自己正躺着的那张床什么都不做（`3004`，静默）；**命中半径内的别人优先于上面全部**（那一下是选中私聊对象，不是躺下）。

**为什么本地判而不是发上行等服务端拒**：省一次往返，也没有「先本地外推迈出一小步、再被错误码拉回」的抖动。代价是**归属过期（30 天）不会主动推给客户端**，所以「有主」的口径与画面上床的填充**同源**（都吃 `ownedBeds`）：跨过每日唤醒后，可能把一张其实已可认领的床报成「这是别人的床」——偏保守的那一侧，与 HUD 的「空床 n」是同一个偏差（见 `../design/backlog.md`）。每张床都常显床号 + 我的床有暖标记，正是为了让你能回到自己那张。

**为什么「有主 / 无主」走填充而不走第四档颜色**：颜色梯次只能容纳三档。明底上 `line` 8.42:1 > `trace` 4.13:1 > `claimed` 3.12:1 已经把「弱到还看得见」用尽——再插一档要么低于 3:1，要么与相邻档分不开。

**为什么不是线型**（原设计用的是「无主虚线 / 有主实线」）：那是「轮廓由代码画」时代的方案。现在床是**素材里的一整张图**（黑线与白填充一起被渐变映射），线型没法只替换线条——要么在图上再叠一个虚线框（会和素材自带的床头、侧栅打架），要么在素材里做两套轮廓。**改用填充**：无主空床的白色填充映射成**透明**（空芯，地板直接透出来），有主床映射成 `paper`。这条通道的优势是**面积**——整个床内区域都在变，而 1.33:1 的细线差是弱通道；大面积的亮度差在低对比度下依然可辨。

配套约束：

- **睡痕整张图降低不透明度**（床与小人都降，不能只改轮廓与名字，否则「睡痕」与「睡着」只差颜色）
- **空芯变体必须是「白 → 透明」而不是「白 → `primary`」**：写死底色等于把地板色抄进素材——改令牌或加档时会露出一块补丁
- **轮廓与填充都不影响可点击性**：命中区域是床的占位区，与画法无关
- **`marker-own` 有最小屏幕尺寸下限**：不得消失，否则「找不到我的床」
- **可躺（空芯）是一条弱通道**：它靠 1.33:1 的面积差。真机上若判「看不出来」，补救顺序是 ① 加大 `paper` 与底色的差；② 在无主空床的床角加一个 `claimed` 色的小标记（**不动几何**）。实测项记在 `../design/backlog.md`

| `conn-banner` | **连接提示条**（断连的自愈状态，不是错误）：`toast-recoverable` 的同一套令牌（`secondary` 底 + `alert` 文 + `label` 档 + `rounded.md`，**不新增 token**）。位置固定为 `chat-panel` 的**第一个子元素**（**占位、不浮层**）——这样可用视口自动扣掉它（世界层已经在观察 `.chat-panel` 的高度），不会遮住最底一行，也不需要改世界层。两态文案：「正在连接…」/「连接已断开，正在重连…」；右侧一个 44×44 的「尝试连接」按钮。**不自动消失**（唯一的消失条件是重连成功），没有入场动画，不抢焦点（`role="status"`） |
| `presence-dot` | 「有人在线」的极小面积点缀 |
| `name-bubble` | **选中对象的名字气泡**。它与聊天气泡**共用头顶那一个槽位**（优先顺序：聊天 > 名字，见下） |
| `whisper-target` | 私聊目标行：选中某个人后出现在聊天输入行上方（「私聊 阿夜 ×」），点 × 取消选中 |
| `emote-panel` | **表情面板**：与输入行**共用同一行位置**——收起时这一行是 `输入框 + 😀 切换键 + 发送`，展开时**原地**换成 `5 个 emoji + 😀 切换键`（展开时「发送」键不出现：那一刻没有待发文本）。**切换键钉在最右**（`margin-inline-start: auto`）：展开时它接替收起态「发送」所在的那个位置（**右缘对齐**；横向会右移一个「发送」键的宽度 ~58px，但不混进 emoji 行、也不用重新找）。emoji 从**左边**起排。点一个 emoji **就发一条聊天消息**（内容就是那个 emoji；未选对象走全局、选中对象走私聊）——**不是插入输入框**，要跟文字混排请用系统键盘。点完**停留在面板**可连发，再点切换键换回输入行；输入框里的草稿原样留着。字形是 emoji、可访问名用中文（`aria-label` 不念 emoji 字符）。切换键是 44px 描边胶囊（`.emote-toggle`，与 `hud-action` 同规格）且带 `aria-expanded`；**5 个 emoji 是纯字形、不带描边**（`.emote-item`，触击区仍是 44×44）——靠**形状**区分「控件」与「内容」，不靠字形差异（emoji 当按钮用正是「看不出哪个能点」）。`EMOTE_SHORTCUTS` 最多 5 项：第 6 个就会顶到切换键，要加先改这一行的排布。**不新占一行、也不做浮层**（浮层会盖住最底一行走道，理由同 `conn-banner`），因此面板总高与可用视口都不变 |
| `bed-actions` | 床上动作行：**只在自己躺在床上时出现**（起身 / 睡了），触摸目标 44px |
| `marker-own` | **属于我的标记**：自己的小人脚下 + 自己的床位角落共用同一颗暖灯色小点。换床模式里**同一个几何通道**换成 `claimed` 色，用来标「这张空床可以搬」（两种标记不会在同一张床上争位：目标就是我的床时，它本来就不需要「可搬」这个标记） |

### 名字什么时候出现

名字是身份信息，不是陪伴信息。**「看到有人和我一样醒着」靠的是看到人本身。**

| 对象 | 名字 | 理由 |
| :--- | :--- | :--- |
| 躺在床上的人（含睡痕） | **始终显示**（裸标签）；被选中时改成气泡样式，**不额外叠第二个** | 床的位置稳定，标签不会飘；而「这是谁的位置」本身就是产品要表达的 |
| 漫游中的人（站着/走动） | **默认不显示**；被选中时显示唯一一个名字气泡 | 几十个人就是几十个随风飘的标签，画面会立刻变吵 |
| 自己 | **一律不画**（地上与床上都不画），靠 `marker-own` 识别 | 我知道我是谁。而且地上不画、床上却画是不对称的 |

**床号与名字的关系**：床号是**位置信息**，每张床都画；名字是**身份信息**，只在床上有占用者时画。两者都不是「界面」，都画在世界里。

**选中态是一个概念、服务两件事**：点中某个小人（或床上的人）→ 他成为选中对象 **且** 成为私聊目标。同一时刻只有一个选中对象（因此只有一个气泡），点地面则取消选中并走动。

**头顶只有一个槽位**（不是两个各管各的气泡）：**聊天 > 选中名字**——聊天/私聊出现时占着它，到点回落到名字。床上的人名字常显在下方那一条，不跟着抢占槽位；比对到自己的名字永远不画。
- **选中即私聊目标**：面板上方出现「私聊 阿夜 ×」；点 × 取消选中。目标离开大厅时**自动取消选中**。
- **表情就是聊天气泡里的 emoji**：点表情按钮 = 发一条只含该 emoji 的**聊天消息**（未选对象走全局、选中对象走私聊），所以它与打字发出去的 emoji 走完全同一条路径、同一个 8 秒气泡、同一套槽位规则。**没有独立通道、没有独立显示时长**。
- **聊天与私聊也是气泡**（`CHAT_BUBBLE_MS` = 8 秒）：同一个人后来的消息**覆盖**前一条并重置计时（不排队、不堆叠）；宽度上封顶 `CHAT_BUBBLE_MAX_PX`（200 世界像素），最多两行、超出截断加 `…`；私聊只在收发双方头上出现，并加一个「悄悄话」前缀（**不另开一档颜色**：少一个语义通道就少一处要记住的规则）。

**床上动作只在床上出现**：「起身 / 睡了」两个按钮仅在自己躺在床上时占位，不躺着的时候它们是空的——界面上不留没有对象的按钮。

## Do's and Don'ts

**Do**

- 把视野中央留给大厅本身，界面只占边缘。
- 用亮度差与边框表达层级，不用阴影。
- 睡痕必须一眼可辨——它比在线者暗得多，这是「这里曾有人睡过」的全部表达。
- 把床位的**归属**与**占用**当成两个独立维度推导，不要合并成一个「床位状态」。
- 无主空床必须画出来（`claimed` 线 + **空芯**）：它是「这里还没人认领」的唯一提示，也是新人找不到床时的唯一依据。
- 占用用颜色、归属用填充。不要为归属新开一档颜色。
- **每一档墨必须同时衬地板与衬床填充 ≥3:1**：描边有一半压在自己的填充上。
- 空芯变体必须把白色映射成**透明**，不能写死成地板底色（写死底色等于把令牌抄进素材）。
- **每张床都画床号**（`neutral-muted`）：1× 下它是主要的导航线索；拉远到 `Z < 0.5` 时文字退役。
- **可点击的东西必须长得像按钮**（描边胶囊 + 44px 触摸目标）。显示性信息既然和按钮混在同一条通栏里，靠外观区分就是唯一线索；纯文字当按钮用，用户就分不清哪个能点。
- **「是我的」靠一个独立的小标记**，不要用轮廓颜色表达。
- 有主但空的床只画轮廓与床号、**不写名字**；名字只出现在床上有人的时候。
- 暖色只用在「这是我的床」的标记上。
- 世界渲染用**可视窗口 + 对象池**：只给相机视野内的那几十张床建对象。
- 三档减光是整屏一层：地板、床、小人按同一比例变暗；**不要为某一层再单独调色**。
- **房间地面与预留位用固定色**（`room` / `rug`）：它们和床板（`paper`）一样是「材料」，不跟着厅里的光变。

**Don't**

- 不要用高饱和像素风或鲜艳渐变。那会让一个失眠大厅变吵闹。
- 不要用红色警报类配色做错误提示。
- 不要把聊天藏进弹出层或二级菜单。
- 不要把表情藏进二级菜单：**两步发出**——点一次切换键展开，再点一下 emoji 就发出去。展开也不要新占一行、也不要做成浮层：它与输入行共用同一行位置。
- 不要让地上的小人常显名字（几十个飘动的标签会把大厅变成名单）。
- 不要在渲染聊天消息时临时去查人名（对方离开后那行名字会变空）——追加时就固化。
- 不要把暖赭用于整张床的轮廓（它在浅底上比墨线更抢眼，会颠倒「有人睡 > 谁的床」的优先级）。
- 不要让轮廓梯次的相邻两档靠得太近（弱不等于不可见，也不等于分不清）。
- 不要把无主空床画成「不画」：那样新人进厅只看到空地板，「看见床位 → 挑一张躺下」这条核心循环就没有入口。
- 不要用「更暗的第四档颜色」表达归属：深底上做不出既单调又都 ≥3:1 的四档。
- 不要在床图上叠虚线框来做「无主」标记：素材自带床头与侧栅，叠上去会打架。归属走填充（空芯 / `paper`）。
- 不要让 `paper` 填充超过 2:1：再亮就把线稿变成色块。
- 不要给睡着的人做逐帧呼吸动画——用整体透明度的低频变化代替（几百个睡着的人逐帧动画会吃掉手机 CPU）。
- 不要引入外部字体文件。
- 不要把**界面控件**（按钮 / 面板 / 列表）画进画布，也不要在 DOM 里重画世界：床号、名字、气泡都是**贴在世界对象上的文字**（跟人走、跟床走），不是界面。
- 不要给每张床都写名字（那是名单，不是大厅）。
- 不要先做桌面再“适配”手机。
- 不要把重要信息做成“悬停才显示”——手机上不存在悬停。
- 不要在常驻 HUD 上放版本号这类排查信息：它进齿轮浮层。常驻版面只留用户做决定要用的数字。
- 不要让输入框字号低于 16px（会触发窄屏浏览器的页面自动缩放）。
- 不要禁用用户缩放页面。
- 不要按设备像素比 1 渲染画布（窄屏高密度屏上会糊），也不要无上限地按比值渲染（低端机扛不住）。
- **不要让世界里的文字停在 1× 栅格密度**：相机 zoom = 画布 DPR（>1），床号 / 名字 / 气泡文字都会被放大采样而发虚；按 DPR 栅格化，与画布同一个比值。
- 不要用桌面浏览器缩窄窗口代替手机视口验收（393×852 / DPR 3 / 触摸）：移动端类验收默认走宿主 Android 模拟器（见 `../design/test.md`）。
- **不要引入放大**：世界只有拉远一档（`Z ≤ 1`），没有捏合放大、没有滚轮、没有双击归一（双击要等 300ms 才能确认不是单击）；也没有世界比例可调——`ART_SCALE` 是常量。
- **不要用 `Tilemap`**：几何是程序生成的，没有 Tiled 数据、没有地形类型、碰撞在服务端。
- **不要给床或小人开 `setInteractive`**：命中判定走「屏幕 → 世界 → 槽位」的纯函数（可单测）。
- **不要启用物理引擎**：位置是服务端权威 + 客户端插值。
- **不要让明暗随时间周期变化**：那会被读成昼夜替身。
- **不要给世界单独叠第二层减光**：两层叠加后，屏上亮度就不再能从文档推算，验收也没有唯一口径。
- **不要让入场层参与档位**：它不属于厅里的档，首屏也不该「从最亮渐暗」。
