# 说明面板（about panel）

**一句话**：一页纯文档——这个厅是什么、这一版更新了什么。它只在「没确认过这一版公告」时挡在大厅前面一次，之后从齿轮浮层随时能翻回去。

## 1. 什么时候出现

| 触发 | 条件 | 出口 |
| :--- | :--- | :--- |
| **自动**（首访 / 新公告） | `sc.about.seen` 缺键，或它与内容指纹 `ABOUT_TOKEN` 不相等 | 主按钮「知道了」（`Esc` 同路）+ 勾选框 |
| **手动**（齿轮浮层 →「关于失眠云」） | 随时（打字态齿轮不可达，见 `60-interaction-shell.md` §9） | 主按钮「知道了」（`Esc` 同路），**无勾选框** |

**页面态顺序**：`加载 → 说明面板（若需要）→ 入场层 → 大厅`。

面板渲染在入场层**之前**（`aboutOpen` 优先于入场层）。理由是层级而不是顺序偏好：入场层是**不透明满屏底**（`outside`）且盖住画布，任何浮在它上面的东西都要另写一套层级；而「先知道这是哪、再填昵称」也符合读者的顺序。代价是首访者要读两屏才进厅——接受，因为这一屏一生只自动出现一次。

## 2. 已读语义（ack）

- **只有一个出口**：主按钮「知道了」（`Esc` 走同一条路）。点它 = 关闭，并按**那一刻的勾选状态**决定是否落盘。
- 勾选框「**以后不再自动显示**」**默认勾选**，只出现在**自动打开**的那一次：
  - 勾着关 → 写 `sc.about.seen = ABOUT_TOKEN`；
  - **取消勾选**再关 → **不写**（意思是「下次还想看」），下次进厅照旧弹。
- **不做第二个出口**：没有右上角 ×、不点遮罩关闭、不放一颗中性的「关闭」。这套语义的前提就是「按了按钮 = 我确认过了」，而第二颗按钮要么承诺它做不到的事（中性关闭却不记录），要么悄悄记录用户没答应的事。同理**不做点遮罩关闭**：遮罩上的每一次误触都等于「已读」。
- 勾选框**只在自动路径出现**：从齿轮打开本来不记录任何东西，「你不读也会被记住」在这里不成立。

## 3. 键与判定

| 键 | 值 | 缺键 | 判废 |
| :--- | :--- | :--- | :--- |
| `sc.about.seen` | `{"v":1,"seen":"1k9f3a2"}` | 等于「从未确认过任何公告」（首访，或本功能上线后的第一次） | `seen` 不是非空字符串、或超过 32 字符 → 删该键 + 当缺键 |

判定是一个纯函数：

```text
shouldShowAbout(seen: string | undefined) → seen !== ABOUT_TOKEN
```

### 3.1 指纹由正文派生，不是手写版本号

`ABOUT_TOKEN` = 正文的短哈希（`src/client/about.ts` 里算，不改任何输入）：

- **先按行归一化，再算 FNV-1a**，取 base36，形如 `1k9f3a2`，落在 `seen` 的 ≤ 32 字符窗口内。归一化只做三件事：**折掉行内连续空白**（含 `\r` 与制表符）、**去掉每行首尾空白**、**丢掉空行**；**换行本身保留**。
- **为什么是 base36**（这一条不关键，换成 hex 也不破坏任何契约）：① `Number.toString(36)` 是语言内置，一行拿到、不用补零；② 只含 `[0-9a-z]`，没有大小写与分隔符歧义；③ 它**长得不像版本号**——`0.0.8` 那种形状会诱人以为可以手改。真正载重的是「由正文派生」，进制只是包装。
- **归一化的理由**：Windows 上 git 换行（CRLF）、文件末尾多一个换行、行内多两个空格，都不该让全体用户被多弹一次——**只改空白不算改内容**。但**行切分算内容**：这个格式里「行就是块」（`## ` / `- ` / 段落全由行决定），所以把一段拆成两行、或把两行并成一行，虽然一个字都没变，渲染结果变了、指纹也就该变。空行是例外——它只是可读性，不影响任何块。
- **算法写死、不许改**：换哈希算法等于全体再弹一次。改的时候当一次内容变更对待。
- 因此不再有「公告版本与发布版本不是同一个数」这条规则：面板里**不显示任何版本号**，正文里的「最近更新」也不带版本（版本历史归 GitHub Releases）；齿轮里那颗 `APP_VERSION` 与此毫无关系。
- **不校验 `seen` 的格式**：它只被拿去与指纹逐字比较，坏值唯一的后果是**再弹一次**（无副作用）。键协议与读写规则见 `40-client-storage.md` §2。

**为什么不用手写版本号**（被否掉的方案）：手写号的失败方式是「改完内容忘了升号 → 新内容永远不弹」——静默、没有症状、没人会发现。指纹的失败方式是「改一个字 → 全体再弹一次」——可见、自愈、一屏文档的代价。同一把尺子量下来，指纹是更小的坏处。

### 3.2 本功能上线那一刻，全体都算「没确认过」

需求说的是「第一次进入大厅」。代码里没有「第一次」这个事实，只有**缺键**——而本功能上线时所有已有设备的 `sc.about.seen` 都缺键，与真首访**不可区分**。

**所以不做种子重置、不碰 `PREFS_VERSION`**：老用户多读一次产品介绍，代价很小（对他而言，这一版的产品介绍本来就是新的）。任何「我是不是老设备」的推断都是在用另一个缺省去猜缺省（例如「有 `sc.weather.rain` 却没有 `sc.about.seen`」——那也是推断，而且会随初始化时机漂移）。

**已知代价**（三条，都接受）：

- `PREFS_VERSION` 递增（任何键的形状变化都会让它递增）会让所有键判废 → 说明面板**再弹一次**。一版一重置本来就是「偏好回默认」的文档化行为，而说明面板再弹一次本身无害。
- **改一个错别字也会弹一次**：指纹只管「字变了没有」，不管「变的是不是重要内容」。这条是换取「不会静默不弹」的对价（§3.1）。
- **改了归一口径也会弹一次**：所以算法写死、不许随手改。上一次从「整体折空白」改成「按行折空白」（换行开始算内容），`ABOUT_TOKEN` 的取值随之变了，全体与内容更新一起再弹一次。以后任何口径调整都按同一条办——**当一次内容变更对待，与内容改动同一次发版落地**，否则全体会白弹两次。

## 4. 内容

内容 = **一个配置文件** `src/client/about.json`（正文）+ `src/client/about.ts`（解析、指纹、判定；纯函数、DOM-free、可单测）。文件里**只有一个字段 `text`**，值是一行一个元素的字符串数组。

```json
{
  "text": [
    "第一段正文",
    "",
    "## 小节标题",
    "",
    "- 条目一",
    "- 条目二"
  ]
}
```

**编写格式**（就这四条）：

| 你写什么 | 结果 |
| :--- | :--- |
| `"text"` 数组里**一个元素 = 一行**，顺序就是正文顺序 | 一行接一行，和写记事本一样 |
| 元素内容以 `## ` 开头 | 一个小节标题 |
| 元素内容以 `- ` 开头 | 一条条目（相邻的 `-` 元素合成一个列表） |
| 元素写 `""`（空字符串） | 一个空行——只为可读，不影响排版结果，也不影响内容指纹 |

- **JSON 语法不是我们的选择**：每行都要带双引号和逗号，**不能写注释**，**最后一个元素后面不能有逗号**。写错了测试当场红（`about.json` 本身的合规由单测守着），不会静默变成空面板。
- 构建期读入：`import about from './about.json'`（TypeScript / Vite 原生，**零配置、类型自动**）——**没有请求、没有加载态、没有失败分支**，内容与 bundle 同一次发布；`vitest` 走同一条管线，所以单测直接读同一份文件。数组元素用换行连起来（`about.text.join('\n')`）再送进解析器，因此「空字符串 = 空行」「`## ` / `- ` 看元素开头」这两条成立。
- **为什么不是一个 markdown 文件**（被否掉的方案）：`.md` + `?raw` 要一个环境模块声明，还要给测试 tsconfig 加一项 `vite/client`；JSON import 原生就有。同一件事少一个零件，代价只是每行一对引号。

**没有预定义内容块**：代码里不存在 `sections` / `items` 这类结构，也没有「每节标题」「每节条目」这些字段——**结构由文本自己决定**。允许的语法只有这四件事：

| 写法 | 结果 |
| :--- | :--- |
| `## 标题` | 一个小节标题 |
| `- 条目` | 一个条目（连续的 `-` 行合成一个列表） |
| 空行 | 忽略（只为可读） |
| `[文字](https://…)` | 一个链接（行内，三种块里都能用） |

- **段落由行决定**：一个非空元素 = 一段；换行即分段，段落内部不手工折行。空字符串只是为了可读，不影响结果。
- **只认这两种前缀**：`## `（两个井号 + 一个空格）与 `- `（一个横杠 + 一个空格）。其余行一律当正文，包括 `# x`、`* x`、`1. x`——不猜作者的意图，按字面显示。
- **不支持任何其它行内标记**：星号、下划线、反引号、`**加粗**` 全部按字面显示。渲染走 React 文本节点，**不碰 HTML**，没有注入面。
- **链接只认 `https://`**：`http:` / `mailto:` / `javascript:` 一律按字面显示。白名单只有一条——黑名单式过滤是 XSS 的经典破口。
- **坏链接按字面显示**：`[x](not-a-url)` 原样出现在面板里。作者侧的错误**可见**才修得掉（与聊天里「打码不拦截」的方向相反，因为错的主体不同）。
- **URL 里不允许空白与 `)`**（扫到第一个 `)` 收尾）：不处理转义括号，面板用不到。
- **整篇 ≤ 24 块**（单测守着）：超了说明该拆成文档，而不是让面板变成长篇。
- **只列最近一版**：面板是通知，不是历史；更早的更新去 GitHub Releases。
- **首访者与老用户看同一份内容**（介绍在前、更新在后）：不做「两种内容形态」，少一套分支。
- 单测还守：正文非空、解析结果里没有空块、`about.json` 这份真实内容本身合规（块上限、至少一个小节）。

**改内容的手续**：改 `src/client/about.json` 里的字。**没有第二步**——指纹自动跟上，所有设备下次进厅都会看到这一版（不需要升号、也不需要动代码）。唯一的纪律在发版那一步：**发版时把它当必做项，别漏掉**（`build.md` §4.3）。

**这个文件完全由开发者手工维护**：`npm run` 里没有任何一条脚本会写它，构建与运行时也不会回写它，它不是从 `CHANGELOG.md` / `package.json` 派生出来的，也没有后台编辑入口——**正文的唯一来源就是提交进仓库的那份手写 JSON**。所以「内容该不该跟上这一版」机器判不了（散文没有可校验的形状，CI 的版本一致性只比版本号，不碰它），漏改的症状是**新版本的人什么都看不到、也没有任何报错**；这一条只能靠 `build.md` §4.3 第 1 步人工补上。

## 5. 渲染与层级

- **世界走画布，界面走 DOM**（硬纪律 16）：这是文档面板，全部是 DOM。
- **复用入场层那套壳**：`.entry-overlay`（不透明底 `outside` + 安全区内边距 + 自己可滚）+ `.entry-card` + `.entry-title` + `.action-primary`；新增的只有正文段落、小节标题、条目、行内链接四类。同一屏、同一批用户、同一套排版，再造第二套只会让两屏不一致。
- **块到元素**：小节标题 → `<h2 class="about-heading">`，正文 → `<p class="about-intro">`，连续条目 → 一个 `<ul class="about-items">` 里的 `<li>`（「·」是 CSS `::before`，读屏不念）。链接 → `<a class="about-link" target="_blank" rel="noopener noreferrer">`；样式与正文同字号 + 显式下划线 + `overflow-wrap: anywhere`（作者可以把整条 URL 当标签，窄屏不能溢出卡片），**内联链接不受 44px 胶囊那条约束**（先例是 `entry-privacy`，WCAG 2.5.1 的行内例外）。
- **不进 `.app-shell` 的网格**：它不是常驻面板，是**覆盖整屏的临时层**（`position: absolute; inset: 0`，锚在本身是 `fixed; inset: 0` 的 `.app-shell` 上），因此不参与 Grid 两态、不做相机坐标补偿（`60-interaction-shell.md` §3）。
- **层级**：世界层与聊天面板之上、`tone-layer` 之下——三档减光照旧整屏连续（连它一起减光），与世界同向。
- **打开前先退打字态**：齿轮里的入口只在空闲态可达，但打开前仍统一走 `exitComposer()`（`60-interaction-shell.md` §2 的出口唯一），避免以后多一个入口时各自为政。
- **焦点给「知道了」，但不许它把面板滚到底**：`.entry-overlay` 自己可滚，而默认的聚焦会把目标滚进视野——内容一长，面板就直接从最下面打开、标题与介绍全在顶上被跳过。所以**聚焦必须带 `preventScroll`**（`focus({ preventScroll: true })`），面板永远从第一行开始展示。这不是美观问题：它是「长内容能不能读」的前提。
- **没有画布**：不进 Phaser、不开相机、不发上行。服务端不知道它存在。

## 6. 不做（与理由）

| 不做 | 理由 |
| :--- | :--- |
| 「历史版本」列表 / 公告中心 | 没有需求方；GitHub Releases 就是历史 |
| 「有未读更新」角标 / 红点 | 它要求记住「上次看到哪一版」并在每次进厅比对，还会把「点掉红点」变成任务。面板一生只自动出现一次，不需要第二套未读语义 |
| 服务端下发公告内容 | 那要新增接口、缓存与审核语义，而公告本来就是随版本发布的一份代码。内容源在 bundle 里 |
| `about.json` 的生成器 / 后台编辑器 | 这个文件一年只改几次、改的是给人读的散文，现在没有需求方；加了就要维护一条「后台 → 仓库 → 发版」的链路，而漏改的症状（不弹、无报错）本来就由 `build.md` §4.3 那一步兜着 |
| 多标签页 / 跨设备同步 | 与全部其它偏好同一个立场（`40-client-storage.md` §4） |
| 点遮罩 / × 关闭 | 见 §2：单一出口是这套已读语义的前提 |

## 7. 验收

| 层 | 判据 |
| :--- | :--- |
| **L1**（vitest） | `shouldShowAbout`：缺键 → true；指纹相等 → false；旧指纹 → true；判废后的坏值 → true。**解析**：`## ` → 小节标题、`- ` 连续行合成一个列表、空行分段、`[文字](https://…)` → 链接、`http:` 与坏 URL 按字面显示、`# x` / `* x` 当正文。**指纹**：只改空白（行内多空格、行尾空格、空行、CRLF）→ 指纹不变；改一个字、或换行的切分（一段拆两行 / 两行并一行）→ 指纹变。`about.json` 本身：正文非空、≤ 24 块、至少一个小节 |
| **手工**（桌面浏览器 + 手机视口 / 模拟器） | 干净存储首访：面板出现 → 点「知道了」→ 入场层出现；重载：不再出现；**取消勾选**再关 → 重载仍出现；**手改 `about.json` 一个字 → `npm run build` → 重启 `npm run dev`** → 重载：面板**再次**出现（指纹不等；不重建 / 不重启 dev server 就看不到变化，见 `test.md` §3 第 3 条）；齿轮 →「关于失眠云」→ 面板出现 → 关闭后大厅仍在 |
| **L3**（模拟器） | 竖屏：卡片不溢出、内部可滚、勾选框整行 44px、`Esc` 与按钮同路、三档减光压住面板 |

## 8. 术语

| 用 | 不用 | 说明 |
| :--- | :--- | :--- |
| 说明面板（about panel） | 公告框、弹窗、欢迎页 | 它是一页文档，入口两个、出口一个 |
| 内容文件（`about.json`） | 配置、文案表 | 说明面板的**唯一**内容源：一个 JSON 配置文件（`{"text": [一行一个元素]}`），构建期 import 内联。改文案只动它。**完全由开发者手工维护**：无生成脚本、无后台入口、无回写（§4） |
| 内容指纹（`ABOUT_TOKEN`） | 公告版本、版本号 | 由正文派生（**按行**归一化 → FNV-1a → base36）。**不是手写数字**，也不是发布版本 |
| 已读（ack） | 看完、记录阅读 | 把内容指纹写进 `sc.about.seen`。它表达「这一版我见过了」，不是「我读完了」 |
