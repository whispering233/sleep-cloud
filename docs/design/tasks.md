## 卡 9 世界渲染（静态）

- [x] PixiJS 画场景与全部床位，按厅时区昼夜配色，按 y 排序解决遮挡
- [x] 按设备像素比渲染（上限 2，兼顾清晰与低端机）
- [x] **验收（除真机目视校准与 `line` 档外已核对）**：轮廓梯次（`line` > `trace` > `claimed` > 不画）有单测；睡痕的小人整体更暗；**最小缩放下暖灯标记仍可见**（有最小屏幕尺寸下限，单测覆盖）；名字只出现在有人的床上且自己不画（单测覆盖）；滚轮/捏合缩放与拖动平移可用；无主的床不画轮廓但可点（命中与轮廓无关）
- [x] 本地实测：375×667 与 1280×800 均正常渲染（大厅边框、四角灯、公告板、睡痕小人 + 名字 + 暖灯标记），控制台无 error；桌面软件渲染下 62 fps
- [ ] **待补**：`line` 档（床上有人）的像素级确认——需要卡 12 的「躺下」才有真实占用态
- [ ] **待真机**：视觉参数校准（三档轮廓与两个模式的暖灯标记色），以真机低亮度下目视可辨为准（当前值是 WCAG 公式初值）
- [ ] **依赖**：卡 3、卡 7（已满足）

## 卡 10 自己在场与走动

- [x] 连接后自己出现在入口；点地面发意图；服务端寻路 + 按节拍推进 + 100ms 合并广播；客户端插值
- [x] 移动者集合（内存）与内存循环启停：路径走完 / 断线 / 被新意图取代三种来源都能移除；集合为空时循环立即清除
- [x] 推进量按**实际经过时间**计算（不按拍数）；客户端按服务端时间戳插值（渲染时往后坐一个节拍）
- [x] **验收（本地实测）**：点地面后自己走过去（真实鼠标点击 → 服务端走到目标格）；点外墙返回 `3006` 且连接不断；**第二个客户端（另一个源 = 另一个身份）实测收到 17 批位置**、速率 4.28 格/秒（= 1/250ms，说明是按时间推进而不是按拍数）；**停下后 1.5 秒内零位置流量**（内存循环已清除）；新连接拿到的快照里权威位置就在点的那一格
- [x] 节拍抖动与「事件循环被阻塞一大截」由单测覆盖（抖动合计 1000ms 走 4 格；一次吞 4 拍也补齐）
- [ ] **待平台面板**：无人走动时段「活跃时长停止增长」的确认（本机无法看用量面板，随卡 20 一并核）
- [ ] **依赖**：卡 8、卡 9（已满足）

## 卡 11 看见别人

- [x] `join` / `leave` / `state` 增量事件；多人渲染与深度排序
- [x] **验收（本地实测，两个源 = 两个身份）**：
  - 互相可见：甲入厅后乙的快照里就有甲；乙入厅时甲收到 `join`（**自己不会收到自己的 `join`**）
  - 一方走动另一方平滑看到：乙收到甲 10 批 `pos`（条目里就是甲的 id）
  - 一方关掉页面后小人消失：**甲走到一半时关页面 → 乙收到 `leave`**，服务端快照里也不再列甲（此刻是立即发；卡 13 会把它推迟到 60 秒宽限之后）
  - 客户端的 `join` / `state` / `leave` / `bed` 归约有单测（幂等、没见过的人忽略、上床后清插值窗口）
- [x] `state` 的产生点已在卡 12 接上（躺下 / 起身 / 睡着）；「睡着的人不产生位置流量」实测成立（躺下后位置流量归零）
- [x] 顺带修的：同一个人的最新连接接管（多标签页时旧连接被断开，原因 `replaced`）——否则旧连接残留的目标会把已躺下的人重新推着走
- [ ] **待卡 13**：`state` 的最后一个来源（变成睡痕）
- [ ] **依赖**：卡 10（已满足）

## 卡 12 躺下 / 起身 / 睡着

- [x] 状态机与归属认领；四重校验（床号合法 / 自己不在床上 / 床未被占用 / 床属于自己或尚未被认领）
- [x] **复合意图**：`lie` = 走过去 + 躺下（路径携带「到达后动作」）；在床上点地面 = 起身 + 走过去
- [x] 每次上床（首次认领、再次躺下、从睡痕恢复）都刷新 `owner_name` = 当前会话昵称
- [x] 无输入满阈值自动转睡着：**读取时推导**（`deriveDisplayState`，有单测），库里的占用状态同步跟上
- [x] 睡着时说话或发表情**自动醒**后处理，不报错（消息内容本身在卡 16/17）
- [x] 认领时**先发 `bed`（归属）再发 `state`（占用）**
- [x] **验收（本地实测）**：空床可躺并完成认领（全厅广播 `bed{owned:true}`）；**从远处点床先走过去再躺下**（4 格实测）；`3001` / `3002`（睡痕占着的床）/ `3003`（别人的空床）/ `3004`（已在床上）/ `3005`（不在床上起身）逐个核对；手动睡着 → `state{asleep}`；睡着后发 `chat` → 自动醒（`state{lying}`）；再躺回自己的床只发 `state`、不再发 `bed`；起身后库里的行是「有主但空着」（`state=empty` + `owner_*` 保留）
- [x] 顺带修的两处顺序/竞态：同一节拍里**位置先于状态**；客户端不为已经躺下的人建插值窗口
- [ ] **待卡 14/20**：自动睡着的 5 分钟阈值实测（需要持久唤醒让它「及时」发生；推导本身的单测已覆盖）
- [ ] **依赖**：卡 11（已满足）

## 卡 13 断线宽限与睡痕

- [ ] 关闭连接时**同一步**完成三件事：把位置与路径搬进宽限会话记录 → 移出移动者集合 → 起宽限计时
- [ ] 期内重连恢复（含行进中的路径）；超时按是否在床上分流：**在床上则不发 `leave`，而是把该人留在列表里、显示态改为 `trace`**；不在床上则发 `leave`
- [ ] **验收**：断网 30 秒内重连状态不变（**含位置与路径**）；断网超过宽限后他人看到睡痕（名字与轮廓明显更暗，且那张床仍属于他）；不在床上断线则小人消失；重连后回到原床原状态
- [ ] **依赖**：卡 12

## 卡 14 时间驱动机制

- [ ] 三种机制各归其位：到期事件（宽限到期 / 自动睡着到期 / 每日清理）走**持久唤醒**；位置节拍走**内存循环**；状态判定走**读取时推导**
- [ ] 到期事件调度器：按到期时间排序的内存最小堆，**先比对堆顶与当前槽位，相同则不重复 `setAlarm`**
- [ ] 驱逐后重建：重算到期事件堆，并与平台上已存在的槽位对账
- [ ] **验收**：无人在线时不设任何持久唤醒；**强制驱逐后状态依旧正确**（靠推导）；`setAlarm()` 调用次数为个位数到几十次/天量级；alarm 处理器内不残留任何内存定时器
- [ ] **依赖**：卡 13

> 术语与理由见 `10-hall-runtime.md` §4。混用两种机制会直接导致「对象永不休眠」或「高频重写持久状态」。

## 卡 15 清理任务

- [ ] 睡痕清理（**发 `leave`**，床上的占用随之消失，床仍属于原主）+ 30 天归属释放（**发 `bed` 且 `owned: false`**，床回到可认领池）
- [ ] **验收**：跨日后睡痕消失但床位仍属原主（淡轮廓仍在）；超过 30 天未出现后床位回到可认领池（淡轮廓消失）；两者均通过下行消息即时可见；一次性清理大量睡痕时不超出单次调用预算（必要时分批）
- [ ] **依赖**：卡 14

## 卡 17 私聊与表情

- [ ] 私聊只推给双方；表情在世界内显示（枚举值定义在卡 2 的共享层，非法值静默丢弃）
- [ ] **选中态**：点中小人或床上的人 → 弹出唯一名字气泡 + 成为私聊目标；点地面则取消选中并走动
- [ ] **验收**：第三人看不到私聊内容；对方不在厅返回 `2005`（静默不提示）；**同一时刻只有一个名字气泡**；表情可见且不进二级菜单
- [ ] **依赖**：卡 16

## 卡 19 移动端实测与修补

## 卡 20 额度观测与实测校准

## 验证方式约定

| 类型 | 方式 |
| :--- | :--- |
| 纯数据模块（2、4） | 单元测试覆盖边界（干扰字符、超长、空串、重名） |
