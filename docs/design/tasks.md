### 卡 1（已完成，`eb75825`）：重锚不倒退（客户端纯函数）

> 已落地；其 off-path 剪枝缺陷由卡 1b 收口。

- **目的**：把重锚从「把画面拽到权威点」改成「保持 `lead`、只许向前收敛」。
- **改动范围**：`src/client/prediction.ts`（新增带符号弧长函数 + 改 `anchorPrediction`）、`src/client/tests/prediction.test.ts`。
- **验收**（假时间轴，不依赖真实网络）：
  - 权威点落在画面**身后**（刚起步、首个 `pos` 的典型情形）→ 锚点时刻前移，`predictionPointAt` 在任一时刻的值**不小于**改前的值（倒退 0px）。
  - 权威点落在画面**身前** → 接受（前向收敛），且收敛后仍不倒退。
  - 权威点已在折线外且距离 > `TELEPORT_SNAP_PX` → 仍返回「作废」。
  - 同一折线上跨拍序列（10 拍）推进：`predictionPointAt(t)` 对 `t` 单调不减。
- **不做**：不改协议、不改 `store` 接线、不加字段。
- **CHANGELOG**：无（内部纯函数）。

### 卡 1b：剪枝按弧长 + 锚点取投影（修客户端重锚的 off-path 缺陷）

- **背景**：`eb75825` 的重锚在主路径上正确，但 `dropPassed` 的方向点积判据在权威点**横向偏离**折线时会剪错拐点。已复现（实测）：
  ```text
  prediction = { x:990, y:128, anchorTs:727, path:[{x:2277,y:128},{x:2277,y:1432}] }
  anchorPrediction(prediction, 1000, 138, 1000)
  画面、改前 = (1050.06, 128)、改后 = (1019.70, 157.96)   // 倒退 30.4px，且斜穿床
  剪枝 = [{x:2277,y:1432}]                                // 拐点 (2277,128) 被误删
  ```
  规格：`docs/design/30-movement-sync.md` §3.2（押头那三行代码块 + 下面两段“为什么”）。
- **改动范围**：`src/client/prediction.ts`、`src/client/tests/prediction.test.ts`。不改 `store.ts` / `hall.ts` / `docs/`。
- **要做**：
  1. 把权威点**投影到折线**，锚点（`Prediction.x/y`）存投影点；横向分量不进轨迹。
  2. `ahead = 画面点的投影弧长 − 锚点的投影弧长`（钳到 0）；`anchorTs = ts − ahead/v`。
  3. 剪掉「画面」与「锚点」中更靠后的那一个已经走过的拐点（**按弧长**，不用方向点积）；**至少保留最后一个途经点**（目的地点不能被剪掉）。
  4. `dropPassed` 永远返回**新数组**（现在 `index === 0` 时直接返回入参数组，两个 prediction 会共享同一个数组）。
  5. 传送判定不变：仍按**原始**权威点与画面的直线距离 > `TELEPORT_SNAP_PX` 作废。
- **验收（全部写成测试，坐标断言，不要只比弧长标量）**：
  - 上面那段复现：改后画面坐标与改前**相等**（容差 1px），`path` 仍含拐点 `(2277,128)`。
  - 权威点向北偏 10px（反向横向）同样不改斜、不倒退。
  - 权威点在画面**前方**时仍是前向跳（不倒退）。
  - 已有 16 拍跨拐点单调、1/2/3 条弧长单测、假时间轴矩阵（0/150/250/500ms）保持全绿。
- **CHANGELOG**：并入卡 2 的 `### Fixed` 条目（本卡不单独写）。

### 卡 2：意图锚点取真值 + `lead` 计算（store 接线）

- **目的**：让「站定起步 / 走路中途改目标 / 在床上点地面 / 点床走躺」四条意图路径都以**真值点**作锚，并把 `lead` 取成「画面点在**新折线上的投影弧长** / v」（= 卡 1 的 `arcLengthAhead`，**不要用直线距离**：在床上起身时那是横向偏移，会把画面凭空前推）。目标是起步 0 帧且不倒退。
- **改动范围**：`src/client/store.ts`（`beginWalk`）、`src/client/tests/prediction.test.ts`。
- **验收**：
  - 站定 → 点地面：首条关于自己的 `pos` 到达时，画面**不后退**（倒退 0px）。
  - 走路中途改目标：`lead` 保持不变，画面在切换那一刻**连续**（单帧位移 < 10px）。
  - 在床上点地面：锚点为床脚前那一点，首帧即起步。
  - 离线（`connection !== 'online'`）时不登记外推（现状保持）。
- **CHANGELOG**：`### Fixed` 一条——起步与改目标时自己的小人不再往回跳。

### 卡 3：新移动者不「补走一拍」（服务端）

- **目的**：节拍运行中才开始走的人，第一拍不许多推进「上一次拍到现在」的整段时间。
- **改动范围**：`src/hall/hall.ts`（移动者携带创建时刻；推进量 = 现在 − max(上一拍时刻, 创建时刻)）、`src/hall/tests/movement.test.ts`。
- **验收**：
  - 一拍已过 80ms 时新增移动者 → 下一拍只推进 20ms（而不是 100ms），位移 ≤ 4.4px。
  - 既有移动者行为不变（仍按实际经过时间推进）。
  - 对象驱逐后重建（`ensureMovers`）不产生追补位移。
- **CHANGELOG**：`### Fixed` 一条——开始走动时不再向前突跳一小段。

### 卡 4：观测探针（`?debug=1`）

- **目的**：让 §6.1 的硬指标可以**举证**，而不是靠肉眼。
- **改动范围**：客户端世界层（每 10s 打印一行，不进 UI、不进 React 状态）、必要时 `src/client/store.ts` 只读导出。
- **验收**：
  - `?debug=1` 时每 10s 打印 `leadMs` / `regressPx` / `posAge` / `tickSpan` 的 p50 与 max。
  - 无参数时完全不打印、无额外开销路径。
  - `regressPx > 0` 时用显眼前缀（便于在控制台一眼看到）。
- **不做**：不加协议字段、不加 HUD 文案。
- **CHANGELOG**：`### Added` 一条——`?debug=1` 的位置同步观测。
