# 开发任务卡片清单（临时）

> 规则：按端到端垂直切片；一张卡必须能独立提交、独立验证、独立回滚。**完成后从本文件删除**（它不是历史记录）。
> 依据：`00-master-design.md`、`architecture.md`、`10-hall-runtime.md`、`config.md`、`build.md`、`../db/schema.md`、`../api/`、`../ui/DESIGN.md`、`../../AGENTS.md`（硬纪律）。

## 卡 1 项目脚手架

- [ ] 一个 Worker 同时提供静态资源与接口；本地一条命令可起、一条命令可部署
- [ ] **验收**：本地访问根路径能看到占位页；部署后公网可见；静态资源请求不占用每日接口请求额度
- [ ] **依赖**：无

## 卡 2 共享契约层

- [ ] 错误码枚举（含为第二版预留的风控码段）、协议消息类型（上行 8 种 / 下行 9 种）、常量、场景数据类型
- [ ] 该层**不依赖前端与后端任何一方**，前端与服务端都从它引用
- [ ] 单元测试可运行
- [ ] **验收**：错误码表与 `../api/error-code.md` 逐条一致；协议类型覆盖 `../api/20-api-ws.md` 的全部消息；单测通过
- [ ] **依赖**：无

> 为什么单独一张卡：这是前后端唯一的共享真相，改它两边同时受影响，必须是可单测的纯数据模块。

## 卡 3 前端脚手架与设计令牌管线

- [ ] 前端工程（构建工具 + React + TypeScript + Tailwind）可构建并被卡 1 托管
- [ ] 设计令牌从 `../ui/DESIGN.md` 导出为 Tailwind 主题；样式不出现硬编码色值
- [ ] **响应式基础一次到位**：视口声明（含覆盖安全区）、窄/中/宽三档布局骨架、44px 触摸目标、输入框字号不低于 16px
- [ ] **验收**：`design.md lint` 通过；在 375×667 手机视口与桌面视口下均不溢出、无横向滚动；输入框聚焦不触发页面缩放
- [ ] **依赖**：卡 1

> 响应式必须在第二章卡就建立：先做桌面再适配手机要返工一遍布局（见 `../ui/DESIGN.md` Layout 节）。

## 卡 4 内容过滤模块

- [ ] 敏感词表 + 干扰字符剥离 + 两种入口：**检测**（用于昵称，命中即拒绝）与**打码**（用于聊天，循环替换直到不再命中后照常放行）
- [ ] **验收**：`傻·逼` 这类插入干扰字符的写法能被命中；昵称命中返回可恢复错误；聊天命中被打码但消息仍送达；词表随应用打包，不依赖外部存储
- [ ] **依赖**：卡 2

## 卡 5 匿名会话

- [ ] 首次访问签发签名 cookie（HMAC）；`GET /api/me` 返回会话内容
- [ ] 会话内容包含：用户标识、所属厅、**昵称**、本地时区、18 岁自述位、该厅中的床位号
- [ ] **验收**：连续两次请求得到同一身份；篡改 cookie 后被视为新会话（`1001`）；全程无注册步骤
- [ ] **依赖**：卡 1

## 卡 6 入场流程

- [ ] 18 岁自述确认、设置昵称、上报本地时区、大区列表与切换（DOM 界面）
- [ ] 昵称经卡 4 的**检测**入口过滤；昵称写入会话，若已认领床位则同步更新床位上的昵称快照
- [ ] **验收**：新访客必须走完自述与昵称才能进入；昵称超长/命中敏感词给出可恢复提示；可切换大区；切换后返回入场
- [ ] **依赖**：卡 3、卡 4、卡 5

## 卡 7 大厅房间服务骨架

- [ ] 房间服务类 + SQLite 表初始化 + 厅注册表加载 + 场景 JSON 加载 + 可行走网格推导
- [ ] **验收**：表结构与 `../db/schema.md` 一致；重复初始化幂等；场景数据能提供全部床位坐标与可行走格集合；厅注册表与 `../design/config.md` 一致
- [ ] **依赖**：卡 2

## 卡 8 WebSocket 握手与全量快照

- [ ] 升级前验签 cookie；前置校验（未自述 `1002` / 未设昵称 `1003`）；首条必须 `hello`；场景标识比对；下发 `snapshot`
- [ ] 快照**只发被占用的床**（空床由客户端从场景数据推出）
- [ ] **验收**：未握手就发业务消息被断开（`2004`）；场景不符返回 `2003` 并断开；未自述/未设昵称被拒；快照内容符合 `../api/20-api-ws.md`
- [ ] **依赖**：卡 5、卡 7

## 卡 9 世界渲染（静态）

- [ ] PixiJS 画场景与全部床位，按厅时区昼夜配色，按 y 排序解决遮挡
- [ ] 按设备像素比渲染（设定上限，兼顾清晰与低端机性能）
- [ ] **验收**：四种床位状态视觉可辨（空 / 被占 / 自己的 / 睡痕）；缩放平移可用；**真机（非仅桌面模拟）上帧率可接受，不发热**
- [ ] **依赖**：卡 3、卡 7

## 卡 10 自己在场与走动

- [ ] 连接后自己出现在入口；点地面发意图；服务端寻路 + 按节拍推进 + 100ms 合并广播；客户端插值
- [ ] **移动者集合（内存）与内存循环启停**：路径走完 / 断线 / 被新意图取代三种来源都能移除；集合为空时循环立即清除
- [ ] **推进量按实际经过时间计算**（不按拍数）；客户端按服务端时间戳插值
- [ ] **验收**：点地面后自己走过去；点不可行走处被拒（`3006`）且无可见报错；第二个浏览器能看到我移动且平滑；**人为阻塞一次事件循环后移动速度仍不变**；**无人在走动的时段平台用量面板上的活跃时长停止增长**
- [ ] **依赖**：卡 8、卡 9

## 卡 11 看见别人

- [ ] `join` / `leave` / `state` 增量事件；多人渲染与深度排序
- [ ] **验收**：两个浏览器互相可见；一方走动另一方平滑看到；一方关闭页面后（宽限结束后）小人消失；睡着的人不产生位置流量
- [ ] **依赖**：卡 10

## 卡 12 躺下 / 起身 / 睡着

- [ ] 状态机与归属认领；四重校验（床号合法 / 自己不在床上 / 床未被占用 / 床属于自己或尚未被认领）
- [ ] **复合意图**：`lie` = 走过去 + 躺下（路径携带到达后动作）；在床上点地面 = 起身 + 走过去
- [ ] 无输入满阈值自动转睡着；睡着时说话或发消息**自动醒**后处理
- [ ] **验收**：空床可躺并完成认领；**从远处点床会先走过去再躺下**；被占的床 `3002`；别人的床 `3003`；已在床上再躺 `3004`；不在床上起身 `3005`；睡着后说话自动醒
- [ ] **依赖**：卡 11

## 卡 13 断线宽限与睡痕

- [ ] 关闭连接时**同一步**完成三件事：把位置与路径搬进宽限会话记录 → 移出移动者集合 → 起宽限计时
- [ ] 期内重连恢复（含行进中的路径）；超时按是否在床上分流；睡痕广播
- [ ] **验收**：断网 30 秒内重连状态不变（**含位置与路径**）；断网超过宽限后他人看到睡痕（明显更暗）；不在床上断线则小人消失；重连后回到原床原状态
- [ ] **依赖**：卡 12

## 卡 14 时间驱动机制

- [ ] 三种机制各归其位：到期事件（宽限到期 / 自动睡着到期 / 每日清理）走**持久唤醒**；位置节拍走**内存循环**；状态判定走**读取时推导**
- [ ] 到期事件调度器：按到期时间排序的内存最小堆，**先比对堆顶与当前槽位，相同则不重复 `setAlarm`**
- [ ] 驱逐后重建：重算到期事件堆，并与平台上已存在的槽位对账
- [ ] **验收**：无人在线时不设任何持久唤醒；**强制驱逐后状态依旧正确**（靠推导）；`setAlarm()` 调用次数为个位数到几十次/天量级；alarm 处理器内不残留任何内存定时器
- [ ] **依赖**：卡 13

> 术语与理由见 `10-hall-runtime.md` §4。混用两种机制会直接导致「对象永不休眠」或「高频重写持久状态」。

## 卡 15 清理任务

- [ ] 睡痕清理（保留归属）+ 30 天归属释放（清空归属）
- [ ] **验收**：跨日后睡痕消失但床位仍属原主；超过 30 天未出现后床位回到可认领池；清理结果通过快照可见；一次性清理大量睡痕时不超出单次调用预算（必要时分批）
- [ ] **依赖**：卡 14

## 卡 16 全局聊天

- [ ] 上行意图 + 卡 4 的**打码**入口 + 服务端上行限流 + 消息展示
- [ ] **验收**：两个浏览器互通；敏感词被打码而非拦截（消息仍送达）；超过 5 条/秒被丢弃且不弹提示；超长消息返回 `4001`；空消息被丢弃
- [ ] **依赖**：卡 4、卡 11

## 卡 17 私聊与表情

- [ ] 私聊只推给双方；表情在世界内显示（枚举值定义在卡 2 的共享层，非法值静默丢弃）
- [ ] **验收**：第三人看不到私聊内容；对方不在厅返回 `2005`（静默不提示）；表情可见且不进二级菜单
- [ ] **依赖**：卡 16

## 卡 18 HUD 与错误反馈

- [ ] 大区名、自己床号、在线人数、当前昼夜；错误码到用户文案的映射
- [ ] **验收**：静默类错误（`3001`/`3004`/`3005`/`3006`/`4002`/`4003`/`2005`）不显示提示；可恢复类错误有可见反馈；在线人数随进入/离开实时变化
- [ ] **依赖**：卡 16

## 卡 19 移动端实测与修补

> 响应式基础已在卡 3 建立，本卡是**真机实测与修补**，不是从零适配。

- [ ] 真机走完整循环；软键盘遮挡；页面进入后台被挂起后再回前台；弱网与切网重连；横竖屏切换
- [ ] 性能降级：睡着者不用逐帧动画；低端机降低背景装饰密度
- [ ] **验收**：真机上完成完整循环（入场→走→躺→聊→起身）；输入框不被软键盘遮挡；锁屏再解锁后自动重连且状态正确；横竖屏切换不丢状态
- [ ] **依赖**：卡 18

## 卡 20 额度观测与实测校准

- [ ] 四项用量观测；三个泄漏信号检查；单厅并发与单次调用 CPU 实测
- [ ] **验收**：给出实测结论——单厅并发上限、每次调用 CPU 用量、行读取量与唤醒次数的比值、节拍实际抖动分布；确认无「常驻循环」「整表加载」「无人在线仍消耗活跃时长」三种泄漏
- [ ] **依赖**：卡 15、卡 19

## 验证方式约定

| 类型 | 方式 |
| :--- | :--- |
| 纯数据模块（2、4） | 单元测试覆盖边界（干扰字符、超长、空串、重名） |
| UI 类（9、11、18、19） | 交给 subAgent 用浏览器验证，避免大量截图占用主会话上下文。**响应式与触摸类验收必须用手机视口** |
| 协议类（8、10、12、13、16、17） | 双浏览器人工验证 + 对拍日志，逐个错误码核对 |
| 状态机类（12、13、15） | 必须覆盖边界：床位被占、重复躺下、宽限边界、跨日清理、30 天释放 |
| 时间机制（14） | 看平台用量面板的活跃时长曲线与 `setAlarm` 次数，不接受推算结论 |
| 额度类（20） | 只看平台用量面板与实测数据 |
