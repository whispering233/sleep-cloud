## 卡 5 · 模拟器实测与定性（不改代码）

**前置**：`.dev.vars` 与 `.android-env` 已就位（本 worktree 已建，都不入库）；`npm run build` 后**重启** `npm run dev`（资产清单是启动时读的）。

**样本上限**（超了没结论就写「未能验证」）：`?debug=1` 下 **3 趟**跳厅走动（每趟 ≤30s）、**2 段** `screenrecord`（各 ≤30s）、**1 次**游戏页进出。

**已完成（第 1、2 项，五次走动，RTT≈1000，60fps）**：

| 判据 | 实测 | 判 |
| :--- | :--- | :--- |
| `frameDelta` p95 / max | 18.1~18.6 / 19.8~22.7ms | 绿 |
| `selfStepPx` p95 / max | 3.7 / 4.2~4.4px（理论 3.67px） | 绿 |
| `regressPx` max | 0.4~1.5px | 绿（量级是 1px） |
| `reversals` | 0~6 | 绿（同上） |
| `camStepPx` opposed | 2%（12/600） | 绿 |
| `isMovingFlips` | 2~4（一次窗口里 5 次点击 = 5 段路） | 绿 |
| `bigStep` | 仪器加上后未再出现（此前有一次 105.8px，未复现） | 待定 |

**结论**：位置 / 帧时 / 相机三条路径没有肉眼可见的抖动 —— 用户报的「抖动」落在**摆动**上（4.5Hz ±3%，`DESIGN.md` 明说不要改幅度与频率），而「到达后快速抖动」已由卡 6 修掉（闸门跟画面走）。

**剩余**：
3. （可选）`WALK_SWAY = 0` 对照：只在「行进中也抽搐」仍复现时才需要，用来把行进中的观感归因到摆动。
4. **游戏页进出（已做，结论见下）**。

**第 4 项结论**：模拟器上拿不到「低帧率」这个条件 —— `Emulation.setCPUThrottlingRate(5)` 对本项目无效（`frameDelta` p50 仍是 16.6ms）。能给的证据是 `loopDelta`（新加，Phaser 真交给动画与猫的帧时）：卡顿帧上取到 **33.4 / 66.6ms**，说明帧时**没有被平滑夹取**（若还被夹，那些帧都会读成 16.7）；而 `smoothStep: false` 之后 `resetDelta()` 里的 `_coolDown` 夹取路径根本不会被调用。**「猫慢一半」这个症状本身没有在模拟器上复现出来**，真机低帧率下才是它的现场。
