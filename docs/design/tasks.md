# 开发任务卡片清单（临时）

> 规则：按端到端垂直切片，一张卡必须能独立提交、独立验证、独立回滚；**完成后从本文件删除**（它不是历史记录）。
> 派活的硬约束、验收基线（`npm test` / `npm run typecheck` / `npm run lint:design`）与「一次只做一张卡」见 `../../AGENTS.md`「开发流程（本项目）」，发版顺序见 `build.md` §4.3。
> 契约与预算的唯一权威是 `100-log.md`：卡片里出现的字段名、阈值、闸门都必须与它逐字一致，不一致就改代码不改文档。

**本批的统一目标**：**一行的主语是「一个人」时，昵称与 `userId` 印在一起**，并且能点开只读抽屉。理由见 `120-admin-console.md` §2.1 末段。

**派 subagent 一律带上这三条**：一条命令一步，**不要管道 / 重定向 / `&&` / 多行内联脚本**（输出工具自己会截断，不要 `tail` / `grep` 过滤）；只做卡片里写的事，别顺手改别的；工具不可用就如实写「未能验证」并退出，不要硬凑结论。

## V1 前端一次性点验（待做）

六张卡的代码已全部落地并提交，只剩静态页与终端页的交互没在浏览器里点过。一张卡交 `ui-verifier` 验完。

**契约**：`120-admin-console.md` §2.1、§9 判据 5/14/15/16；`70-privacy-risk.md` §4.7。

**验收**（条目上限 8，一次验完；起站方式见 `test.md`，需管理员登录 + 有举报/反馈/台账数据）

1. 举报表第 2 列 = `昵称 · userId`，两钉钉子（窄屏被挤压时不折行）。
2. 举报行能点开只读抽屉（Esc / 遮罩 / 「关闭」三种退出口径都对，抽屉里没有封禁按钮）。
3. 反馈表表头是「提交者」，点击能开同一个只读抽屉。
4. 台账表头仍是 8 列；「身份」格能点开抽屉。
5. 黑名单 / 审计的 `user` 行显示 `昵称 · userId`、`ip` 行只显示 IP 且不可点。
6. `/about` 与 `/privacy` 两个静态页能打开，「举报」一节里 5 条 + 3 个文本框看得见；`/privacy` 里看得到「历史举报 90 天」「永久封禁不自动清除」。

报告方式是逐条「通过 / 不通过 + 证据」，不要求改代码。
