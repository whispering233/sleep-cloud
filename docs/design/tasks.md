- [ ] 卡 1：寻路改按像素距离最短（修「绕左边缘」）
  - **症状（已复现）**：第 1 级（114 床）下，从 94 号床上方 `(1424.5, 596)` 走到 113 号床上方 `(1424.5, 752)`（直线距离 156px），实际路径 `(-28,596) → (-28,752) → (1424.5,752)`，总长 3061px：**先向左 1452px 到左边缘，再向下，再向右**。
  - **根因**：`src/hall/pathfinding.ts` 的 `findPath` 是**纯跳数 BFS**——出队撞到第一个 goal 就返回，而源节点按块号 `-1`（左余量）起入队。跨横走道带的两点「同块列直上」与「绕左余量」跳数相同，谁先入队谁赢 → 永远走左边那条。起点→源节点、目标节点→终点这两段距离**从未计入代价**。
  - **改**：改成按**实际像素距离**的最短路（Dijkstra；相邻节点的边权 = 两点欧氏距离；起点到各源节点、各目标节点到终点两段也计进总代价，取总代价最小的那个 goal）。保留「两点在同一条走道带内 → 一条直线段」的快捷返回。**不动 `src/shared/layout.ts` 的格网定义**（卡 2 才搬）、不动几何常量、不动协议。
  - **测试**（`src/hall/tests/pathfinding.test.ts`）：① 回归 case——同一列、相邻两行的两点，路径总长 ≤ 抵达该点的曼哈顿下界 × 1.6；② 属性测试（抽样若干床对）——路径总长 ≤ 起点与终点各自曼哈顿下界之和 × 1.6，且折线每一步都落在街网上（沿用现有判据）。**用 `frontPointOf` / `PITCH_Y` 推导坐标，不写死像素**（卡 3 换格距后仍须绿）。
  - **验收**：`npm test` 全绿、`npm run typecheck` 通过；`CHANGELOG.md` 的 `### Fixed` 补一条（不写任务卡语义）。
  - **不做**：不新增接口、不做路径缓存、不动厅的几何。
