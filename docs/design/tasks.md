## 验收卡 A5（剩下的未决项）

A1–A4 已实现并通过代码级独立验证；真视口取证（headless Chromium + Playwright，入口 `http://localhost:8787`）已覆盖：床位全可见与线型区分（截图位置与 `ownedBeds` 吻合）、墙的单条内沿线与无外沿描边（2560×1440）、默认缩放 12.28 格、夹取不越界、拖动跟手、无回拉、点自己回中、聊天面板 129px。**以下仍未定论：**

- [ ] **虚线节奏的可辨性（需人眼定）**：每边 26 世界像素、`DASH_PX=6` / `DASH_GAP_PX=4`（按屏幕像素给）时，1:1 缩放下实线段 6px 但间隔只有 4px（占空比 60%），缩略图上与实线难分。若要更明确，最小改法是 `DASH_PX=4` / `DASH_GAP_PX=8`（实测落在「4px 实线 + 约 7px 间隔」，且 0.6 缩放时节奏不变）——**动手前先看一眼真机**。
- [ ] **出生点在厅角导致刚进厅就看得到墙（需人眼定）**：`hall.ts` 的出生点是扫到的第一个可行走格 `(1,1)`，相机夹取在厅角 → 左侧（HUD 之下还有上侧）会出现墙带与内沿线。设计文档已按事实改口（`ui/DESIGN.md` 的 `world-wall` 行）。确认是否可接受；若不接受，考虑改出生点或初始视野，而不是改墙的画法。
- [ ] **手感第 ③ 条未测出**：走动中站在床边点床，是否落成「回中」而不是躺下（窄带约 0.1 格 ≈ 3px）。静止状态点床 → 躺下成功已由取证确认（HUD 出现床号）。真机上补测，不可接受就收窄「点自己」的半径。
- [ ] **环境未覆盖**：headless SwiftShader 软件 WebGL（真机 GPU 路径未跑）、`devicePixelRatio` 只能为 1（「窄屏高密度屏会不会糊」未验）、触摸是 CDP 合成事件（真实手指路径未跑）。真机跑一遍再收本轮。
- [ ] **帧率观感未测**：headless 软渲染下的 fps 无参考价值。真机在「有人走动 + 256 张床（含虚线）」下看是否掉帧；若明显掉帧，再考虑把静态床位层与动态小人层分开重建。
