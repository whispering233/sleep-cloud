# 开发遗留项（Backlog）

本文件收集**已决定推迟**的事项。每项必须写清：为什么延后、什么时候该回头做。已确定不做的方案（而不是推迟）不记在这里。

> 已落地、不再属于遗留项的事：复用 `WheatCloudSleep` 美术素材（已定稿并写进 `../ui/DESIGN.md`）、满员自动扩厅（已由级表取代）、跨厅串门（已不存在多厅）、世界拉远（只缩不放，见 `../ui/DESIGN.md` 的世界相机）、页面缩放（**维持浏览器默认**：不声明 `maximum-scale` / `minimum-scale`——iOS 10+ 默认忽略 `maximum-scale`，且禁缩放是 WCAG 1.4.4 失败）。

## 一、产品功能类

| 项 | 为什么延后 | 何时该做 |
| :--- | :--- | :--- |
| **聊天历史持久化** | **现在连客户端也不保留消息流**：聊天只在世界里以 8 秒气泡出现，划过去就没了（删面板列表前是「本地留最近 N 条」）。服务端存历史会带来存储成本与隐私负担 | 出现「睡醒后想看看昨晚别人说了什么」的真实反馈时。届时需同时定：存哪、保存多久、谁能读 |
| **共处时长展示**（Nylu 式「一起睡了 6h10m」） | 第 1 阶段不做 UI。**但数据已经白送**：睡痕本身就是「躺下时间 + 起床时间」，也就是一条 sleep session，现在就在存 | 第 1 阶段跑通后即可加，零改表 |
| **解绑床**（主动释放归属、不认领新床） | 换床已开放（齿轮浮层里的「更换床位」模式内点一张无主空床），但「我不想占着这张床」没有入口：解绑后我处于**没有床**的状态（HUD 没有床号、没有「回我的床」、没有暖标记），是一个负收益状态 | 出现「想把床还回池子」「想换个身份重新开始」的真实反馈时。实现 = 一条上行意图 + 一次归属清理（同 `releaseExpiredOwnerships` 的单行形态） |

| **睁眼躺姿补画** | 躺姿素材只有闭眼那一张。现在 `lying`（清醒躺着）靠代码在脸部位置叠两个点 | 在 SAI 2 里改 `bedBoy.sai2` / `bedGirl.sai2` 导出两张 PNG 即可；**替换是零成本的**（贴图换 overlay） |
| **装饰自己的床位 / 床头留言** | 属于「玩法」，不在第 1 阶段范围 | 第 2 阶段；注意这会引入 UGC 审核负担。**几何口子已留**：每间房有一块 `56×100` 的预留位（`layout.reserveOf(bedNo)`），且预留位在可走性上是**不可走**的 → 装饰物永远不会堵住街网，也不需要阻挡集 |
| **音频 / 白噪音 / 环境音** | 无音频则无音量设置，因此「设置」界面在第 1 阶段整体不存在 | 第 2 阶段；会同时带出设置界面与移动端自动播放限制问题 |
| **多厅 / 串门 / 追着夜晚走** | 单厅 + 自动伸缩已经把「厅会满」这件事消掉；多厅会立刻带出「选哪个厅 / 能不能串门 / 厅间社交割裂」三个问题 | 单个厅的并发或活跃度真的逼近平台上限时（级表已经到最后一档且仍然不够） |
| **周期地板贴图** | 房间地面与预留位已按固定色画出（`room` / `rug`，见 `../ui/DESIGN.md`「地面梯次」），房间与走道已经分得出来 | 出现「地板太平、想要一点质感」的真实反馈时。做法：格距恒定，一张 `173×156` 的贴图用 `TileSprite` 铺满整厅（1 个绘制调用），但要动 `npm run art` 管线 |
| **床号的可读性（两处）** | ①**已认领空床上偏暗**：床号用 `neutral-muted`，在**空芯**床上对底色 **5.99:1**（够），但在**有主空床**（`paper` 填充 `#313747`）上只有 **3.91:1**——低于小字 AA 的 4.5:1（端到端验证时验证方要把截图提亮 4× 才能读清）。②**会被自己挡住**：床号画在格子左下角，而人正站在床脚前中心——站在落点时，小人的头正好压住自己那张床的号牌（端到端验证实测） | 真机上确认「一眼读不出床号」或「站在床边反而找不到号」时。改法候选：①床号颜色按床位填充分档（空芯 `neutral-muted` / 有主 `neutral` 9.85:1）；②只提 `neutral-muted` 一档（会连带 HUD 与别人说的话，面积大得多）；③把床号从不被站姿遮挡的角（如右上）起算。**不动几何** |
| **「放不下」提示比渲染少吃一个字** | 气泡两行 = 28 格，截断时 `…` 自己占一格 → 实际显示 27 字 + `…`，而输入框上方那句提示按「前两行装得下的字数」报（30 字消息说「末尾约 2 字」，实际吃掉 3 字）。已在 `src/client/bubble-fit.ts` 的 `bubbleHintOf` 留 `shortcut:` 注释 | 真机出现「说好 2 字结果少 3 字」的抱怨时：把返回值 +1（并同步单测里 40 字那条） |
| **安静区 / 热闹区的分区** | 调研结论：安静陪伴与热闹聊天互斥（Nylu 与 SleepInLate 都做了隔离）。但分区在第 1 阶段会引入「选哪个区」的入口 | 出现「想安静躺一会儿但聊天太吵」的真实反馈时（那时也得先解决多厅，见上） |
| **`replaceOlderConnections` 里 `ws.close()` 也在循环里** | `hall.ts` 那段逐个关旧连接：某一条 `close()` 抛会让循环中断，**同一用户后面的旧连接漏关**，残留的重复连接各带一份附加数据，可能把已经躺下的人推回移动者集合。与刚修好的「广播给死连接发消息会抛」是同一类风险 | 出现「同一个人重复出现在厅里 / 躺下后又被推回走动」的迹象时。修法与出站守卫同理：把「关连接」也收成一个吞异常的出口 |
| **入场层的昵称输入框会被浏览器自动填充** | 两次独立观察（`ui-verifier` 的本地会话、**生产站点的部署冒烟**）都看到输入框被填了上一次的值，而 `/api/me` 返回的是空昵称 —— 用户可能不自知地用一个非预期的名字进厅。输入框**已经**设了 `autoComplete="off"`，浏览器照样填（对 `autocomplete=off` 有启发式忽略） | 真机上再用两个不同昵称复现一次。彻底规避要在挂载时清空该字段（受控组件要小心别把用户正在输的内容也清掉）；「浏览器帮忙记住昵称」到底要不要保留是个产品判断 |
| **外圈改蛇形编号** | 今天的编号是「级内行优先 + 每级只给新增外圈编号」，所以外圈里有一处空间跳变（如第 2 级：137 在右上、138 跳到左下）。改沿 L 形外圈蛇形编号能让**环内相邻号空间相邻** | 出现「顺着床号走会跳」的真实反馈时。注意：它修不了跨级的跳变（任何 L 形外圈都躲不掉），且要动编号契约与单测 |
| **HUD 的「延迟」不会过期** | 采样源是 `chat` 回投 + **按需探活的 `pong`**（两处都不引常驻心跳：心跳会阻止 Durable Object 休眠、整夜计费，见 `../api/20-api-ws.md` §1）。探活让「回到前台 / 恢复联网」也会刷新它，但**仍可能停旧数**：一直不聊天、也不切前后台，屏上那个 `42ms` 就不代表现在。做过期就要加客户端定时器触发重渲染（否则 HUD 根本不重渲染），那就是为一行诊断信息养一个循环 | 真机上出现「看着像实时但明显不准」的误判时。改法顺序：①超 30s 显示 `—`（定时器只在有样本时活着）；②改成 `42ms · 3分钟前` |
| **HUD 的连接图标与断线重连** | 连接生命周期管理与断线探测由**另一条支线**负责（现状：`state.connected` 只在快照时置 `true`、`close` / `error` 时置 `false`，**没有重连**，断线后只能刷新页面；锁屏 / 切后台 / 切网都会走到这条路径）。HUD 这轮里做一个只有两态的图标，会与那条支线的状态字段打架 | 那条支线落地后，HUD 直接接它给的连接状态（届时再决定要不要「连接中」第三态）；在此之前 HUD 不显示连接图标 |
| **`空床 n` 只会偏小** | 它由 `bedCount − ownedBeds.size` 算（与「厅满」判定同义），而归属过期是**读取时推导**，服务端不会在过期那一刻给客户端推 `bed`。于是快照之后陆续过期的床继续被算成「有主」，数字**只可能偏小**（不会把躺不上的床算成空） | 出现「显示没床位但其实有空床 / 和服务端的厅满判定对不上」的反馈时。改法：归属过期时广播 `bed(owned:false)`（每日唤醒已经会释放过期归属，缺的是那一刻的广播），或快照里额外下发一个「可认领数」 |

## 二、架构类

| 项 | 为什么延后 | 何时该做 |
| :--- | :--- | :--- |
| **`walk` 没有 ack** | 自身外推（`../api/20-api-ws.md` §6）假设服务端会接受这条意图。服务端**静默**拒绝时（`3006` 目标点不在街网 / `4002` 限流）客户端会先走一小段、2 秒无回执就冻结、再被下一条权威 `pos` 纠正。两条拒绝路径都很罕见，所以不加协议字段 | 出现「点了一下，自己走一小段又停住」的真实抱怨时。做法：给 `walk` 回一条 `{t:'ack'}`（或直接复用 `pong` 的形态），客户端等 ack 再开始外推 |
| **真碰撞（占用格 + 让路 + 死锁兜底）** | 现在**不做碰撞**：小人可以重叠、可以相向穿过（已决策，见 `../design/architecture.md` §7）。走道宽 56px、小人半宽 24.25px → 两个相向的人**必然互相挡死**，真做就得配占用格 + 让路/等待 + 超时放弃，而每拍按人查邻接与「睡着的人零成本」的计费优势直接冲突 | 出现「人一多，重叠看着难受」的真实反馈时。**不要**用渲染层「同格错位」的折中：那会让画出来的位置 ≠ 权威位置，等于在渲染层造第二个事实源 |
| **多套布局主题**（换布局公式 / 换级表） | 第 1 阶段只需要一种几何。布局是纯函数，换主题 = 换函数 + **递增布局版本号** | 出现「想要不同形态的厅」的真实需求时 |
| **老 bundle 的平滑迁移** | 布局版本不一致现在直接 `2003` + 断开（要求刷新页面）。第 1 阶段只有自家前端，刷新是可接受的 | 出现「用户停在旧页面上很久」导致频繁被踢的迹象时 |
| **D1 / 全局用户表** | 单厅 + 匿名 cookie 的规模下「用户属于哪」不是一个问题（没有第二处）。引入 D1 只增加一个需要同步的真相源 | 出现跨厅迁移、用户资料页、全局数据看板时 |
| **目录服务 / KV** | 同上 | 同上 |
| **反作弊加固**（寻路滥用之外的防护） | 第 1 阶段只有 5 条/秒上行限流 + 目标点必须在街网上。服务端寻路本身能挡住大部分伪造目标点 | 出现脚本刷走动、刷聊天等滥用迹象时 |
| **`appearance-option` 里的文字样式已成死代码** | 入场层形象选项去掉可见文字后（`gap` / `color` / `font-family` / `font-size` / `letter-spacing`）不再影响任何渲染：按钮内只剩一个预览 `span`，素材是烤好色的 PNG（不吃 `color`），选中态只剩 `border-color` 起作用。留着会让人以为 sprite 受 `color` 影响 | 下次动 `app.css` 的入场层样式时一并删（约 5 行；删完按 393×852 复看一次选中态边框） |
| **本地 dev 端口探测与绑定之间的竞态** | `npm run dev` 先探测空闲端口、再交给 `wrangler dev` 绑定，两个 worktree **同一瞬间**启动时仍可能撞一次（撞了重跑即得下一个端口，见 `build.md` §2）。彻底消掉要给端口加锁文件（`wx` 创建 + PID 存活检查） | 并行 worktree 同时启动撞端口成为常态、重跑成本明显时 |
| **睡痕过期与归属过期的「提前通知」** | 两者都是读取时推导，客户端自己算。代价：**大厅里最后一个在线的人**看不到别人睡痕到期（他不在场）——这不是问题 | 不需要回头做，除非出现「睡痕到期没消失」的实测证据 |
| **同一身份多开标签页互相顶掉、各自不停重连** | 服务端只保留最新一条连接（`hall.ts` 用 `close(1000, 'replaced')` 顶掉旧连接，这是「一个人一条连接」的设计）。但客户端只看 close code：1000 属正常关闭 → 按退避重连 → 两个标签页互相顶、各自不断重连（端到端验证实测：一次会话里累计 **38 次** `close 1000`）。语义上没错，但它**反复唤醒房间对象**（每次重连都要建连、读快照），与「按需探活、不做常驻心跳」的成本纪律方向相反 | 出现「开了两个标签页就一直在重连」的真实反馈，或用量面板显示重连造成的唤醒偏多时。做法：客户端识别 `close` 的 `reason === 'replaced'`（服务端已经带上）→ **不自动重连**，改成一条「你已在别处打开」的提示 |

## 三、风控与治理类（Phase 2）

第 1 阶段只做：**内容过滤**（昵称 + 聊天敏感词，打码不拦截）、**上行限流**（5 条/秒）、**错误码体系预留风控码位**。

| 项 | 参数/形态参考（来自 WheatCloudSleep 源码） |
| :--- | :--- |
| **举报** | `CmdReport` → 记录到独立日志 |
| **渐进惩罚封禁** | `block_period_m` 10 分钟起 → 上限 `max_block_period_m` 1440 分钟；观察期 `watch_period_m = 2 × block_period_m` |
| **违规检测维度累计** | Wheat 按 IP 维度累计（`ViolationDetector` 观察者） |
| **投票踢人** | 判定 `agree >= 2 * refuse && agree > 2`（至少 3 票同意且同意数 ≥ 反对数 2 倍）；Wheat 还有发起冷却 `vote_kick_ratetime_s` |
| **封禁维度** | 设备 id（cookie 内）+ IP |
| **年龄分区**（成人区 / 未成年区） | 第 1 阶段只存「18 岁自述」这一个字段，不做分区 |
| **聊天历史举报取证** | 与「聊天历史持久化」绑定：不存历史则事后取证只能靠实时记录 |

**已知且未解决的风险**：匿名 deviceId 存在 cookie 里，清掉即可换身份，因此封禁只能延缓不能阻止。若要真实保障必须上账号。

## 四、性能与验证类

> 这一节里**可在真机或用量面板上实测**的条目，已整理成 `build.md` §7 的《真机验收清单》（带判据与「不行就怎么补」）。跑完请把这里对应的行删掉（清单留在 `build.md`，它是常驻流程，不随条目消失）。

| 项 | 说明 | 何时该做 |
| :--- | :--- | :--- |
| **单厅容量压测** | 官方只给「单对象软上限 1,000 requests/s、单线程」，未给每对象 WebSocket 连接数上限。第 1 阶段的目标（114 床起步 / 并发 100）是拍的，必须实测校准 | 上线后按用量面板校准 |
| **Phaser 世界层帧率**（真机） | 本地已量：同屏对象数**约 60**（床 + 床号 + 小人）→ 现在**约 80**（每张床多了房间地面与预留位两块固定色贴片）。本机是 **SwiftShader 软件渲染**（28~38fps，不代表真机）。**画布 DPR 上限已提到 3**（`config.md` §3，为了与基准设备 1:1），填充率是上限 2 时的 2.25 倍 → 这条实测比之前更关键 | 真机（基准 iPhone 16）实测后。若低端机不够，最小改法是减少床号文字对象（只给整行编号）或把床号换成位图字体 |
| **桌面鼠标拖拽平移是否生效** | `ui-verifier` 用合成 `mouse.down/move/up` 拖 300px，相机只动了 0~22px 且方向不一致；改用 `Input.dispatchTouchEvent` 后平移完全正常（几何自洽）。**无法判定是应用缺陷还是合成事件的假象**（本机无真人手测） | 桌面浏览器上真人拖一次。桌面只是次场景，但它是主场景之外唯一的平移手段（另有「点自己回中」与 HUD 跳回我的床）。若是真缺陷：查 `world.ts` 的拖拽判据是否只认 touch |
| **空芯（可躺）通道的真机可辨性** | **本地已像素级验收**（明色调冷灰令牌）：空芯内部 = 地板 `primary`、有主床内部 = `paper`（面积差 1.33:1）、睡痕 = 0.45 混合，三者可辨。剩下的只是**真机低亮度**下再扫一眼 | 真机看；若判「看不出」，补救顺序 ① 加大 `paper` 与底色的差；② 无主空床床角加 `claimed` 色小标记（**不动几何**） |
| **睡痕的有效对比度** | 整图 `TRACE_ALPHA = 0.45` 会把墨拉向地板：`trace` 衬地板 4.13:1，混合后只剩 **1.75:1**，低于 3:1 门槛。这不是亮底引入的（暗底同位置也是 1.8:1 量级），但亮底是修它的时机 | 单独一张卡：`TRACE_ALPHA` 提到 **0.8** + `trace` 墨 `#4C525C` → 有效 **3.60:1**（填充也会变实：1.14 → 1.27），属于外观变化，需独立视觉验收 |
