# 开发遗留项（Backlog）

本文件收集**已决定推迟**的事项。每项必须写清：为什么延后、什么时候该回头做。已确定不做的方案（而不是推迟）不记在这里。

> 已落地、不再属于遗留项的事：复用 `WheatCloudSleep` 美术素材（已定稿并写进 `../ui/DESIGN.md`）、满员自动扩厅（已由级表取代）、跨厅串门（已不存在多厅）、世界拉远（只缩不放，见 `../ui/DESIGN.md` 的世界相机）、页面缩放（**维持浏览器默认**：不声明 `maximum-scale` / `minimum-scale`——iOS 10+ 默认忽略 `maximum-scale`，且禁缩放是 WCAG 1.4.4 失败）、**客户端本地持久化的契约与「记住缩放档位」**（已定稿并写进 `40-client-storage.md`）、**同一身份多开标签页互相顶掉后各自不停重连**（已随「带语义的 close」解决，见 `../api/20-api-ws.md` §5.1.1）、**天气（雨天 / 无雨）与雨声**（个人偏好 + 屏幕空间雨层，见 `../ui/DESIGN.md` 与 `config.md` §4）。

## 一、产品功能类

| 项 | 为什么延后 | 何时该做 |
| :--- | :--- | :--- |
| **私聊的可发现性** | 私聊本身是完整的（点一个人 = 选中 = 私聊目标，面板上方出现「私聊 <名字> ×」，服务端只投收发双方各一条，第三人零流量）。但**不点人就没有任何「可以私聊」的提示**：入口完全依赖「随手点一下别人」这个动作 | 先看名字常显落地后够不够（能看见别人叫什么，才知道那是可以点的人）；仍不够时再加入口提示——先定它是「选中后才出现的一句引导」还是「面板上一个常驻的私聊标识」，别先做样式 |
| **聊天历史持久化** | **现在连客户端也不保留消息流**：聊天只在世界里以 8 秒气泡出现，划过去就没了（删面板列表前是「本地留最近 N 条」）。服务端存历史会带来存储成本与隐私负担 | 出现「睡醒后想看看昨晚别人说了什么」的真实反馈时。届时需同时定：存哪、保存多久、谁能读 |
| **共处时长展示**（Nylu 式「一起睡了 6h10m」） | 第 1 阶段不做 UI。**但数据已经白送**：睡痕本身就是「躺下时间 + 起床时间」，也就是一条 sleep session，现在就在存 | 第 1 阶段跑通后即可加，零改表 |
| **解绑床**（主动释放归属、不认领新床） | 换床已开放（齿轮浮层里的「更换床位」模式内点一张无主空床），但「我不想占着这张床」没有入口：解绑后我处于**没有床**的状态（HUD 没有床号、没有「回我的床」、没有暖标记），是一个负收益状态 | 出现「想把床还回池子」「想换个身份重新开始」的真实反馈时。实现 = 一条上行意图 + 一次归属清理（同 `releaseExpiredOwnerships` 的单行形态） |
| **睁眼躺姿补画** | 躺姿素材只有闭眼那一张。现在 `lying`（清醒躺着）靠代码在脸部位置叠两个点 | 在 SAI 2 里改 `bedBoy.sai2` / `bedGirl.sai2` 导出两张 PNG 即可；**替换是零成本的**（贴图换 overlay） |
| **装饰自己的床位 / 床头留言** | 属于「玩法」，不在第 1 阶段范围 | 第 2 阶段；注意这会引入 UGC 审核负担。**几何口子已留**：每间房有一块 `56×100` 的预留位（`layout.reserveOf(bedNo)`），且预留位在可走性上是**不可走**的 → 装饰物永远不会堵住街网，也不需要阻挡集 |
| **音量**（0…1 / 滑杆） | **开 / 关已经有了**：声音是独立于天气的开关（齿轮里的「雨声 / 静音」）。剩下的只有「多响」：文件电平已定死，加滑杆要先定默认值与记忆方式，而当前没有需求方 | 出现「太响 / 太小」的真实反馈时。届时需同时定：滑杆值是否入本地存储、是否连开 / 关一起记 |
| **另一条雨声 / 雷声 / 其它天气类型** | 首版的成品是**纯雨**（源素材里的雷已在加工时避开），天气只有两态。雷是会把睡着的人吵醒的声音，不属于「雨天」语义 | 出现「雷声挺好的」「想要雪 / 雾」的真实反馈时。注意：每加一种天气，就要多一个视觉层与一条音频，两个预算都要重算 |
| **`prefers-reduced-motion` 下的雨** | 雨是**全屏持续运动**，而 WCAG 2.3.3 只管「交互触发」的动画，所以当前不算违规；做「减弱版」要先把「冻成静态细线」还是「干脆不画」定下来——那是外观决策，不是纯工程问题 | 出现晕动 / 不适的真实反馈时 |
| **地面涟漪 / 水花 / 湿地面** | 第二套与床位、地板交互的视觉系统（要改地板绘制与减光层之间的层级），现在没有需求方 | 出现「下雨看不出来」的反馈时——先确认是不是雨本身密度 / 不透明度不够，而不是缺涟漪 |
| **多标签页同时播放雨声** | 两个标签页各有一份 `AudioContext`，于是雨声叠成两份（略响、轻微相位差）。它属于已记录的「同一身份多开」问题族的又一个症状，不单独处理 | 与「同一身份多开」一并做时 |
| **中块（床中占位块）的内容** | 三块等分已落地，中块是**故意空着**的：块是摆放锚点、不是包围盒，而它只有 `56×33`，任何现有素材都会向上溢出 | 出现「中间那块空着浪费」的反馈时；同时要重新权衡「等分」是否还成立 |
| **别人看得见的装饰** | 现在两样东西只有自己可见，服务端完全不知道它们存在——可见性天然成立（不广播），也不占协议字段 | 出现「想让别人看见我的猫/火」的真实反馈时。那会把它从纯客户端装饰变成**需要同步、需要审核、需要容量预算**的东西，是另一个量级的决定 |
| **装饰开关（隐藏猫 / 篝火）** | 只有自己可见的东西，关掉的好处是安静；但需求方还没有，而多一个开关就多一条本地偏好键与一个设置项 | 出现「猫一直跟着有点吵」的真实反馈时。落地很便宜：`prefs` 加两个布尔 + 齿轮浮层两个开关 |
| **猫的朝向帧（左右翻面）** | 素材是正面视角，`setFlipX` 只会把尾巴换边，不表达方向；所以现在**不翻面** | 素材侧补了左右两个朝向之后。届时按水平速度符号翻面即可 |
| **多厅 / 串门 / 追着夜晚走** | 单厅 + 自动伸缩已经把「厅会满」这件事消掉；多厅会立刻带出「选哪个厅 / 能不能串门 / 厅间社交割裂」三个问题 | 单个厅的并发或活跃度真的逼近平台上限时（级表已经到最后一档且仍然不够） |
| **周期地板贴图** | 房间地面与预留位已按固定色画出（`room` / `rug`，见 `../ui/DESIGN.md`「地面梯次」），房间与走道已经分得出来 | 出现「地板太平、想要一点质感」的真实反馈时。做法：格距恒定，一张 `173×156` 的贴图用 `TileSprite` 铺满整厅（1 个绘制调用），但要动 `npm run art` 管线 |
| **床号的可读性（两处）** | ①**已认领空床上偏暗**：床号用 `neutral-muted`，在**空芯**床上对底色 **5.99:1**（够），但在**有主空床**（`paper` 填充 `#313747`）上只有 **3.91:1**——低于小字 AA 的 4.5:1（端到端验证时验证方要把截图提亮 4× 才能读清）。②**会被自己挡住**：床号画在格子左下角，而人正站在床脚前中心——站在落点时，小人的头正好压住自己那张床的号牌（端到端验证实测） | 真机上确认「一眼读不出床号」或「站在床边反而找不到号」时。改法候选：①床号颜色按床位填充分档（空芯 `neutral-muted` / 有主 `neutral` 9.85:1）；②只提 `neutral-muted` 一档（会连带 HUD 与别人说的话，面积大得多）；③把床号从不被站姿遮挡的角（如右上）起算。**不动几何** |
| **「放不下」提示比渲染少吃一个字** | 气泡两行 = 28 格，截断时 `…` 自己占一格 → 实际显示 27 字 + `…`，而输入框上方那句提示按「前两行装得下的字数」报（30 字消息说「末尾约 2 字」，实际吃掉 3 字）。已在 `src/client/bubble-fit.ts` 的 `bubbleHintOf` 留 `shortcut:` 注释 | 真机出现「说好 2 字结果少 3 字」的抱怨时：把返回值 +1（并同步单测里 40 字那条） |
| **安静区 / 热闹区的分区** | 调研结论：安静陪伴与热闹聊天互斥（Nylu 与 SleepInLate 都做了隔离）。但分区在第 1 阶段会引入「选哪个区」的入口 | 出现「想安静躺一会儿但聊天太吵」的真实反馈时（那时也得先解决多厅，见上） |
| **缩小时气泡与名字保持屏幕尺寸恒定** | 现在缩到 `0.5×` 时气泡文字只有 6.5px（画得出、读不出），而固定档里最小的一档就是 `0.5×`。想做「缩小也能读气泡」就要走另一套机制：气泡 / 名字 / 床号按 `1/Z` 缩放（像两颗暖标记那样保持屏幕尺寸） | 出现「固定档下看不清别人在说什么」的真实反馈时。**代价要先算清**：世界尺寸按 `1/Z` 放大（0.5 档气泡 200→400px 世界宽），邻近几个人的气泡会互相叠死，且「宽度上限」在屏幕尺度上不再恒定 |
| **`replaceOlderConnections` 里 `ws.close()` 也在循环里** | `hall.ts` 那段逐个关旧连接：某一条 `close()` 抛会让循环中断，**同一用户后面的旧连接漏关**，残留的重复连接各带一份附加数据，可能把已经躺下的人推回移动者集合。与刚修好的「广播给死连接发消息会抛」是同一类风险 | 出现「同一个人重复出现在厅里 / 躺下后又被推回走动」的迹象时。修法与出站守卫同理：把「关连接」也收成一个吞异常的出口 |
| **入场层的昵称输入框会被浏览器自动填充** | 两次独立观察（`ui-verifier` 的本地会话、**生产站点的部署冒烟**）都看到输入框被填了上一次的值，而 `/api/me` 返回的是空昵称 —— 用户可能不自知地用一个非预期的名字进厅。输入框**已经**设了 `autoComplete="off"`，浏览器照样填（对 `autocomplete=off` 有启发式忽略） | 真机上再用两个不同昵称复现一次。彻底规避要在挂载时清空该字段（受控组件要小心别把用户正在输的内容也清掉）；「浏览器帮忙记住昵称」到底要不要保留是个产品判断 |
| **外圈改蛇形编号** | 今天的编号是「级内行优先 + 每级只给新增外圈编号」，所以外圈里有一处空间跳变（如第 2 级：137 在右上、138 跳到左下）。改沿 L 形外圈蛇形编号能让**环内相邻号空间相邻** | 出现「顺着床号走会跳」的真实反馈时。注意：它修不了跨级的跳变（任何 L 形外圈都躲不掉），且要动编号契约与单测 |
| **HUD 的「延迟」不会过期** | 采样源是 `chat` 回投 + **按需探活的 `pong`**（两处都不引常驻心跳：心跳会阻止 Durable Object 休眠、整夜计费，见 `../api/20-api-ws.md` §1）。探活让「回到前台 / 恢复联网」也会刷新它，但**仍可能停旧数**：一直不聊天、也不切前后台，屏上那个 `42ms` 就不代表现在。做过期就要加客户端定时器触发重渲染（否则 HUD 根本不重渲染），那就是为一行诊断信息养一个循环 | 真机上出现「看着像实时但明显不准」的误判时。改法顺序：①超 30s 显示 `—`（定时器只在有样本时活着）；②改成 `42ms · 3分钟前` |
| **`空床 n` 只会偏小** | 它由 `bedCount − ownedBeds.size` 算（与「厅满」判定同义），而归属过期是**读取时推导**，服务端不会在过期那一刻给客户端推 `bed`。于是快照之后陆续过期的床继续被算成「有主」，数字**只可能偏小**（不会把躺不上的床算成空）。**同一个偏差还包括本地那两条提示**：「这是别人的床」也是按 `ownedBeds` 判的 | 出现「显示没床位但其实有空床 / 和服务端的厅满判定对不上」的反馈时。改法：归属过期时广播 `bed(owned:false)`（每日唤醒已经会释放过期归属，缺的是那一刻的广播），或快照里额外下发一个「可认领数」。**这一次广播同时消掉提示文案的偏差** |
| **插槽面板退场要不要做成看得见的动画** | 现在两态瞬切（硬纪律 34），退场那 160ms 的淡出实际作用在一块**空盒子**上：面板在同一帧就换到 idle 那一行、内容一起卸掉，盒子与聊天面板重合同色（`50-slot-panel.md` §5 有逐帧实测），用户感知是「面板瞬消」。真做动画要反过来「手势期间保住旧盒子 / 旧高度」，那是另一种布局模型（会把量与位移重新引回来，与「不量高度」直接冲突） | 出现「面板消失得太突然」的真实反馈时。做之前先定两件事：动画期间世界是否可见、可点性归谁（现阶段手势期间的盒子归属是 §4 红线的核心） |
| **插槽面板的第三个内容 / 触发源** | **第二个内容已有真实需求方：类型文本**（`reading` 会话，入口是动作行的书本图标胶囊，见 `50-slot-panel.md` §附）——面板因此变成「一次一个占用者」的**多源**模型，但**两个源天然互斥**（`reading` 与 `idle` 不同时成立），所以还不需要「谁优先」的规则。统计 / 天气 / 日历 / 键盘判定触发仍在等内容占位与实际需求 | 出现「想在打字时看到 X」的真实反馈时。届时要同时定「两个源同时 active 时谁优先」与切换动效 |
| **类型文本接后台管理** | 目前是静态文件（`public/fun/type-texts.v1.json` + `_headers` 的 `immutable` + 文件名版本号，吃 CF 静态资源的免费与缓存）。文章量、分类量上来之后要能在线增删改，必须进后台：届时内容进库、静态文件退成导出产物或直接由接口发 | 需要「改一条文案不用重新构建部署」的那天。届时要同时定：审核归谁、缓存与版本号如何失效（前端已经走文件名版本，接口方案的失效要重新定）、`sc.read.seen` 里的旧 id 怎么处理 |
| **类型文本的多分类切换** | 一期只取数据文件里**第一个分类**（内容是冷笑话，但入口与版面都按「类型文本」设计，不写死分类）。存储与协议都是按分类 id 分组的（`sc.read.seen` 的 `seen` / `current` 都是按分类的映射），只缺一个 UI 入口与「切换分类时当前条怎么办」的规则 | 真的出现第二个分类而且需要用户挑的时候。届时要同时定：选分类的控件放哪儿（面板内还是入口长按）、每个分类各自记忆当前条（数据形状已支持） |
| **按钮没有按下态 / 悬停态** | 全站胶囊按钮（`hud-action` / 齿轮 / 阅读入口 / 表情 / 发送）只有键盘的 `focus-visible` 那圈：实测 `document.styleSheets` 里含 `:active` / `:hover` 的规则 **0 条**，按下时 computed style 零变化（`ui-verifier` 对四颗按钮逐项比对）。功能都生效，缺的是「按到了」那一下即时反馈 | 出现「点了不知道有没有点上」的反馈时。触屏下 `:hover` 不可靠，按下态要能独立成立（`:active` 或按压期间的类名），并同时定它是否与 `focus-visible` 抢同一圈描边 |

## 二、架构类

| 项 | 为什么延后 | 何时该做 |
| :--- | :--- | :--- |
| **VirtualKeyboard API（`overlaysContent` + `env(keyboard-inset-height)`）** | 它是「界面真知道键盘占多少」的标准答案，但 MDN 标 Limited availability、非 Baseline（只有 Chromium）。现在整套设计**不需要键盘高度**（`60-interaction-shell.md` §1），引它只会把一条不必要的依赖加回来 | Safari 落地且 iOS 份额内的目标内核普遍支持后。届时可**删除** `visualViewport.offsetTop` 平移那条补丁 |
| **把输入框关进 iframe（键盘隔离的终点站）** | PlayCanvas 圈用这招根治「键盘缩布局视口 → 画布重建」：键盘只缩 iframe 的文档，父页画布纹丝不动。代价是 composer 整块搬进 iframe（令牌、字体、安全区、焦点跨文档、a11y 全要重来） | L3（宿主 Android 模拟器）或真机实测**仍**存在内核导致的黑闪时。届时只需替换「输入宿主」这一处，状态机与布局契约不变 |
| **广播折线替代位置采样** | 下行的 `pos` 是「位置采样」。而位置其实是闭式可算的（街网寻路 + 常量速度）——改播「被验证的折线 + 服务端起始时刻」，别人的滞后可从 `oneWay + 100~400ms` 降到 ≈`oneWay`，每拍台阶消失，出站也从 10 条/秒降到每次走动 1 条。**但它不修手感问题**（自身领先量仍需 `lead`），且是协议级改动 | 任一条成立：① 出现按位置判定的交互（距离可见性、谁能和谁说话、任何「谁先到」的规则）；② 真机/线上明确抱怨「看别人像慢半拍」；③ 唤醒次数或出站量被平台用量面板证明是瓶颈。规格与「禁止混合形态」的结论见 `30-movement-sync.md` §4.4 |
| **`lead` 前向收敛（限速追平）** | 画面领先真值 `oneWay`，于是「走到床边 → 躺下」要多站 `2 × oneWay`（RTT 500 → ≈500ms）。限速追平能把等待减半，代价是走速短暂降约 20%，并破坏「按经过时间等速推进」这条纯函数口径 | 真机反馈「到床后站着不动」明显时。规格见 `30-movement-sync.md` §3.9 |
| **真碰撞（占用格 + 让路 + 死锁兜底）** | 现在**不做碰撞**：小人可以重叠、可以相向穿过（已决策，见 `../design/architecture.md` §7）。走道宽 56px、小人半宽 24.25px → 两个相向的人**必然互相挡死**，真做就得配占用格 + 让路/等待 + 超时放弃，而每拍按人查邻接与「睡着的人零成本」的计费优势直接冲突 | 出现「人一多，重叠看着难受」的真实反馈时。**不要**用渲染层「同格错位」的折中：那会让画出来的位置 ≠ 权威位置，等于在渲染层造第二个事实源 |
| **多套布局主题**（换布局公式 / 换级表） | 第 1 阶段只需要一种几何。布局是纯函数，换主题 = 换函数 + **递增布局版本号** | 出现「想要不同形态的厅」的真实需求时 |
| **老 bundle 的平滑迁移** | 布局版本不一致现在直接 `2003` + 断开（要求刷新页面）。第 1 阶段只有自家前端，刷新是可接受的 | 出现「用户停在旧页面上很久」导致频繁被踢的迹象时 |
| **D1 / 全局用户表** | 单厅 + 匿名 cookie 的规模下「用户属于哪」不是一个问题（没有第二处）。引入 D1 只增加一个需要同步的真相源 | 出现跨厅迁移、用户资料页、全局数据看板时 |
| **目录服务 / KV** | 同上 | 同上 |
| **反作弊加固**（寻路滥用之外的防护） | 第 1 阶段只有 5 条/秒上行限流 + 目标点必须在街网上。服务端寻路本身能挡住大部分伪造目标点 | 出现脚本刷走动、刷聊天等滥用迹象时 |
| **`appearance-option` 里的文字样式已成死代码** | 入场层形象选项去掉可见文字后（`gap` / `color` / `font-family` / `font-size` / `letter-spacing`）不再影响任何渲染：按钮内只剩一个预览 `span`，素材是烤好色的 PNG（不吃 `color`），选中态只剩 `border-color` 起作用。留着会让人以为 sprite 受 `color` 影响 | 下次动 `app.css` 的入场层样式时一并删（约 5 行；删完按 393×852 复看一次选中态边框） |
| **本地 dev 端口探测与绑定之间的竞态** | `npm run dev` 先探测空闲端口、再交给 `wrangler dev` 绑定，两个 worktree **同一瞬间**启动时仍可能撞一次（撞了重跑即得下一个端口，见 `build.md` §2）。彻底消掉要给端口加锁文件（`wx` 创建 + PID 存活检查） | 并行 worktree 同时启动撞端口成为常态、重跑成本明显时 |

## 三、风控与治理类（Phase 2）

已落地：**内容过滤**（昵称拒绝 + 聊天打码；约 2.5 万条词库，昵称走窄词集）、**上行限流**（5 条/秒）、**封禁**（user / ip 两维度，拒绝入场）、**来源台账与审计**、**举报**（上行 `report`、24 小时去重、被举报人最近 10 条发言作证据、90 天清空、后台只读列表）。语义与边界见 `70-privacy-risk.md`；接口见 `../api/30-api-admin.md`。

| 项 | 为什么延后 | 何时该做 |
| :--- | :--- | :--- |
| **禁言（`muted` / `5001`）** | 没有取证链时，禁言只能让用户看到「话发不出去」却解释不了；封禁（拒绝入场）才是用户真正要的「拉黑」 | 出现「只想让他闭嘴、不想让他走」的真实反馈时 |
| **渐进惩罚** | 需要「违规维度累计」作为前提，而现在**没有自动判定**，举报来的信号也还是人工在读（不存历史、不做累计）。参考参数：Wheat `block_period_m` 10 分钟起 → 上限 1440 分钟、观察期 `2 × block_period_m` | 有了举报或自动检测之后 |
| **投票踢人** | 同上（有举报但无累计），且小厅里容易变成少数人工具。Wheat 判据：`agree >= 2 * refuse && agree > 2` | 并发与举报量上来之后 |
| **年龄分区**（成人区 / 未成年区） | 只有「18 岁自述」一个字段，且它是自述不是核验；分区的法律意义不成立 | 真要做年龄保障时，那不归本产品解决 |
| **设备指纹 / 更强的来源信号** | 平台只给 IP / 国家 / UA（已取到边界）；再强就是自建指纹，属过度采集，隐私代价远大于收益 | 不回头做。唯一正路是 L2 凭据（见下） |
| **换内容过滤引擎（Aho–Corasick）** | 今天 2.5 万条用「逐词字面查找 + 区间合并」：单条 200 字约 1.0 ms、最坏构造 1.8 ms、峰值占免费额度 CPU 的 0.6%–1%（口径见 `config.md` §6）。AC 能把最坏情况摊成线性，代价是多几套测试 | 词表涨一个数量级、加入拼音/正则后单条超 2 ms、或峰值 CPU 超 3% 时 |
| **词表的更新回路** | 词表是生成产物，改它 = 一次部署。缺的是「线上发现漏网词 → 补进来」的通道 | 举报里反复出现同一类词时（配合举报卡一起看） |
| **存量昵称不重校验** | 新词表只作用于**新的** `hello`；已在厅里或离线持有昵称的人不会被重查。原因：重校验要扫 `identity` 表（行读取放大），且当事人不在场、改不了名 | 出现旧昵称卡住风控的真实投诉时（届时做「下次 `hello` 时一次性检查」） |
| **形近字 / 繁简归一** | 需数千条映射表（Wheat 形近字典 1,331 行、`ToolGood.Words` 繁简+形近共 1.4 万条），收益低于已做的插入字符与全角归一 | 出现「用形近字绕过」的实测证据时 |

### 三、1 L2 凭据扩展（匿名不改，只多一种凭据）

**问题**：今天只有一种凭据（签名 cookie），“清 cookie / 无痕 / 换设备” = 身份与床位一起丢。同时封禁只能延缓（清 cookie 免成本换身份）。

**为什么不现在做**：没有需求方（还没有真实用户丢过床），而且**它对封禁几乎无用**——任何需要当事人配合的凭据，攻击者都不会出示。

**该做什么**：WebAuthn 匿名凭据（passkey，无账号、无邮箱、系统弹窗一次）> 可选登录 > 找回码。**L1 一个字不用改**：`user_id` 语义不变、`bed.owner_user_id` 关联键不变，只加「凭据 → 身份的映射」；`identity` 表已经是它的地基（`../db/schema.md` §4.1）。

**何时**：出现「床位丢了 / 换手机想接着睡」的真实反馈，或封禁被证明无效到影响运营时。

**已否决的做法**（不要重提）：派生式 id（`hash(ip+ua)`）、把签名 cookie 镜像进 localStorage（等于把 HttpOnly 交给 XSS）、用户自持找回码（密码的差版）。

### 三、2 按 IP 的跨连接限流

**问题**：限流只挂在一条连接上，重连即清零。

**为什么延后**：它解决的是「重连绕过 5 条/秒」，而**封禁落地后这条路本身就被堵了**（被封的人连不进来）。先观测，再决定维度。**何时**：出现「换身份重连刷屏」的实测证据时。

### 三、3 素材 / 材料管理（后台第二期）

**问题**：现在素材是**构建期管线产物**（`npm run art`，产物入库），没有运行时上传。

**为什么延后**：后台改素材要引入 R2 + 上传 + 审核 + CDN 刷新四件事，而现在**没有内容运营方**——“后台管素材”只是“以后可能需要”。

**何时**：出现真实的内容运营需求（例如装饰物上线后要换图）。届时还要同时定：图片审核归谁、旧图怎么下线（老 bundle 引用旧图集的问题）。

| **渲染时钟平滑**（把“节拍晚点补上的位移”均摊到后续几帧） | 快照改成固定节拍发送后，单帧台阶的来源只剩一个：服务端节拍偶尔晚点（100ms 的拍拖到 260ms），客户端会在那一帧一次补上 ~20px。**为什么延后**：逐帧模拟显示 1× 滞后在这组场景里不劣于 1.5×，而“平滑”是新机制（会动客户端时间轴），得先有真实数据。**本地实测的结论是「现在不需要」**：`tickSpan` p95 = 102ms（节拍极准），唯二的晚点（1496ms）都发生在「停后重新起步」那一拍——而那时窗口跨度远超 `MAX_INTERPOLATION_DELAY_MS`，客户端本来就取端点、不跨窗口插值，没有台阶可平 | 生产上跑一次「节拍实际抖动」那条里的同一个探针。若 `tickSpan` p95 > 150ms 或 `posAge` p50 > 200ms 且真机观感有台阶，再做；两者都没有就不做 |
| **捏合的锚点残差约 16px** | 带触摸面的桌面 Chromium + 合成双指实测（中点固定、比例 1 → 0.60）：锚点处的最佳对齐偏移 dx=+16px / dy=+8px，≈ 一格的 15%（小于半格，粗判据「不整体跑掉」已满足）。成因未定：可能是残余手指在收尾时拖了一下，也可能是逐帧重算的精度 | 真机上若「捏到哪、哪就跑」看得出来：把锚点从「手势起点」改成逐帧「两指中点位移 + 距离比」重算 |
| **双击必然发 2 条 `walk`** | 双击 = 两次轻点，代码本就是逐 tap 分派；5 条/秒限流内无坏结果。若用户心里把双击当“一次动作”，就在客户端做双击去抖 | 出现真实抱怨时 |
| **提示条自清只挂在 `animationend`** | 动画被外力取消/禁用（截图管线、未来的 `prefers-reduced-motion` 分支）时提示条会常驻；产品默认路径下不复现 | 改提示条生命周期时一并改 |
| **提示条遮住顶部两行床号** | 提示条出现时盖住 y≈41~77 的床号约 3 秒（`pointer-events:none`，不影响点击） | 窄屏面板高度与提示条位置一起看时 |

## 五、部署与交付类

| 项 | 说明 | 何时该做 |
| :--- | :--- | :--- |
| **push main / PR 的常驻 CI** | tag 触发的部署工作流里已经跑 `npm test` / `typecheck` / `lint:design`，但**只在发版那一次**；main 上的日常提交依旧没有任何 CI 校验 | 有人在 main 上合入未经本地三条基线的改动时 |
| **部署版本标记与回滚** | 平台保留版本历史（`wrangler deploy` 也能给版本打 tag/message）；现在回滚靠本机 `npm run deploy` 重推旧代码 | 生产真出过一次需要回滚的事故 |
| **端到端冒烟脚本** | CI 现在只探 `GET /api/health`；「入场 → 走动 → 躺下 → 另一客户端确认可见」需要 WebSocket 客户端才能验 | 想自动挡住「接口活着但厅坏了」那一类回归时 |
| **占位符机制的终局** | 域名与 zone 现在靠 CI 注入以避免入库。如果哪天接受域名进仓库，占位符 + `sed` 那一步就能整个删掉 | 决定公开入口域名时 |
| **action 版本维护** | `actions/setup-node@v4` 已触发 Node 20 弃用警告，advisory 还建议把 action pin 到 commit SHA | 下次动工作流时 |
