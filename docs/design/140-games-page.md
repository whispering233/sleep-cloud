# 游戏页（games page）

**一句话**：礼物托盘里的「游戏」打开的是一整屏**纯程序化的东西**——它跟大厅无关，也拿不到大厅的任何数据；大厅只是暂时让开（画布暂停、雨声挂起），人还站在厅里。

这一页同时定了第二件事：**在场但不在看大厅**这个人怎么被别人看见（`act` → 名字后面两个字）。

## 1. 位阶与顺序

| 项 | 决定 |
| :--- | :--- |
| 页面态顺序 | `加载 → 说明面板（若需要）→ 入场层 → 大厅 → 游戏页` |
| 挂载点 | `App.tsx` 里挂在 `ChatPanel` **之后**、`AboutOverlay` **之前**——层级靠 DOM 顺序、不加 `z-index`（与 `90-about-panel.md` §1 同一种做法） |
| 与明暗的关系 | `tone-layer` 仍在最上：游戏页在睡下档打开时画面偏暗。**不接受例外**——「明暗只有一层」是硬纪律，给游戏页开例外等于再造一个明暗状态机 |
| 与聊天面板 | 游戏页盖住它。面板里的动作行在非空闲态（打字 / 举报）已被「收起」胶囊占位，因此**游戏只可能在 `composer === 'idle'` 时被打开**，不需要额外的退场逻辑 |
| 整屏写法 | 复用 `.entry-overlay`（`position: fixed; inset: 0`）+ 安全区内边距 + 自己可滚，卡片与标题复用 `.entry-card` / `.entry-title`——它就是第三种「临时整屏页」，不再造第二套排版 |

## 2. 入口与出口

**返回是一个栈，不是两颗按钮**：`大厅 ← 游戏列表 ← 具体游戏页`，每层一条 `history` 条目。

| 方向 | 是什么 |
| :--- | :--- |
| 进列表 | 礼物托盘里的「游戏」（`aria-label="游戏"`，44×44 描边胶囊）→ 压 `list` |
| 列表 → 具体页 | 点条目 → 压 `game`，列表收起（§3） |
| 具体页 → 列表 | **系统返回键** / `Esc` / 浏览器后退。**具体页不画任何按钮**（零 chrome，理由见下） |
| 列表 → 大厅 | 左上「返回」胶囊（44×44）/ `Esc` / 系统返回键 —— 三颗都是同一个 `back()` |
| 大厅层返回键 | 维持现状：**离开站点**（代价见 §8） |
**为什么不给具体页一颗按钮**：出口是「往回一层」，不是这一页的东西；而 `.games-stage` 是 `inset: 0` 铺满整页，一颗常驻胶囊只能浮在游戏画面上。列表页有可见出口、系统返回键在两层都工作，所以具体页选择**零 chrome**：一个像素都不占。桌面的兜底是 `Esc`。

**返回栈的纪律**（漏一条的失败形态是整站被退出去）：

| 项 | 规则 |
| :--- | :--- |
| 唯一状态来源 | `popstate` 决定当前层级；页内按钮与 `Esc` **只调 `back()`**，不直接改状态 |
| 压栈 | 只发生在进入下一层那一刻（`pushLevel('list')` / `pushLevel('game')`），一层一条，不重复压 |
| 刷新归位 | 加载时若 `history.state` 残留，`replaceState` 归大厅：刷新一律回大厅，不恢复游戏页 |
| 停住 | 封禁（`5002`）/ 被顶替强制关页时先 `history.go(-depth)` 再归位，否则栈里留一层空列表 |
| 不做恢复 | 浏览器「前进」顺带正确（同一条映射），但没有「恢复某个游戏上一帧」这回事 |
| 压栈必须有用户激活 | Chromium 会**跳过没有用户手势的 `history` 条目**。模拟器实测：页面加载时 `pushState` 两次（无手势）→ 按返回键**直接退出 Chrome 到桌面**，两条全被跳过；把同样的两次 `pushState` 放进 `pointerdown` 里（有激活）就正常逐层回。我们的两次压栈都紧跟点按，所以不会被跳；**将来若想在进站时自动打开某一层，这一条会立刻咬人** |

**为什么推翻首版的判断**：首版不碰 `history`，代价是安卓返回键直接离开站点（连接关闭 → 宽限 60 秒 → 在床上的人变睡痕）。零 chrome 又拿掉了具体页的可见出口，于是返回键从「省掉一次点击」变成唯一出口，必须支持。

## 3. 列表

| 项 | 决定 |
| :--- | :--- |
| 形态 | **纯文字条目**：标题 + 一句说明 +（可推导的）「横屏更好」小标。不做缩略图——每个条目一张图就要多写一段绘制代码，且与游戏本体争启动时间 |
| 触击 | 整行可点、高度 ≥ 44px、描边胶囊外观（可点的才画成胶囊） |
| 「横屏更好」 | **由基准尺寸推导**：`base.w > base.h` 就标。不新增字段，也不靠人记 |
| 空态 | **不画**：扫不到任何游戏时列表就是空的（只剩标题与「返回」），`games-registry.test.ts` 的「至少一个条目」会先红——不为不可能发生的状态写 UI |
| 滚动 | 条目多了由卡片自己滚（同 `.entry-card`），不出现第二个滚动容器 |
| 进入之后 | 列表收起（`.games-page[data-playing]`）：列表只是「选哪一个」的那一下，选中后整页交给舞台。**换游戏 = 返回列表再点**（一次返回，§2），不需要离开这一页 |

条目**不是手写的表**：`games/<id>/` 文件夹就是注册（§4.1），扫描器在 `src/client/games/registry.ts`。列表看到的仍是五个字段：`id`（文件夹名）+ `title` / `blurb` / `base`（`meta.ts`）+ `load`（扫描器现包）。

## 4. 游戏契约

### 4.1 注册：文件夹即注册

游戏代码**不在项目源码里**，住在仓库根的 `games/`：

```text
games/
└── skyline/          ← 一个游戏 = 一个子文件夹 = 一次注册；id = 文件夹名
    ├── meta.ts       ← export const meta = { title, blurb, base }
    ├── index.ts      ← export default { mount }
    └── …             ← 游戏自己的模块与资源，扫描不认它们
```

| 项 | 规则 |
| :--- | :--- |
| 扫描器 | `src/client/games/registry.ts` 里两条 `import.meta.glob`：`*/meta.ts` **eager**（列表要它）、`*/index.ts` **lazy**（点开才载） |
| 为什么要两个文件 | `meta` 必须能被列表读到而**不载入游戏代码**；同一个文件里既写 `meta` 又写 `mount`，扫描它就得侵蚀懒加载 |
| 没有中心表 | 没有手写的条目数组、没有 `registry.json`。加一个游戏 = 加一个文件夹 |
| 只支持子文件夹 | 单文件游戏没法把 `meta` 与 `mount` 分开（要么被打进首屏，要么旁挂一个 JSON = 还是两个文件，只是散着），所以只有一种形态 |
| 守护 | 两条单测：①每个 `games/<id>/` 都有 `meta.ts` + `index.ts`、`meta` 三字段齐；②`games/**` 里除同目录相对 import 外**零运行时项目 import** |
| 构建期 | 不做代码生成、不挂 npm script：扫描是 Vite 在构建期展开的，产物仍是普通 chunk |

### 4.2 模块与上下文

```ts
export interface GameModule {
  /** 画进 `el`，返回值为 `dispose`。必须自己管 rAF / 定时器 / 事件，并在 `dispose` 里停掉。 */
  mount(el: HTMLElement, ctx: GameCtx): () => void;
}

export interface GameCtx {
  base: { w: number; h: number }; // 条目自己声明的基准尺寸
  dpr: number;                    // **每基准像素对应的设备像素**（= min(dpr, MAX_DPR) × 舞台 scale，封顶 2 × MAX_DPR）
  now: () => number;              // 外壳给的单调时钟，游戏不必自建时间源
}
```

### 4.3 外壳与舞台

**外壳（`games/host.ts`）负责**：按 `base` 建一块舞台、等比 `scale = min(cw/bw, ch/bh)`、居中、裁掉溢出、交出 `el`；同一时刻只挂载一个；换条目 = 先 `dispose` 再 `mount`；关闭页面 = `dispose` + 清空 `el`。**舞台尺寸变了（转屏 / 窗口尺寸变）就按新 `scale` 重挂一次**（`dispose` + `mount`），游戏不必自己处理 resize。

**`dpr` 是「每基准像素对应的设备像素」，不是裸的 `devicePixelRatio`**：舞台是「按基准尺寸建、再用 CSS 放大 `scale` 倍」，所以 `canvas.width = base.w * dpr` 只有在 `dpr` 含 `scale` 时才能一颗设备像素对一颗位图像素（`docs/design/140-games-page.md` 的作者踩过：只乘 `devicePixelRatio` 时真机上 1.2 倍放大，窗格边缘是插值出来的）。上限取 `2 × MAX_DPR`：手机上 `scale` 约 1.2，`3 × 1.2 = 3.6` 刚好落在里面；桌面大窗口下继续乘上去会白吃几十 MB 显存与位图，所以在这里封顶、宁可略软。

**游戏自己负责**：往 `el` 里放 `canvas`（`canvas.width = base.w * dpr`，CSS 宽高 = `base.w/h`）或 SVG / DOM；自己的 `requestAnimationFrame` 与定时器；**在自己的手势里**建 / `resume()` 它的 `AudioContext`——点列表那一刻的手势不算（中间隔着 `await import`，Safari 已判定解锁失效）。

**禁止**：`import` 任何项目模块（`store` / `ws` / `world` / `audio` / `prefs`…）；发任何上行；读本地存储；读网络。这一条让每个游戏都能独立删除，改大厅不会连带改游戏。

**唯一例外是 `import type`**：游戏要吃到 `GameModule` / `GameCtx` 这两张契约，只能从 `src/client/games/types.ts` 引，且必须写成 `import type`（`verbatimModuleSyntax` 下产物里一行不剩，不构成运行时依赖）。复制一份契约到 `games/` 不在选项里——那就是两份契约，改一份忘一份比耦合更贵。守护单测按「运行时 import 为零」判。

**基准尺寸**：条目自己声明，**贴近手机上可用区域的比例**（393×852 竖屏下可用区约 377×776 ≈ 1:2）。`1:1` 的方形会在上下各留近 190px 背景，像一张被裁窄的海报；`16:9` 会被缩到 377×212，基本没法玩，只有确实需要横向视野的条目才用，并因此自动标上「横屏更好」。

### 4.4 大厅上下文（预留，今天零实现）

游戏想读大厅（在线人数、我自己的显示态…）时**不是**去 `import store`，而是走一个门面：

```ts
// src/client/games/api.ts —— 将来游戏唯一允许 import 的项目模块
export interface HallSnapshot { /* 白名单字段，逐个加 */ }
/** 每次调用现读：无缓存、无副作用、返回新对象 */
export function hall(): HallSnapshot;
```

- **今天不建这个文件**：没有需求方就没有死代码，`games/**` 保持零项目 import（由 §4.1 的守护单测钉住）。
- **不订阅**：游戏自己就有 rAF（§4.2 已要求），每帧读一次即可；订阅要在 `dispose` 里断，等于给契约多一条错法。
- **不给整份状态**：`getState()` 会把 `people` / 位置 / 气泡一起交出去，那是把大厅的私有状态变成游戏依赖。
- **加字段的流程**：先改这一节（写清字段语义与来源）→ 再加到 `HallSnapshot` → 再放行那一条 import → 同步守护单测的白名单。
- **禁止项不变**：不发上行、不读本地存储、不联网。

## 5. 让位：世界与音频

| 让什么 | 怎么做 |
| :--- | :--- |
| 世界 | 走**同一套整屏页挂起**：判据只有一处——纯函数 `coversWorld`（`src/client/covered.ts`，入场层 / 说明面板 / **游戏页** / 求签页）→ `setWorldSuspended(true)` → Phaser `game.loop.sleep()`，恢复时 `resetDelta()` + `wake()`。游戏页**不另造一对 pause/resume**：两套机制会各自记一份暂停态，醒来时先醒的是哪一份就成了运气。**位置与状态一个字节都不改**：暂停的是渲染循环，不是人 |
| 大厅音频 | 进页面 `suspendHall()`、退出 `resumeHall()`——雨声不与游戏声叠着响。不建 `AudioContext`（本来没建就什么都不做）、不改用户偏好、不共用 context、不做统一总开关 |
| 封禁 / 被顶替 / 厅满 | `5002` 与任何停住（`halted`：`blocked` / `replaced` / 布局版本不符 / `2002` 厅满）到达时**强制关掉游戏页**：整屏页会把提示条和入场层盖住，那一瞬间人以为自己被封了却看不到原因 |

## 6. 在场状态（`act`）与头顶后缀

**问题**：进游戏页后人与服务端的连接还在（§5 的暂停只停渲染），所以别人看到的是一个站着不动、不发消息的人。要说明「他还在，只是不看厅里」。

| 项 | 决定 |
| :--- | :--- |
| 语义 | `act` 与显示态（`state`）**正交**：它说的是「我在看什么页面」，不是「我躺着还是睡着」 |
| 上行 | `act: { act: 'game' \| 'hall' }`，**只在进 / 出游戏页各发一次** |
| 存储 | 连接附加数据（可丢弃的临时量）：断线即丢，别人立刻看不到后缀——可接受降级 |
| 下行 | `Person.act?: 'game'`（`hall` 时字段省略）；随 `join` / `snapshot.people` 下发，变化复用一条 `state` 报文 |
| 渲染 | 名字行改成 `名字 \| 游戏中`（同字号、同色、不加粗）。**只在名字行**：聊天气泡上的名字行不加 |
| 截断 | **后缀优先保留，名字先截断**（否则 `小明 \| 游戏中` 会把名字吃掉一半） |
| 缩放 | `Z < ZOOM_TEXT_MIN = 0.5` 时名字与后缀一起退役（`全厅` 档下没有文字） |
| 文案 | 服务端只发机器值 `'game'`；中文映射在 `src/client/act-text.ts`（同 `error-text.ts` 的做法），协议里不放中文 |
| 重连 | 重新握手后若仍在游戏页，客户端要在 `hello` 之后补发一次 `act`；漏写的后果是后缀静默消失，没有任何报错 |
| 谎报 | 这是少数「客户端声明即可信」的字段：服务端无从推导，而后果只有别人名字后面两个字，没有收益 |

**为什么不给大厅内的显示态也加后缀**：躺着、睡着、睡痕在画面上本来就看得出来；给名字加字只会在同一个信息上画两遍，还持续吃掉名字宽度。

## 7. 不做什么

- **不做具体页的出口按钮**：零 chrome（§2）。返回键与 `Esc` 就是出口，一层一颗按钮只会盖住游戏。
- **不做游戏恢复**：刷新回大厅，不记住「你上次在玩哪个」（§2）。
- **不做缩略图**：条目多了再说，届时每个条目要写第二张画（不是另开一个字段就能解决）。
- **不做游戏内的聊天、分数持久化、排行榜、服务端积分**：游戏是纯本地的观赏物，没有第二个真相源。
- **不做游戏页里的上行**：除了 §6 那一条 `act`，游戏页对协议是完全沉默的。
- **不让游戏直连大厅模块**：想读大厅只能走 §4.4 的门面（它今天还不存在，等于「读不到」）。

## 8. 已知代价

| 代价 | 说明 |
| :--- | :--- |
| 大厅层返回键 | 不在游戏页时，返回键照旧离开站点：连接关闭 → 宽限 60 秒 → 在床上的人变睡痕 |
| 配对纪律 | `push` 与 `back` 必须严格配对（§2）：漏一次，返回键会把站点整个退出去 |
| 具体页没有可见出口 | 手机靠系统返回键、桌面靠 `Esc`；桌面用户只能靠惯例知道怎么退（换来的是游戏画面零遮挡） |
| 刷新回大厅 | 游戏页不做恢复（§2） |
| 睡下档画面偏暗 | 明暗层不例外（§1）；在躺下 / 睡下档打开游戏页，程序化夜景会整体压暗 |
| `act` 断线即丢 | 重连后靠客户端补发；漏写没有报错 |
| 非基准比例下留背景 | 舞台只等比缩放、不按屏幕比例重排（程序化美术不要求移动端自适应）：基准是 1:2，横屏或平板上就上下左右留背景 |
| 熄屏 | 游戏页里挂后台时，大厅渲染循环本来就是"slept"状态，回来时 `wake(true)` 一帧恢复；但游戏的 rAF 由浏览器节流，不在本契约保证范围内 |
