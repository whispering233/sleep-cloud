# 配置说明

## 1. 厅注册表（唯一需要人工维护的配置）

| 字段 | 类型 | 说明 |
| :--- | :--- | :--- |
| `id` | string | 厅标识，用作房间服务实例名与 cookie 中的归属标识。**一旦上线不可更改** |
| `name` | string | 显示名（界面/HUD 使用） |
| `timezone` | string | 厅固定时区（IANA 名称），决定昼夜与每日清理时刻 |
| `sceneGuid` | string | 场景标识，客户端与服务端必须一致 |
| `capacity` | number | 床位数，第一版 256 |

第一版注册表：

| id | name | timezone | sceneGuid | capacity |
| :--- | :--- | :--- | :--- | :--- |
| `asia-1` | 亚洲厅 | `Asia/Shanghai` | `dorm-asia-01` | 256 |
| `europe-1` | 欧洲厅 | `Europe/Berlin` | `dorm-europe-01` | 256 |
| `america-1` | 美洲厅 | `America/New_York` | `dorm-america-01` | 256 |

**满员怎么办**：手动在此表加一条（例如 `asia-2`），部署即生效。老用户不受影响。不做自动扩厅（见 `backlog.md`）。

## 2. 时间常量

| 常量 | 值 | 说明 |
| :--- | :--- | :--- |
| `GRACE_MS` | 60_000 | 断线宽限期。期内重连恢复原状态，超期按是否在床上分流 |
| `AUTO_SLEEP_MS` | 300_000 | 在床上无输入满 5 分钟自动转睡着 |
| `TICK_MS` | 100 | 位置推进与广播合并的**目标**周期。仅在有人走动时启用（内存循环，非持久唤醒） |
| `MOVE_MS_PER_TILE` | 250 | 走完一格的目标耗时。推进量按实际经过时间计算，节拍抖动只影响平滑度、不影响移动速度 |
| `SLEEP_TRACE_CLEAR_HOUR` | 8 | 厅时区 08:00 清理睡痕 |
| `BED_OWNERSHIP_TTL_MS` | 30 天 | 归属释放阈值（最后出现时间） |
| `EMOTE_MS` | 2500 | 表情在世界内的显示时长。**只用于客户端渲染时推导过期**，服务端不记状态 |

## 3. 限制

| 项 | 值 | 说明 |
| :--- | :--- | :--- |
| `UPSTREAM_RATE_PER_SEC` | 5 | 每连接上行限流（条/秒），超出丢弃 |
| `NICKNAME_MAX_LEN` | 16 | 昵称长度上限（按字符计） |
| `CHAT_MAX_LEN` | 200 | 全局聊天消息长度上限（按字符计） |
| `CHAT_LOG_MAX` | 50 | 客户端本地保留的最近消息条数（只用于显示；服务端不存历史，见 `backlog.md`） |
| `SCENE_BED_COUNT` | 256 | 场景数据中的床位数，**必须等于该厅的 `capacity`**；不一致视为配置错误（启动时校验并报错） |
| `ENTRY_REQUIRE_AGE_CONFIRM` | true | 入场是否要求 18 岁自述确认 |

## 4. 密钥

| 名称 | 用途 | 存放 |
| :--- | :--- | :--- |
| `SESSION_SECRET` | 会话 cookie 的 HMAC 签名 | 平台密钥存储（`wrangler secret`），**不写入仓库** |

本地开发把它放进 `.dev.vars`（`cp .dev.vars.example .dev.vars`，该文件不进仓库）；**任何环境缺少该密钥都直接报错**，绝不静默使用可猜的密钥——生产与本机可能共用同一个域名，按域名判断「这是本机」是靠不住的。（生产表现为 500 + 日志里的 `SESSION_SECRET 未配置`，见 `build.md` §4.2。）

**这是对称密钥（HMAC），不是公私钥对**：同一把密钥既签名又验签，所以它只有一个要求——不外泄。谁拿到它就能伪造任意用户身份的会话 cookie。

**轮换的真实代价**：密钥一换，现有 cookie 全部验签失败 → 每个人都变成**新身份**，而他们原来的床仍绑在旧用户标识上，要等 30 天归属释放才回到可认领池。也就是说轮换 = 所有人（临时）丢床。

因此**第一版不做轮换**（没有泄露迹象就不换）。真要轮换，得先做身份迁移：让旧密钥只用于验签一段时间，把旧 cookie 里的用户标识搬进新 cookie，再停用旧密钥。

## 5. 场景数据（每个厅一份，手写 JSON）

| 字段 | 类型 | 说明 |
| :--- | :--- | :--- |
| `guid` | string | 场景标识。客户端与服务端必须一致，不一致返回 `2003` |
| `width` / `height` | number | 网格列数 / 行数 |
| `beds` | array | `{ bedNo, x, y }`：床号 → 格子坐标。条数必须等于该厅的 `capacity`；坐标范围与该厅容量属于**配置错误**，启动时就报错 |
| `blocked` | array | `[x, y]` 不可行走格（墙与家具）。**床格不需要写在这里**：可行走格 = 网格内 ∧ 非 blocked ∧ 非床格 |
| `decorates` | array | `{ sprite, x, y }`：零星道具（灯、公告板等） |
| `backgrounds` | array | `{ sprite, x, y }`：第一版就是一条从 `(0, 0)` 开始可平铺的地板贴图 |

坐标一律按网格计（格子，不是像素）；格子到像素的换算由客户端按缩放决定。**床的轮廓由 `beds` 画**，不要在 `decorates` 里再铺 256 个床精灵。

**一份数据，两个读者**：静态资源路径是 `/scenes/{guid}.json`（客户端在收到快照后按 `sceneGuid` 取用），服务端在构建时读入同一份文件（推导可行走网格与床位坐标）。**不得各自维护一份副本**，否则出现「服务端认为不可走而客户端画得出」这类分歧。

```json
{
  "guid": "dorm-asia-01",
  "width": 35,
  "height": 35,
  "beds": [{ "bedNo": 0, "x": 2, "y": 2 }],
  "blocked": [[0, 0], [34, 0]],
  "decorates": [{ "sprite": "lamp", "x": 1, "y": 1 }],
  "backgrounds": [{ "sprite": "floor", "x": 0, "y": 0 }]
}
```

**第一版的厅**：35×35 格，外围一圈墙；256 张床按 16×16 排在偶数格上，奇数格自然形成床间走道（每张床四周都是走道，走得到床边才躺得下）。

第一版手写，不做编辑器（见 `backlog.md`）。

## 6. 内容过滤数据

| 文件 | 内容 |
| :--- | :--- |
| 敏感词表 | 一行一词，随应用打包 |
| 干扰字符表 | `·（）【】！？《》￥` 等，匹配前剥离 |

**空白、零宽字符与大小写同样不影响匹配**（`傻 逼`、`傻`+零宽字符、`FUCK` 都会被命中）。剥离只作用于判定，不改写发出去的内容（打码除外）。

打码替换为**等长**的 `*`（`傻·逼` → `***`，整段一起打），因此聊天消息的长度与其余部分不受影响。

第一版随包发布，不做热更新。词表变更走一次部署（静态资源与包体积均免费/宽松）。

## 7. 前端可见配置

由服务端下发，不硬编码在前端：

| 项 | 来源 |
| :--- | :--- |
| 本人身份与所属大区 | 会话接口 |
| 厅时区、场景标识、容量 | 厅元信息接口 |
| 在线人数 | **只在 WebSocket 里下发**（快照的 `hall.online` 与 `join`/`leave`/`state` 上的 `online`）——它是运行时事实，不是厅的静态元信息 |
| 全部时间常量与限制 | 不下发（服务端自行执行，前端不需要知道） |

## 8. 环境差异

| 环境 | 差异 |
| :--- | :--- |
| 本地开发 | 只注册 1 个厅、容量可调小（便于制造「厅满」「床位被占」等场景）；使用本地密钥 |
| 生产 | 完整注册表；密钥由平台注入 |
