# 配置说明

> **厅的尺寸、床位与格子规格、级表、可走性与布局契约不在这里** —— 一律见 **`20-layout.md`**（唯一来源）。本文只放**运行时可调的配置与限额**。

## 1. 只有一个厅

| 项 | 值 | 说明 |
| :--- | :--- | :--- |
| 厅标识 | `main-1` | 房间服务实例名（`idFromName`）。**没有厅注册表、没有大区、没有多厅** |
| 布局版本 | `LAYOUT_VERSION`（如 `room-1`） | **几何是程序化生成的**，所以一致性校验的对象从「场景文件」变成「布局版本号」。客户端建连时必须在 `hello` 里带上它，不一致返回 `2003`（防止旧 bundle 连上新几何） |
| 床位数 | **运行时事实**，不是配置 | 由级表（`20-layout.md` §3.1）与 `meta.bed_count` 决定：117 ~ 9558 之间自动伸缩 |

**为什么没有厅注册表**：一个厅时，「厅在哪」不再是配置问题；真正需要人工维护的只剩级表（`20-layout.md` §3.1）。将来若真的要多厅，那时才需要注册表（见 `backlog.md`）。

## 2. 时间常量

| 常量 | 值 | 说明 |
| :--- | :--- | :--- |
| `GRACE_MS` | 60_000 | 断线宽限期：到期把床上的行转成睡痕（`state → 'trace'`）。**与「重连能不能恢复」无关**——那个只看床位行（见 `10-hall-runtime.md` §13） |
| `AUTO_SLEEP_MS` | 300_000 | 在床上无输入满 5 分钟自动转睡着（**显示态读取时推导**，由一个到期事件负责写库与广播） |
| `TICK_MS` | 100 | 位置推进与广播合并的**目标**周期。仅在有人走动时启用（内存循环，非持久唤醒） |
| `TICK_LOG_MS`（定义在 `src/hall/hall.ts`） | 300_000 | `tick` 日志的周期（5 分钟一条）。**工作集是连接**而不是移动者：`hello` 起、最后一条连接关掉就清除；对象被驱逐重建后若没有新 `hello` 就不恢复——宁可少一条统计，也不要一条永不清的循环。见 `100-log.md` §7 |
| `WALK_SPEED_PX_PER_S` | 220 | 走动速度（世界像素/秒）。**推进量按实际经过时间算**，节拍抖动只影响平滑度、不影响速度 |
| `DAILY_WAKE_UTC_HOUR` | 20 | 每日唤醒时刻（UTC 20:00 = 北京 04:00，低峰）。同时刻做两件事：**归属释放** + **缩级评估** |
| `BED_OWNERSHIP_TTL_MS` | 30 天 | 归属释放阈值（依据 `last_seen_at`）。**归属过期同样是可读取推导的**：判定「这张床能不能躺」时把过期归属当作无主 |
| `BED_SWITCH_COOLDOWN_MS` | 10_000 | **换床冷却**：从「我名下那张床的认领时刻」（`bed.claimed_at`）推导，只挡「再认领另一张床」（`3008`）——“躺回自己那张”不受影响。**不挂定时器**（读取时推导，同睡痕/归属过期） |
| `CHAT_BUBBLE_MS` | 8_000 | 聊天 / 私聊**气泡**的显示时长。同人后来的消息覆盖前一条并重置计时；过期按「到期时刻 vs 现在」推导（**不挂定时器**），服务端不记状态 |
| `PROBE_TIMEOUT_MS` | 2_000 | **探活超时**（只在客户端）：发 `ping` 后这么久没有 `pong` → 判连接已死、关掉并重连 |
| `INTENT_ECHO_TIMEOUT_MS` | 1_500 | **意图无回执超时**（只在客户端）：发出上行后这么久没收到任何「关于自己的下行」→ 视为可疑，触发一次探活 |
| `RECONNECT_BACKOFF_MS` | 1_000 / 2_000 / 4_000 / 8_000 / 15_000 | **重连退避序列**（封顶 15 秒），成功后归零；**页面 hidden 期间不重试**。理由与三条探活触发点见 `../api/20-api-ws.md` §5.1 |
| `PREDICTION_STALE_MS` | 2_000 | **自身外推的保鲜期**（只在客户端）：从「最后一条关于自己的 `pos`」起算，这么久没收到任何 `pos` → 停在最后一个外推点（**不回退**）。基准是**真值时刻**、不是锚点时刻；携带领先量的闸门取它的一半。规格见 `30-movement-sync.md` §3.7 |
| `IDENTITY_FORGET_MS` | 90 天 | **来源信息留存期**：`identity.last_ip` / `last_country` / `ua_hash` 在这么久无访问后被清空（**不删行**）。由每日唤醒执行，见 `70-privacy-risk.md` §7 |
| `BLOCK_PURGE_MS` | 30 天 | **到期封禁记录的清理延迟**（从 `until_at` 起算）。**永久封禁（`until_at` 为空）永不清理** |
| `AUDIT_TTL_MS` | 365 天 | **审计留存**，由每日唤醒删除 |
| `ADMIN_SESSION_MS` | 24 小时 | 后台会话（`sc_admin`）有效期；过期重登一次，成本可忽略 |

**速度为什么是 220**：一格 173px ≈ 0.79s、一屏 393px ≈ 1.8s。它服务的是「一屏之内的走动手感」，**不负责跨厅**（第 1 级厅宽 2361px 是 10.7s，末档 20526px 是 93s——跨厅这种场合不由走动承担）。两条硬约束：相机跟随上限 `CAMERA_FOLLOW_PX_PER_S = 500` 必须大于它；`../ui/DESIGN.md` 的「不跳」口径要求小人单帧位移 <10px（60fps 下 3.7px）。

**没有昼夜、没有厅时区**：`SLEEP_TRACE_CLEAR_HOUR`、厅 `timezone`、`owner_tz` 以及整套时区换算都已删除（见 `00-master-design.md`「在场与时间模型」）。**色调的档位与时间无关**（按自己的显示态，见 `../ui/DESIGN.md`「三档色调」）。

## 4. 天气与雨声

| 项 | 值 | 说明 |
| :--- | :--- | :--- |
| 天气状态 | `rain: true / false`（落盘为 `sc.weather` 的 `kind`） | 客户端本地偏好（`sc.weather`，值 `none` / `rain`），**只驱动雨层画面**。**不进协议**、服务端不知道、两个人可能不同 |
| 与雨声的关系 | **各自独立** | 两个键、两颗胶囊：无雨也可以只听雨声（屏幕不画雨），雨天也可以静音（只看雨）。两者都不是「总开关」 |
| 首次默认 | `false`（无雨） | 缺键即无雨。**所有偏好键的默认值都是常量**，不读时钟、不按日期推导（见 `40-client-storage.md` §3） |
| 雨声状态 | `sound: true / false`（落盘为 `sc.sound` 的 `kind`） | 客户端本地偏好（`sc.sound`，值 `none` / `rain`），缺键 = **静音**。默认值是常量，不读时钟、不按日期推导（同 §3 全表规则） |
| 雨声文件 | `/audio/rain-loop.v1.wav`（30 s）、`/audio/rain-loop-intro.v1.wav`（8 s） | 单声道 / 32 kHz / 16-bit PCM。**版本号写进文件名**，换素材必须改名（`immutable` 缓存下浏览器不会再来问） |
| 早播切换 | 主循环就绪后 **1 s 交叉淡化** | 小文件只负责「尽快出声」；切完停掉它的 source 并释放 buffer |
| 雨声电平 | 文件内已做好（峰值 -3 dBFS），播放增益固定为 1 | **只有开 / 关，没有音量**（见 `backlog.md`）。关 = 齿轮里那颗胶囊切到「静音」，与天气无关 |
| 雨滴纹理 | **2 × 14 CSS px** 竖线，运行时 `Graphics.generateTexture` 生成 | 不走 `npm run art`（那是手绘素材的管线）；宽度 2px 经相机 `DPR` 放大后是恒定屏幕粗细 |
| 雨滴速度 | `speedY 950…1250`、`speedX -90…-30`（CSS px/s） | 屏幕空间，因此与相机缩放无关 |
| 雨滴不透明度 | `0.24…0.40`，色令牌 `line` | 覆盖率 ≈ 1.2%，全屏平均亮度下降 < 1%——**不是第二层明暗** |
| 雨滴寿命 | `(屏幕高 + 70) / 950 × 1000` ms | 按屏幕高算：落到底边之下才死，存活粒子数 ≈ 发射率 × 寿命（基准机约 160） |
| 发射率 | `quantity 2` / `frequency 12`（ms） | ≈ 167 颗/秒 |
| 降雨过渡 | 400 ms 线性淡入 / 淡出 | 走 Scene 的 `update`：**不挂 tween、不挂定时器**。400 ms 说的是**整层 alpha**；淡入时粒子密度按一个寿命（约 1 s）自然爬满，所以肉眼到「满雨」约 1 s——这是刻意的缓入，不是漏了 |
| 常驻内存 | 主循环解码后**常驻约 3.8 MB**，切「无雨」不释放（小循环的 1.0 MB 在交叉淡化后释放） | 再开不必重解（字节本来也在 HTTP 缓存里）；代价是整页存续期间占用，属已知取舍 |

## 5. 密钥

| 名称 | 用途 | 存放 |
| :--- | :--- | :--- |
| `SESSION_SECRET` | 会话 cookie 的 HMAC 签名 | 平台密钥存储（`wrangler secret`），**不写入仓库** |
| `SESSION_SECRET_PREV` | **上一把**签名密钥，**只用于验签**（密钥环） | 同上；正常时为空 |
| `ADMIN_TOKEN` | 后台登录令牌（32 字节随机） | 同上 |

| 项 | 值 | 说明 |
| :--- | :--- | :--- |
| `ADMIN_LOGIN_MAX_PER_MIN` | 5 | 同一 IP 每分钟登录尝试上限，超出 429。**取不到 IP 时不限速**（本地开发没有那个头） |

本地开发把它放进 `.dev.vars`（`cp .dev.vars.example .dev.vars`，该文件不进仓库）；**任何环境缺少该密钥都直接报错**，绝不静默使用可猜的密钥。

**这是对称密钥（HMAC），不是公私钥对**：同一把密钥既签名又验签，所以它只有一个要求——不外泄。谁拿到它就能伪造任意用户身份的会话 cookie。

**轮换走密钥环**：签名一律用 `SESSION_SECRET`，验签先试它、失败再试 `SESSION_SECRET_PREV`。轮换步骤 = 「把当前密钥挪到 `_PREV`、写入新的 `SESSION_SECRET`」；回到来的用户一经验签通过就重签成新密钥（每次响应都重签）。**旧密钥至少保留到活跃用户都回来过一次**（以 400 天的 cookie 寿命为上限，实际一两个月即可）。

**为什么要有密钥环**：没有它，一次轮换 = 现有 cookie 全部验签失败 → 每个人都变成**新身份**，而原来的床仍绑在旧用户标识上，要等 30 天归属释放才回到可认领池。也就是说**轮换 = 所有人（临时）丢床**。这个代价高到「不敢轮换」，等于没有轮换能力。密钥环把它降到「什么都不丢」。

## 6. 内容过滤数据

词表是**生成产物 + 一份手工维护的小表**，合成一份 JSON 随应用打包（构建期内联，运行期不读文件）。

| 项 | 内容 |
| :--- | :--- |
| 数据 | `src/shared/blocked-words.json`，按**类目**分组（`categories`）另有手工维护的 `curated` 一组 |
| 规模 | 25,376 条（外来 15 类 25,265 + 手工 111）。上游会增删，**以 `npm run words` 的输出为准** |
| 来源 | `konsheng/Sensitive-lexicon`（MIT），**固定 commit**，取其中 15 个类目文件 |
| 排除 | `零时-Tencent.txt`、`网易前端过滤敏感词库.txt`：第三方转存（作者的 MIT 覆盖不到），且含 505 个**单字词条**——实测让日常聊天 9.2% 的字符变星号，却不增加检测力（真实信号都是 2 字以上短语） |
| 生成 | `npm run words`（`tools/words/`）：拉 15 个类目 → 去重 → 合并 `curated.txt` → 写 JSON。**只在改词表时手动跑一次**（需要访问 GitHub 固定 commit）；产物入库，构建 / 部署不访问上游，运行期也不读文件 |
| 许可 | 词库 MIT 原文随源留在 `tools/words/`；`CHANGELOG.md` 记来源 |
| 干扰字符表 | `·（）【】！？《》￥` 等，匹配前剥离；**剥离在折半角之后判定**，所以 `傻～逼` / `傻－逼` / `傻＿逼` 与半角写法一样命中 |

**空白、零宽字符、大小写、全角半角同样不影响匹配**（`傻 逼`、`傻`+零宽字符、`FUCK`、`ＦＵＣＫ` 都会被命中）。剥离只作用于判定，不改写发出去的内容（打码除外）。

打码替换为**等长**的 `*`，因此聊天消息的长度与其余部分不受影响。第一版随包发布，不做热更新。

### 两条路径用不同的词集

| 路径 | 词集 | 理由 |
| :--- | :--- | :--- |
| 聊天 / 私聊打码 | **全部类目** | 误伤代价只是几个星号，可以偏严 |
| 昵称拒绝 | **九类**（色情、色情词库、政治、暴恐、涉枪涉爆、反动、贪腐、新思想启蒙、非法网址）+ 手工表 | 昵称命中即**无法入场**，误伤代价是用户进不来。因此排除 GFW / 民生 / 补充 / 其他 / COVID / 广告 六类；剔除 10 条**拆词残留**（`疫情` `肺炎` `中央` `政府` `武汉` `总理` `北京` `兼职` `招聘` `网络`）；再剔除**单字词条**（单字检测力极低，而昵称命中就是进不来） |

### 联系方式与引流（打码，不拒绝）

聊天与私聊除了词表，还过一遗**联系方式模式**：手机号、邮箱、URL、裸域名、平台引流（`qq` / `微信` / `vx` / `v信` 后面跟 4 位以上账号）。命中一律**打码**，不拒绝。

它跑在**第二套归一化文本**上——保留 `.` `-` `_` `:`（词表那套把它们全剥掉，剥掉之后邮箱的域名要点与裸域名都无从判定）。位置映射与词表共用，所以打码照旧等长、分隔符一起变星号（`138-1234-5678` 整段）。

裸域名的 TLD 列表**小而保守**（`com cn net org io cc tv info top vip shop site app xyz club link live`）：`me` / `co` / `so` 这类会撞上普通英文词尾，收进来 `internet` / `laptop` 就会被整词打码。反例（`internet` / `laptop` / `3.14 和 2.71` / `床号 12345 明天 67890` / 无点的 `a@b`）都钉成了单测。

拼音与缩写只进**手工表**（`shabi` / `caonima` / `nimasile` / `gannima` / `qunimade` / `nmsl`）：**不加** `sb` / `nb` / `2b` 这类两字母缩写（误伤），不加数字谐音（`88` = 拜拜）。

### 引擎与代价（实测口径）

测于 Node 22 单核，按 **2.4 万条**那个版本的词集；现在 25,376 条，耗时同比约 +5%。workerd 的 V8 版本不同，数值可能有 ±50% 偏差。

| 项 | 数值 |
| :--- | :--- |
| 单条 9 字 | 约 0.31 ms |
| 单条 200 字（`CHAT_MAX_LEN` 压满） | 约 1.0 ms；最坏构造（200 个同首字符）约 1.8 ms |
| 模块初始化归一化 2.5 万条 | 约 31 ms，**一次性**。它计入平台的 1 秒 startup 预算，**不占**每请求 10 ms 的 CPU 预算 |
| 峰值 CPU 占比（限流 5 条/秒） | 0.6% – 1% |
| 联系方式那一遗 | 与词表共享同一遍归一化输入（第二套 strip 表），六条模式另跑。含它在内的 200 字最坏构造实测 **2–3 ms**（`w`×200、`a@b.b.b…`、全数字）——无回溯爆炸，远低于 5 条/秒对应的预算 |

匹配是**逐词字面查找 + 区间合并**，不用 Trie / Aho–Corasick：这个规模下实测够用，且最坏情况有界。**首字符分桶被否决**——`w` 开头的域名条目有 5,750 条，用户发 200 个 `w` 就会放大到 15 ms/条（可构造）。换引擎的阈值见 `backlog.md`。

## 7. 前端可见配置

| 项 | 来源 |
| :--- | :--- |
| 当前床位数 `bedCount` | **厅下发**（快照与 `resize` 消息）——它是运行时事实，不是静态元信息 |
| 在线人数 `online` | **只在 WebSocket 里下发**（快照的 `hall.online`，以及 `join` / `leave` / `state`） |
| 无主空床数（HUD 的「空床」） | **客户端推导**：`bedCount − ownedBeds.size`（归属位图就是「有效归属」，谓词与「能不能躺」逐字对应）。**不新增下发字段**；已知偏差是归属过期不会主动推，数字只可能偏小（见 `backlog.md`） |
| 延迟（HUD 的「延迟」） | **客户端采样，不占任何下行字段**：取 `chat` 回投、以及**按需探活的 `ping` / `pong`** 的往返（RTT）。**不做常驻心跳**（会阻止房间服务休眠，见 `../api/20-api-ws.md` §1）——探活本来就只在怀疑连接已死时发，顺手把它的往返也当样本（所以回到前台 / 恢复联网后延迟会自己刷新一次）；没有样本时显示 `—` |
| 产品版本号（齿轮浮层） | **构建期注入**（`vite.config.ts` 把 `package.json` 的 `version` 写成 `__APP_VERSION__`），**不走任何接口**；前后端同一次部署，因此没有第二个版本号需要核对 |
| 布局版本 | 会话/元信息接口与快照各一份，供客户端自检 |
| 全部时间常量与几何常量 | **不下发**：前端引用同一份 `src/shared/` 常量，编译期内联 |
| 色调档位 | **客户端本地推导**（按自己的显示态） |
| 缩放档位（自由缩放 / 全厅 / 0.5× / 0.75× / 1×） | **客户端本地状态**（`store.zoomMode`），不进协议、不进快照。**来源**：显式锁定的档读自**本地存储**（键 `sc.zoom.mode`，规格见 `40-client-storage.md`）；缺键或不合法一律回 `自由缩放`。整页加载后按它恢复比例，**连续比例（自由缩放模式下的捏合结果）不持久化、回 `1×`** |
| 类型文本（冷笑话等） | **静态文件** `/fun/type-texts.v1.json`：懒加载、静态资源直给，**不进 Worker 代码、不进任何接口**。**版本号只在文件名里**（常量 `TEXT_PACK_VERSION` 是唯一来源，与 `public/_headers` 的 `immutable` 配套，换内容必须改名）；JSON 内的 `schema` 只表**形状**版本。阅读进度存在本地（键 `sc.read.seen`，见 `40-client-storage.md`），服务端不知道它的存在 |
