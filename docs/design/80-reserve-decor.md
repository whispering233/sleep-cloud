# 子模块设计：我的预留位装饰（篝火与猫）

每间房有一块 `56×100` 的**预留位**（`20-layout.md` §2）。第 1 阶段往里放两样**只属于我、只有我看得见**的东西：**床头的篝火**与**床尾的猫**。

**本文是这两样东西的唯一规格来源。** 几何（在哪放）归 `20-layout.md`；长什么样、暖色怎么算归 `../ui/DESIGN.md`；这份文档只管**行为**：什么时候亮、什么时候睡、怎么跑、什么时候说话。

## 0. 范围与边界

| 项 | 决定 |
| :--- | :--- |
| 谁看得见 | **只有我自己**。它们不进 `people`、不进 `state.bubbles`、不进 `ownedBeds`——服务端完全不知道它们存在 |
| 服务端 | **零改动**：没有协议字段、没有错误码、没有数据库列、没有广播。可见性天然成立（不广播），不是靠过滤实现的 |
| 几何 | 摆放锚点一律来自 `20-layout.md` 的预留位三块；猫的行走复用**共享街网**（`src/shared/pathfinding.ts`），不引入第二套可走性 |
| 改写状态 | 两者都**只读** `me`（我的显示态与我拥有的床）与 `decor`（选了哪样），不写 store、不进 React 的渲染循环（逐帧状态住在世界层，`AGENTS.md` 硬度 17） |
| 装饰的选择 | **每块单选 + 「无装饰」**（§4）：世界层只认「这一块选到了我」这**一个**判据；没选中的装饰不画，**也不可点** |
| 不做 | 用户自定义装饰（UGC）、他人可见的装饰、素材包（多包清单 / 包级开关）——见 `backlog.md` |

**为什么值得为「只自己可见」写一条子模块**：它不带来任何社交语义，却要跟三样东西严格遵守同一条口径——我的显示态（三档色调的驱动）、街网（猫不能穿床）、预留位几何（不能堵街）。不写清就会各自长出一套。

## 1. 预留位的三块

预留位沿**床长方向**等分三块（`BED_H / 3 ≈ 33.3` 世界像素高，宽 56）：

| 块 | 位置 | 候选（`DECOR_BLOCKS`） | 默认选出 |
| :--- | :--- | :--- | :--- |
| **床头装饰块**（`head`） | 靠床头那三分之一（y 最小） | `fire` | **篝火** |
| **床中占位块**（`middle`） | 中间三分之一 | 无 | **空着**（暂定、无规划） |
| **床尾宠物块**（`foot`） | 靠床脚那三分之一（y 最大） | `cat` | **猫的窝** |

规则：

1. **三块只是摆放锚点，不是包围盒。** 素材比一块高（猫 58.5、篝火燃烧时约 42 世界像素——按可见墨迹算，帧框里那圈光晕的透明边不算），**允许向上溢出**：篝火最高冒出房间上沿约 9px，猫的上半身会压到中块。分块契约保证的是「床头 / 床中 / 床尾各住谁」，不是「谁不能越过界线」。
2. **画面上不分块**：预留位仍是一整块 `rug`，不画分界线、不加色阶（三块之间的视觉差异会让「一间一块空地」读成「三格地板」，而且每床要多两个绘制对象）。
3. **摆放锚点**：篝火 = 床头块的**底边中心**（火堆压在中线上、火苗往上窜）；猫的窝 = 床尾块的**底边中心**（猫的脚站在房间的床脚边线上）。
4. 行的**左右错位**由预留位本身决定（`reserveOf` 已按行奇偶镜像），三块跟着走，不需要另写镜像逻辑。
5. **每块最多摆一样。** 同一块的候选互斥（不能同时摆篝火与台灯、不能同时养猫与狗），换候选就是换掉这一块的内容，不叠加。**互斥只发生在块内**：床头选什么与床尾选什么互不影响（§4）。

## 2. 篝火

### 2.1 位置与亮灭

| 项 | 决定 |
| :--- | :--- |
| 放在哪张床 | **我拥有的那张床**（`ownedBedNo`）的床头块。没有床就没有篝火 |
| 什么时候燃 | 我的显示态 ∈ {`lying`, `asleep`} → 播燃烧循环；其余（`roaming` / `trace`）→ 切到**熄灭帧** |
| 选不选它 | **只有床头块选到 `fire` 才画**；选「无装饰」= 整摊**不画**。这与「熄灭」不是一回事：熄灭是状态（柴、灰、石圈还在），不画是没有（§4） |
| 熄灭后 | 不隐藏：留下柴、灰与石圈。「熄灭」是状态，不是消失——与「床有人/没人」靠形态而不是靠消失表达是同一条语言 |
| 换床 | 篝火跟着 `ownedBedNo` 走；换床必然先起身，所以搬过去的那一刻它本来就是熄灭的，不存在「火苗搬家」 |
| 断线 | 沿用最后一次已知的 `me`（不为网络抖动把火掐掉） |
| 裁剪 | 那张床不在可视窗口内就不画（与床位同一套裁剪口径） |
| 命中 | **不可点**：它不参与「人 > 猫 > 床 > 地面」的优先级，点它等于点它所在的位置（预留位不可走 → 落到最近的空床/地面判定） |

### 2.2 素材与动画

| 项 | 值 |
| :--- | :--- |
| 燃烧 | 6 帧、8fps、循环；墨迹 **48 × 32~42**（帧框 96×99，多出来的是光晕的透明边） |
| 熄灭 | 1 帧（同一素材屏掉火苗/火星/辉光，留柴 + 灰 + 石圈）；墨迹 **48 × 21**（与燃烧帧共用同一个帧框，切亮灭时柴堆不位移） |
| 锚点 | 墨迹**底边中心** |
| 颜色 | 素材原色：墨 → `neutral`、白 → `paper`，**橙色与光晕原样保留**（映射规则见 `../ui/DESIGN.md`「构建期要产出的变体」） |

### 2.3 与三档色调的关系

篝火是画布对象，**跟着整屏那一层减光一起暗**（不为它单独留第二套色值，也不加画布滤镜）。暖色面积：1× 下约 1600 世界 px² ≈ 屏面 0.5%，与「暖色总面积 < 5%」相容。

## 3. 猫

### 3.1 归属与窝

| 项 | 决定 |
| :--- | :--- |
| 绑谁 | **绑「我」**，不绑床：我没有床的时候它也必须存在（首次进厅就是这种状态，见 3.5） |
| 选不选它 | **只有床尾块选到 `cat` 才存在**；选「无装饰」= 不画、不推进、不可点、问候也不发（§4） |
| 窝 | 我拥有的那张床（`ownedBedNo`）的**床尾块底边中心**；没有床 = 没有窝 |
| 窝的作用 | 我躺下时它回那里睡；换床时窝跟着换 |
| 它的位置 | 只在客户端。别人看不到，也不会被别人的任何消息影响 |

### 3.2 状态

猫只有一个消费者视角的状态机，**每个状态都由「我的显示态」直接决定，不是自己攒出来的**：

| 我的显示态 | 猫 | 播什么 |
| :--- | :--- | :--- |
| `roaming`（或还没有显示态） | 跟到我身后 60px 待着（§3.3） | 移动中 `walk` / `run`；到了 `idle` |
| `lying` / `asleep` | 走回窝里睡（窝就在我那张床的床尾） | 移动中同上；到窝 `sleep` 循环 |
| `trace` / 没有 `me` | 不画 | — |

到位的判据是**距离**（目标点与当前位置重合，或剩余路程为 0），不是计时器。起身会立刻把它从 `sleep` 拉回移动——没有「醒来动画」这一档，`idle` 的第一帧就是睁着眼。

**这个状态机只在「床尾块选到了 `cat`」时运行**：没选中的猫不推进、不落位、也不可点（§4）。

### 3.3 移动

| 项 | 决定 |
| :--- | :--- |
| 路径 | **街网**：窝与目标点都直接在街上——窝的锚点（床尾块底边中心）正好落在床脚前那条横走道的边界上（`isWalkable` 在 `y % CELL_H === BED_H` 处为真），所以不需要额外开一个「门口」节点：`findPath(当前位置, 目标点)` 一条就够。它不会穿床、不会穿墙 |
| 跟随目标 | **跟在我身后 60px**：沿我所在走道的轴（竖走道走 y、横走道走 x）拉开，方向取**我刚才来的那一侧**，停下来保持上一次。候选顺序：当前轴的反侧 → 同轴另一侧 → 另一轴两侧，取第一个可走的。为什么不「站旁边」：走道只有 56px 宽，小人 48.5 + 猫 46.5 → 并排需要 47.5 的中心距，而走道内最多只能拉开 27px，**几何上做不到不重叠**；前后拉开 60 > 猫高 58.5，才是不重叠的唯一解 |
| 不重叠的判据 | 两条贴图都是**脚底锚点**，所以「同一轴拉开 ≥ 两条贴图里较高的那条（猫 58.5）」即贴图方框不相交。60 是这么来的，不是拍的 |
| 速度 | `clamp(1.2 × 剩余**折线**长度, 260, 1320)` px/s：远处飞奔、近处收步（绕拐角时按真正要走的路算，不是直线）。**任意距离都在约 2 秒内追上**（末档跨厅 ≈ 1.9s），所以 `hop` 之后不需要「传送」这种例外 |
| 动画切换 | 速度 > 300 px/s 播 `run`，否则 `walk`；剩余路程 ≤ 6px 就按站定处理，播 `idle`（/ 窝里 `sleep`）。**到位容差与碎步**：没有它，最后几像素会让 `walk` 与 `idle` 逐帧翻转，静止时看起来像在抽动 |
| 重算 | 目标点移动超过 24px，或厅的床位数变了（街网几何变了）→ 重算一次折线；重算用同一份 `findPath`，不引入第二套寻路 |
| 推进 | 按**实际经过的时间**沿折线推进（与小人同一条「推进量按时间算」的纪律），不按拍数 |
| 朝向 | **不翻面**：素材是正面视角，左右翻只会把尾巴换边，不表达方向 |
| 静止时 | **必须看不出位移**：站定后不追一个抖动的目标、不做碎步修正。它靠三件事保证——① 同一动作的帧**共用一个裁框**（见 `../ui/DESIGN.md`「多色素材」），否则逐帧锚点会让身体左右滑；② 到位容差吃掉最后几像素；③ 目标点移动 ≤ 24px 时不重算折线 |

### 3.4 问候

| 项 | 决定 |
| :--- | :--- |
| 何时 | **每次打开页面后的首次进厅**、猫第一次跑到我附近的那一刻（「首次」是本次页面加载的首次，不是首次访问；重连不算） |
| 说什么 | 「欢迎回来」——每次打开页面回来都会说一句（重连不重发），所以按「回来」写 |
| 怎么显示 | 复用**聊天气泡的外观**（圆角矩形 + 尾巴，可复用件），但对象是猫自己的，**不进 `state.bubbles`**（那是聊天通道，进了就变成「有人说话」） |
| 多久 | 4 秒；到点由渲染时比较时间戳决定，不挂定时器 |
| 之后 | 本次页面内不再重复；**重连不发**（回到前台不该被反复打招呼），换床也不发；下次打开页面会再说一次 |
| 退役 | `Z < ZOOM_TEXT_MIN` 时与其它世界文字一起不画（猫本体照画） |
| 进厅位置就是我的床脚时 | 不单独处理：猫的窝就在那张床的床尾，它只是走一小段出来，走到我附近说话 |

### 3.5 边界情形

| 情形 | 行为 |
| :--- | :--- |
| **首次进厅、还没有床**（常态：出生点是「最小可认领床的脚前走道」，躺下才认领） | 猫照常出现、照常问候。起跑点 = 我旁边**沿街网 120px** 处（`nearestStreetPoint(我 + (0, 120))`），跑过来再说话；若那个点算出来离我不到 40px（贴着墙夹取后可能发生），改用「我 + (0,120)」本身 |
| 我在走动 | 猫持续跟随（重算阈值见 3.3），不会因为我在走就停在原地 |
| 我 `hop` 到厅的另一头 | 猫从原位置跑过去（速度公式保证约 2 秒）；相机直接落位，不等它 |
| 我躺下 | 猫回窝睡；即使它此刻在厅的另一头也走回来 |
| 我换床 | 窝跟着换。换床必经起身（猫那时已经离开旧窝），所以它只是沿街网走到新窝；若出现「睡着时窝变了」的异常态，也按同一条路走 |
| 我的床被降级砍掉 / 归属过期（`ownedBedNo` 变空） | 篝火消失；猫继续跟着我（无窝状态），我躺下时它会跑到我此刻那张床的床尾 |
| 断线 / 重连 | 断线期间沿用最后一次已知的 `me`（不闪烁）；重连后再按当前态落位，不重发问候 |

### 3.6 摸猫（可点）

| 项 | 决定 |
| :--- | :--- |
| 命中 | 脚点上方 28px 为圆心、半径 26px 的圆（世界像素）。**不给对象开 Phaser 交互**（硬纪律 21）：命中走「屏幕 → 世界 → 纯函数」，与点人 / 点床同一条管线 |
| 优先级 | 别人 > 自己 → **猫** → 床 → 地面。猫站在走道上、可能看起来压着床的一角；点它只演一个本地动作，抢错也没有不可逆后果（不像换床会释放旧归属） |
| 反应 | 随机播 `pat`（摸摸头）或 `nuzzle`（蹭手撒娇）之一：6 帧 @ 4fps = **1.5 秒**。这段时间它原地不动、不换动作；演完自然回到「跟着我 / 回窝睡」 |
| 节奏 | 「1.5 秒内不许再点」由动画自身长度兜住；重复点击只会重开一次，不排队、不叠加 |
| 边界 | 纯本地：不发上行、不动选中、不改床位、不进 `state.bubbles`；猫不在视野内时点不到（命中按**画出来的位置**算，不是它的目标点） |

## 4. 装饰的选择

装饰不是「一堆开关」，而是**每个块单选**：每一块的值 = 该块的某个候选，或 `none`。因此「猫和狗同时存在」这种状态在存储里**写不出来**，不需要靠校验去拦（§1 规则 5）。

### 4.1 值

| 项 | 决定 |
| :--- | :--- |
| 形状 | `{ head: 候选 ｜ 'none', foot: 候选 ｜ 'none' }`——候选表 `DECOR_BLOCKS` 是**唯一真源**（`src/client/decor.ts`） |
| 默认 | `{ head: 'fire', foot: 'cat' }`：与「选择」上线前的行为**完全一致**（那时两样都在） |
| `'none'` | **一等值**：「我把它关了」必须能记住，所以它不是「没写过」的别称 |
| 存储 | `sc.decor`（`40-client-storage.md` §3）：缺键 / 坏 JSON / 版本不符 → 回默认；某块的值不在该块候选里（包被删了 / 搬到了别的块）→ **只把这一块回默认**，另一块不动 |
| 块归属 | 写在候选表里（`head: ['fire']`），与 §1 的三块同一份口径。**中间块还没有候选，于是不进数据、也不进界面**（没有可选的东西，连「无装饰」都不必给） |

### 4.2 世界层的判据

- 篝火：`head === 'fire'` 才画；亮 / 熄仍只由我的显示态决定（§2.1）。
- 猫：`foot === 'cat'` 才存在。**画、命中、问候走同一条判据**——没选中的猫不画，也没有可点的圆（命中按「这一帧真的画了没有」判）。
- 换掉或关掉猫时，**丢掉它的位置与折线**（`petMove` / `petTargetPoint`）：再打开时它从窝（有床）或起跑点（§3.5）出现，而不是从关掉前那个位置跨厅跑过来（末档 20526px 按 1320px/s 要 15 秒）。
- 逐帧只**读** store（`getState()`），不写、不进 React 的渲染循环（`AGENTS.md` 硬纪律 17）。

### 4.3 入口

齿轮浮层 →「装饰」→ 二级视图：两个 12px 纯文字标题（**床头** / **床尾**），每块的候选上下排开（**实心 + ✓** 表示选中，与缩放的档位同一套单选语言），末尾一个「**无装饰**」，再下面是「返回」。点一项**立即生效、不关浮层**（与天气 / 雨声 / 缩放同一口径）。root 那颗只写「**装饰**」——选没选在世界里本来就看得见，浮层里不必再说一遍。

### 4.4 加一样装饰

| 步骤 | 改哪 |
| :--- | :--- |
| 素材 | `npm run art` 加帧组（管线见 `../ui/DESIGN.md`） |
| 候选 | `DECOR_BLOCKS` 的那一块加一个 id——**存储层零改动**（新 id 立刻可存；老值里没有它，读到的就是默认） |
| 文案 | `decorLabel` 加一行中文名 |
| 世界层 | 一个视图 + `decor.<块> === '<id>'` 的判据（篝火 / 猫是两个现成样板） |
| 界面 | **不用改**：视图按候选表遍历，加 id 就多一行（高度预算见 `../ui/DESIGN.md` 的 `decor-picker`） |
| 服务端 | 零改动：没有协议字段、没有错误码、没有数据库列 |

## 5. 常量（都在客户端，不进协议、不进服务端配置）

| 常量 | 值 | 说明 |
| :--- | :--- | :--- |
| 速度系数 / 下限 / 上限 | `1.2 / 260 / 1320` px/s | 见 3.3；系数按「距离」而不是「时间」算，所以不需要追赶模式 |
| 跑动阈值 | `300` px/s | 超过它才是 `run` |
| 跟随距离 | `60` px | 身后拉开；≥ 猫高 58.5（脚底锚点下这就是「贴图不相交」的充分条件） |
| 到位容差 | `6` px | 剩余路程不超过它就按站定处理（吃掉碎步） |
| 摸猫命中 | 圆心 `脚点上方 28`、半径 `26` px | 见 3.6；比「点人」的 22 大一档，因为猫的贴图比小人矮胖 |
| 摸猫时长 | `1500` ms | 6 帧 @ 4fps；期间猫原地演完 |
| 重算阈值 | `24` px | 目标点移动超过它才重算折线 |
| 问候时长 | `4000` ms | 见 3.4 |

## 7. 已知代价

1. **猫比它的块高**（58.5 vs 33.3）：上半身压在中块上。这是 A1 的取舍——块是摆放契约，不是裁剪框。
2. **猫与篝火对别人不存在**：同一个位置在别人眼里就是一块空地。它不是共享空间的一部分，也就不承担任何社交语义。
3. **问候只在自己这边可见**：它不会出现在聊天里，也不会有第二次。
4. **两个暖色物体**（橙火 + 粉腮）打破了原来「唯一暖色 = 我的床标记」的纯度，靠面积上限（<5%）与「只在我自己那一格里」约束。
5. **`Z < 0.5` 时问候不可见**：与床号、名字同一档退役；那时猫也只剩几个像素，本来也读不出文字。
6. **每块只能摆一样**：想要「篝火 + 台灯」，得先改掉「一块住一样」这个前提（§1 规则 5），而那会把预留位从「三个位置」变成“一张桌子”，是另一个量级的设计。
7. **多一次点击**：「关掉猫」从浮层里多一层（齿轮 → 装饰 → 无装饰）。设置页不是高频入口，一次点击换一个不随包数变高的 root。
8. **宠物块现在只有一个候选**：所以「无装饰」实际上就是「关猫」。等有了狗，同一张视图才真的变成二选一——界面已经按那个形状写了。
9. **进厅时关着、之后才打开**：本次页面会补一次问候（问候旗子只在「首次进厅」用掉一次）。没为这个边角加代码，它只发生一次、也不上上行。
10. **换装饰后新装饰从“窝 / 起跑点”开始**：不从旧位置继续（§4.2），所以换回猫的那一下它可能走一小段——比跨厅跑 15 秒好得多。
