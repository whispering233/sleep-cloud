# 求签（lot）

**一句话**：礼物托盘（`gift-tray`）里的「求签」拉起一页独立的求签页——一天求一次，抽到的永远是吉签；已经求过就只把结果摊开给你看，不再摇。

## 1. 入口与出口

| 项 | 规格 |
| :--- | :--- |
| 入口 | 礼物托盘（`gift-tray`）里自上而下第二项（`aria-label="求签"`，44×44 内联 SVG 签筒 + 一行可见中文，外观见 `../ui/DESIGN.md` 的 `gift-tray` / `hud-action`）。**只在空闲态可达**——非空闲态右端那一组被「收起」占住（`60-interaction-shell.md` §9），托盘连同礼物与齿轮一起消失，与其余三颗同一规则 |
| 出口 | 页底主按钮「收起来」（`primary-action`，44px）+ `Esc` 同路。**不做 ×、不做点空白关闭**（整屏页没有遮罩可点；单一出口与说明面板同一立场） |
| 打开前 | 统一走 `exitComposer()`（`60-interaction-shell.md` §2 的唯一出口），与说明面板一致。**关闭后不恢复打字态** |
| 页面态 | 挂在 `EntryOverlay` 之后、`ToneLayer` **之前**（§7）。不是浮层、不进 `.app-shell` 网格、不做相机坐标补偿 |
| 让位 | 这一页是**不透明整屏页**（复用 `.entry-overlay` 的 `outside` 满屏底）→ 世界在底下看不见 → 开着期间**世界整帧停渲染**。判据在 `coversWorld`（`60-interaction-shell.md` §5.2），不在这里另写一份 |

**为什么是独立页而不是插槽面板**：求签是一段有始有终的仪式（摇 → 出签 → 读），插槽面板是「一边说话一边看」的常驻区；把仪式塞进那条 44px 高的行里，动画与签文都会被面板高度挤变形。

## 2. 三个状态

| 状态 | 内容 | 退出这一状态的唯一方式 |
| :--- | :--- | :--- |
| `idle`（今天还没求） | 标题「求签」+ 签筒 + 主按钮「求签」+ 一行小字「一天一次，静下心来」 | 点「求签」→ `shaking`（**同时写盘**，§3） |
| `shaking`（摇签中） | 签筒轻晃 → 一支签升起 → 结果卡淡入（三段合计 1200 ms，写在 `app.css` 的 `lot-*` 关键帧上） | 动画跑完（`animationend`）或**点页面任意处** → `revealed` |
| `revealed`（今天已求） | 等级 + 四字签题 + 签诗四行 + 解签两句 + 宜；下方小字「今日已求 · 明天再来」 | 出口（§1） |

- **已求时再进页面 = 直接 `revealed`**：动画只属于「今天这一次求签」，不重播。
- **托盘里那颗在已求时照常可点**，点它就是打开结果页（不摇）。
- **`shaking` 里没有第二个按钮**：跳过靠点页面，不额外画一颗「跳过」——动画只有 1.2 秒，多一颗按钮反而是噪声。
- **`prefers-reduced-motion: reduce`**：动画压到 `0.01ms`（沿用「到点即终态」的做法，`animationend` 照旧触发）。求签动画是**交互触发**的，WCAG 2.3.3 管得到它——这与雨（环境性、连续、不在此列，见 `backlog.md`）不是同一条判据。

## 3. 一天一次与写盘时机

- **判定只看本地日期字符串**：`new Date()` 按**设备本地时区**取 `YYYY-MM-DD`，与 `sc.lot.date` 逐字比较。相等 = 今天已求。
- **写盘发生在点「求签」那一刻**，不是动画结束：否则跳过动画、中途关页、动画期间刷新都会**重复抽**，而「一天一次」是本功能的唯一约束。
- **跨零点**：过了本地零点，旧签立刻失效（`date` 不等），页面回到 `idle`。不做「保留昨天的签」——那是一份要单独清理的状态。
- **已知代价**：改系统时间可以再求一次。这是纯本地判定的必然（用户 m00051 定「纯本地就够」）；不接受服务端时间，因为那要开接口。

## 4. 键与判定

| 键 | 值 | 缺键 | 判废 |
| :--- | :--- | :--- | :--- |
| `sc.lot` | `{"v":1,"date":"2026-10-22","no":7}` | 等于「今天没求过」 | `date` 不匹配 `^\d{4}-\d{2}-\d{2}$`、或 `no` 不是 `0…LOT_POOL_SIZE-1` 的整数 → **删该键 + 当没求过** |

判定是纯函数：

```text
lotOfDay(stored, today) → LotSign | null      // stored.date === today 才算今天那张
```

**不校验 `date` 是不是真日期**：它只被拿去与今天逐字比较，坏值唯一的后果是**再求一次**（无副作用）。键协议与读写规则见 `40-client-storage.md` §2。

**为什么只存 `no` 不存整条签文**：签文是随 bundle 发布的常量，存一份就是第二个事实源；`no` 是索引，签库换了内容也只需保证 38 条仍在（单测守着）。索引失效时（`no` 越界）判废，不是崩。

## 5. 数据

数据住在 `src/client/lots.ts`（纯数据 + 纯函数，DOM-free，可单测）：

```text
LOT_SIGNS: readonly LotSign[]        // 38 条，**下标即 no**
type LotSign = { level, title, poem: [string × 4], reading, good }
```

| 字段 | 说明 | 例 |
| :--- | :--- | :--- |
| **下标** | 内部序号 `0…37`，同时是 `sc.lot.no`；**不另存字段**，也不显示给用户 | `7` |
| `level` | 等级，只有三档：`上上`（28 条）/ `大吉`（8 条）/ `上吉`（2 条） | `上上` |
| `title` | 四字签题，自拟（原文没有标题） | `云开见月` |
| `poem` | 四句七言，**原文照录**（观音灵签） | `…` |
| `reading` | 解签两句，**自写**（原文的「解曰」是古文，现代读者读不动） | `…` |
| `good` | 宜，两到三字 | `出行` |

**选条规则**：取观音灵签里 `level ∈ {上上, 大吉, 上吉}` 的 38 条，**剔除全部下签**（`中` / `中平` / `下下` / `下`）。正文里仍带凶语的条目**保留**：整体是「否极泰来」，删句会破掉签诗的完整（用户定案）。

**签题与解签的所有权在作者**：改字不需要改代码结构，但改完要跑 `npm test`（单测守着 38 条、`no` 连续、字段长度、等级集合）。

## 6. HUD 那一句

顶部 HUD 行尾固定加一项纯文字：**`今日宜 睡觉好梦`**。

- **固定文字**，不随当天抽到的签变化：求签结果不进 HUD（用户要求），而轮换「宜」会把签的内容漏到常驻版面。
- **行尾第五项**，不打断「在线 / 空床 / 延迟 / 缩放」这组运行信息。
- **窄屏允许折到第二行**（`.hud-info` 现有 `flex-wrap` 兜底），不隐藏——隐藏会让「每天都能看到的一句好话」在部分手机上消失。
- **不进 `hud-view.ts`**：它不是派生数据，是常量。组件里直接一个 `<span>`。

## 7. 明暗

**插在 `ToneLayer` 之前 → 跟着三档一起减光**（`B` 方案，用户定案）：不造第二套明暗语义。

对比度算式（令牌见 `../ui/DESIGN.md` 的 Colors）：正文 `neutral #23262B` 衬 `secondary #E2E4E7` = **11.9:1**；睡下档 α=0.22 后 = **10.1:1**，仍远高于 4.5:1。所以这一页只要求「文字用 `neutral` 衬 `secondary` / `paper`」，减光后依然合格。

## 8. 常量

见 `config.md` §5：`LOT_POOL_SIZE = 38`；动画时长不设 TS 常量，只写在 `app.css` 的三段关键帧上（合计 1200 ms）。HUD 那句文案写在 `Hud.tsx` 一处（单点使用，不进常量表）。

## 9. 不做（与理由）

| 不做 | 理由 |
| :--- | :--- |
| 「再求一次」/ 一天多次 | 用户定的规则；一天一次的稀缺感就是它「让人感到好运」的来源 |
| 求签历史 / 记录页 | 没有需求方；只存一个 `no` 也凑不出历史 |
| 显示求签日期 | 结果页只需要「今天这张」；日期会让它看起来像台账 |
| 签诗竖排 | 竖排是中文排版的另一套行内布局（`writing-mode` + 行高），而这一页是 4 行短诗，横排读得更好 |
| 等级用颜色区分 | 颜色梯次已用完（`../ui/DESIGN.md` 的「为什么不是线型」同理）；等级是文字，不是通道 |
| 服务端校验 / 下发签文 | 纯本地（用户定案），服务端不知道它存在 |
| 求签动画走美术管线 | 签筒与签是 CSS + 内联 SVG，只动 `transform` / `opacity`，不需要位图 |

## 10. 验收

| 层 | 判据 |
| :--- | :--- |
| **L1**（vitest） | `LOT_SIGNS`：38 条、`no` 连续且唯一、`level` 只在三档集合内、`poem` 恰好 4 句、`title` 4 字、`reading` 非空；`lotOfDay`：同日 → 返回该条、异日 → `null`、`no` 越界 → `null`、`date` 形状坏 → `null` |
| **L2**（桌面浏览器） | 未求：页面出签筒与「求签」→ 点它 → 动画 1.2s → 结果卡；**动画中点页面任意处** → 立刻出结果；刷新后重进：直接结果、不播动画；`Esc` 与「收起来」同路；改系统日期到明天 → 回到 `idle` |
| **L3**（模拟器，393 竖屏） | 签诗四行不溢出、卡片内部可滚；`收起来` 44px；三档减光压住整页且文字仍可读（睡下档重点看）；`prefers-reduced-motion` 下无动画直接出结果 |

## 11. 术语

| 用 | 不用 | 说明 |
| :--- | :--- | :--- |
| 求签页（lot panel） | 抽签弹窗、签筒界面 | 覆盖整屏的独立页，入口在礼物托盘、出口一个 |
| 求签 | 抽签 | 「求」是这套仪式的动作；「抽」只是其中一下 |
| 吉签 | 上签、好签 | 三档等级的统称（上上 / 大吉 / 上吉）；**下签不在库里** |
| 签题 | 标题、名字 | 四字，自拟 |
| 解签 | 解释、译文 | 现代汉语两句，自写 |
| 宜 | 吉时、推荐 | 两到三字的一个方向 |
