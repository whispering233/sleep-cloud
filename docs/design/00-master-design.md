# 总体设计：失眠云

## 1. 一句话

浏览器打开就是一个睡眠大厅：**每个用户在大厅里有一张属于自己的床**，躺下时小人睡在床上，睡不着的人可以在厅里走动、看见别人、和别人说话。

**只有一个大厅**，床位随人来人往自动变多变小（117 ~ 9558）。没有大区、没有昼夜。**世界只缩不放**：相机能拉远到 0.175（看一眼整个厅），不能放大。

## 2. 核心循环

```text
打开网页 → （首次 / 公告升版时）看一眼说明面板，点「知道了」→ 匿名入场（昵称 + 18 岁自述）→ 看见一屏的床位与人
        → 走到某张空床边躺下（该床从此属于我）→ 睡着 / 睡不着躺着
        → 睡不着时起身走动、看别人、聊天
        → 关掉网页 → 床上留下「睡痕」（你回来就还原；30 天不回来，床才真的让给别人）
```

第一版只验证这条循环。**任何不服务于这条循环的功能都不做**（见 §9）。

## 3. 空间模型

```text
应用（= 一个厅 = 一个房间服务实例 + 一份私有 SQLite）
  └─ 间（每间一张床 + 一块留给装饰物的预留位；一间占一格，一格自带一条竖走道）
       └─ 床位（容量由级表给出：117 → 150 → … → 9558，按需要自动伸缩）
            └─ 用户（匿名身份，持久认领一张床）
```

| 决定 | 内容 |
| :--- | :--- |
| 厅的形态 | **一个宽矩形大厅**（`宽:高 ≈ 1.618:1`，即 `y:x = 0.618:1`）：**一间一格的房间阵** + 规则街网（每格一条竖走道 + 每格一条床脚前横走道 + 贴墙一圈环形走道）。一格 = 一条竖走道 + 一间房（床 + 预留位），相邻行的床**左右错位**，所以看起来是交错排布而不是队列 |
| 床位密度 | 一格一床 → **iPhone 16 竖屏一屏约 10 床**（格 173×156 的推导见 `20-layout.md` §2）。比「每格塞多张床」疏一倍多，这是「不压抑」的代价，也是「每间房有块空地」的前提 |
| 床位伸缩 | 级表跳档（类似 `ArrayList` 扩容，步长约 ×1.37）：床不够才扩，**只在外圈加床，老床位一动不动**；外圈没人要了则缩 |
| 只有一个厅 | 没有大区、没有厅列表、没有切厅。入口只有「昵称 + 18 岁自述 + 形象」三项 |
| 满员怎么办 | 触顶（9558 张全被认领）→ `2002`「厅满了」。这是理论边界，不是运维事件 |
| 为什么不做多厅 | 多厅会立刻带出「选哪个厅 / 能不能串门 / 厅间社交割裂」三个问题；单厅 + 自动伸缩一次性消掉它们 |

**已知副作用**：床位编号按「建成的先后」分配（先内圈后外圈），所以号大的床在厅的外围。用户看到的是「这个厅在往外长」——这是可接受的隐喻，也是「老用户的床永远不动」这条硬要求的必然结果。

**编号不承载方位**：它编码的是「年龄」，不是位置；级与级之间必然有一处空间跳变。所以方位**另外给**：HUD 的「我的床 N」在我的床不在视野内时补一个 8 方位字形，且整条可点 = 相机跳到我的床（与「点自己 = 回中」配成一对）。**床号从 1 开始显示**：内部编号从 0 起（位图、数据库、协议一律用它），只在渲染与文案处 +1，所以用户看到的第一张床就是「1 号床」。

## 4. 身份与床位归属

| 决定 | 内容 |
| :--- | :--- |
| 身份 | **匿名身份**（L1）：首次访问由服务端签发一个随机标识（`u_` + 16 hex = 64 bit）并放进 HMAC 签名 cookie（L2）。**服务端从不知道真实身份**；来源信息（L3：IP / 国家 / UA 哈希）只入运维台账、永不下发。三层分工与禁令见 `70-privacy-risk.md` §2 |
| 昵称来源 | **用户在入场层自己输入**（没有登录、没有第三方资料、没有默认名）；昵称随会话存在签名 cookie 里，**不是从数据库查出来的** |
| 改名时机 | 只在入场层、**建立连接之前**。因此协议不需要「名字变更」消息；代价是已连接的其他人要等自己下次进入才看到新名字 |
| 外观 | **入场时自己选**（`boy` / `girl` 两个，入口在入场层；厅内不改选）。**没选的按 `user_id` 派生**——无论选没选，同一个人永远同一个外观 |
| 注册 | **不做**。深夜失眠的人不会注册，保留匿名是门槛设计 |
| 升级通路 | 将来要跨设备/永久昵称时，把匿名标识升级绑定登录方式，床位跟着迁移，数据模型不重做 |
| 年龄 | 入场时**「我已满 18 岁」自述 + 一次点击**。这是法律免责表述，**不是核验** |
| 认领时机 | **第一次躺下时认领**（不是入场时分配）。点哪张空床就躺哪，天然实现了「在空床里挑」 |
| **一人一床，但可以换床** | 任何时刻名下最多一张床（数据库唯一索引兜底）。**换床是一次显式操作，不是一个可误触的动作**：齿轮浮层 →「更换床位」→ 换床模式内点一张无主空床 = 旧床当场释放、新床认领，同一个事务（客户端会收到两条 `bed`：旧床 `owned:false` 在前）。**模式外点无主空床不换床**，只给一句提示（旧床归属一旦释放就可能被别人捡走，误点的代价不能由一次轻点承担）。**距上次认领不足 10 秒 → `3008`**（可见提示，躺着不动不算）。**这道闸只在客户端**——服务端看不到模式，`lie` 的语义不变（见 `../api/20-api-ws.md` §4.5）。没有「解绑床」按钮（见 `backlog.md`）。重访时靠**床号 + 我床暖标记**回到自己那张 |
| 出生点 | **已有归属的人落在自己那张床脚前的走道**（跨厅走不动，见 `10-hall-runtime.md` §9）；**还没有床的人落在「编号最小的无主空床」前方走道**：新人处在已有住户中间（30 天释放留下的坑会被新人补上），而不是被丢在没有住户的尾部 |
| 归属 vs 占用 | **归属**持久绑定用户，30 天未出现才释放；**占用**表示此刻床上有人/有睡痕 |
| 别人能用我的床吗 | **不能，永远不能**。空床很多，这条不造成摩擦，但让「我的床位」成为真实私人物品 |
| 重名 | **允许**。显示时一律带床号（「12 号床 小明」），歧义由此消除，省掉重名检查 |

## 5. 在场与时间模型

### 5.1 状态机

三个**正交维度**，服务端是唯一真源：

| 维度 | 取值 |
| :--- | :--- |
| 位置 | `ROAMING`（不在床上）/ `IN_BED` |
| 清醒度 | `AWAKE` / `ASLEEP`（仅在 `IN_BED` 时有意义） |
| 连接 | `ONLINE` / `GRACE`（断线宽限中）/ `OFFLINE` |

派生显示态：

| 位置 | 清醒度 | 连接 | 别人看到 | 占床 | 能聊天 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| ROAMING | — | ONLINE | 站着/走动的小人 | 否 | 是 |
| ROAMING | — | GRACE / OFFLINE | 不显示 | 否 | — |
| IN_BED | AWAKE | ONLINE | 睁眼躺着（失眠的人的真实状态） | 是 | 是 |
| IN_BED | ASLEEP | ONLINE | 闭眼睡着 | 是 | 否 |
| IN_BED | 任意 | OFFLINE（未过 TTL） | **睡痕**（更暗、更低饱和） | 是 | — |

**睡痕不是第四种姿势，而是「IN_BED + OFFLINE」这个组合的显示名。**

### 5.2 转移规则

| 触发 | 前置 | 结果 |
| :--- | :--- | :--- |
| 点地面 | IN_BED | **自动起身**（释放占用，保留归属）→ 走过去。一条命令完成，少点一次 |
| 点地面 | ROAMING | 走过去（新目标覆盖当前路径；目标即当前点则原地不动） |
| 躺下 | **ROAMING 或躺在床上**（躺在床上 = 先自动起身，见上行「点地面」那条），且该床无主（或归属已过期）且无占用 | **先走到该床旁，再躺下**（一条意图完成两段动作）；在床上时是**起身 → 走过去 → 躺下**三段。同时认领归属（若可认领）。**我已有别的床 → 这是一次换床**：旧床当场释放；距上次认领不足 10 秒 → `3008`。**唯一的例外**：点自己正躺着的那张床 → `3004`（静默、什么都不做）。**服务端不校验「这次躺下是不是换床意图」**：换床模式的闸门在客户端（只有模式内才会为另一张无主空床发出 `lie`），因为它只是人的意图，不构成任何需要服务端拦的越权 |
| 无输入满 5 分钟，或手动睡着 | `IN_BED + AWAKE` | `IN_BED + ASLEEP` |
| 说话（聊天 / 私聊） | `IN_BED + ASLEEP` | **自动醒**后处理，不报错 |
| 起床 | IN_BED | ROAMING（站在床边） |
| 断线 | 任意 | GRACE（宽限 60 秒） |
| 宽限超时 | IN_BED | `ASLEEP + OFFLINE`（睡痕），占床保持 |
| 宽限超时 | ROAMING | 离开，小人消失 |
| 宽限内重连 | 任意 | 恢复原状态 |
| **重连（不论隔了多久）** | IN_BED + OFFLINE | **从床位行还原**：`lying` / `asleep` 一律回到原状态（睡下就是睡下） |
**为什么躺在床上断线一律转睡痕**（哪怕断线前睁着眼）：「躺下」这个动作本身就是「我要睡了」的声明。这样就不必为「躺着但清醒且离线」单独定义一个状态，状态机少一整个分支。

### 5.3 归属与占用的生命周期

| 事件 | 占用 | 归属 |
| :--- | :--- | :--- |
| 首次躺下 | 占用 | 认领 |
| 起身 | 释放 | 保留 |
| 断线超宽限（在床上） | 保持（睡痕） | 保留 |
| 30 天未出现 | 释放（床变空，行被改写） | **释放**，床回到可认领池（每日唤醒里批量清行） |

**关键区分：睡痕 ≠ 独立存在的东西。** 睡痕就是「有主、人不在、但还没到 30 天」的那张床的显示态。它没有自己的 TTL，所以**睡痕消失与释放归属是同一件事**：30 天不出现，床与睡痕一起消失（要提示“你的床没了”就得在 30 天之外再多留一份记录，不做——见 `10-hall-runtime.md` §13）。

**两个「过期」都是读取时推导**：判定「这张床能不能躺」时，过期的睡痕视为无占用、过期的归属视为无主（`../db/schema.md` §6）。写入只发生在别人真的躺上去、或每日唤醒清行的时候。

### 5.4 时间与光照

| 决定 | 内容 |
| :--- | :--- |
| **昼夜** | **取消**。按时间周期变化的明暗会被读成昼夜替身；用户的「心理时间」不由时钟决定（可能是凌晨，也可能是白天） |
| **时区** | **整个概念删除**：服务端不存、不接收、不使用任何时区信息（没有厅时区、没有用户时区、没有按人区分的时间语义） |
| 三种时间机制 | 持久唤醒（宽限到期 / 自动睡着 / 每日唤醒）、内存循环（位置节拍）、**读取时推导**（睡着、睡痕、归属过期）——职责不重叠，详见 `10-hall-runtime.md` §4 |
| 每日唤醒 | **UTC 20:00（北京 04:00，低峰）**：归属释放（30 天）+ 缩级评估。用户侧不可感知 |
| 服务端时间轴 | 一律 UTC 时间戳。**不为用户分裂出多套定时机制** |
| **色调** | 明色调基底 + **三档减光**：档 = 我的显示态（`roaming` → `0` / `lying` → `0.12` / `asleep` → `0.22`），整屏一层、约 0.9 秒过渡。不读时钟；入场层不参与（色值与上限见 `../ui/DESIGN.md`「三档色调」） |
| **天气** | 只有两态：**雨天 / 无雨**。它是**个人偏好**（本地存储），不是厅的事实：不进协议、服务端不知道、同一时刻两个人可能不同。**它只管雨层画面**；**雨声是第二个独立开关**（同一个齿轮浮层里隔壁那颗胶囊，桌椅各管各：无雨也能只听雨、雨天也能静音）。两颗胶囊都缺键时关：无雨、静音（默认值是常量，不读日期）；用户切过之后永久生效（见 `../design/40-client-storage.md` §3） |

**为什么色调由「我的行为」而不是时钟驱动**：一条视觉通道只能有一个驱动。用全厅困倦度会得到第二条光轴（别人的状态、随人进出抖动），而「我正在躺下 / 睡下」是我自己的行为、可预期。「大家都睡下了」由画面里的睡着者与睡痕本身表达，不靠亮度。

## 6. 交互模型

| 决定 | 内容 |
| :--- | :--- |
| 走动方式 | **点目标点，服务端在街网上寻路并推进**。客户端只发意图，服务端自己按节拍推进位置并广播权威值 |
| **世界缩放** | **只缩不放**（`0.175 ~ 1×`）：双指捏合连续缩放（`自由缩放`），或从动作行那颗**缩放档位胶囊**里选一档**锁死**（`全厅` / `0.5×` / `0.75×` / `1×`——固定档下捏合只平移、不改比例；胶囊文案就是当前档位，所以「锁在哪一档」常驻可见）。固定档里没有低于 `ZOOM_TEXT_MIN = 0.5` 的档（只有 `全厅` 例外，那一档本来就不画文字），所以**选档不会把世界文字弄没**。理由：一屏只有约 10 张床（厅宽是屏幕的 6~52 倍），拖屏找目标与「对厅的整体感」都是真问题；而原来那三条反对理由逐条让了路（见 `../ui/DESIGN.md` 的世界相机）。**不做放大**（捏合放大必然被放大采样而糊），也不做世界比例可调（`ART_SCALE` 是常量） |
| **导航** | **床号常显在每一张床上**（1× 下它是主要的导航线索；拉远后文字退役）+ 我的床有暖色标记 + 动作行显示我的床号。玩家按编号自己走过去。厅变大之后再加两层保险：动作行那条「我的床 N」在床离屏时显示 8 方位字形，点它 = **小人回床 + 相机跟随**（两件事一起做：需要看的时候本来就要回去；走动时不保留「只看不动」）。**已经在床上时它只对准相机、零上行**——那时「回床」没有对象，再发一条一跳就等于把躺着的人叫起来（睡着的还会被叫醒），而用户点它想要的只是「我这张床在哪」（见 `../ui/DESIGN.md` 的 `action-row` 行）；动作行上还有一个「GO」**跳到指定床号**（输入显示床号 → 瞬移到那张床脚前 + 相机对准）——厅一大，「走过去」就不再是可接受的代价。**拉远是第四层**：一眼看到厅的大致规模与自己在哪一片，但它不是导航手段（精确操作前先放大回来） |
| 目标设备 | **移动端优先**。手机是主场景（躺在床上、单手、竖屏、弱网、随时锁屏），桌面是次场景 |
| 输入方式 | 只有点击/点按与拖拽。**不依赖 hover、不依赖右键、不依赖键盘** |
| 名字显示 | 名字是身份信息，不是陪伴信息。**每个别人的名字都始终显示**（床上、站着、走动都一样），点中时改为**唯一一个**名字气泡；自己一律不画 |
| 选中态 | 点中小人或床上的人 → 成为**选中对象**：弹出名字气泡 + 作为私聊目标。一个概念服务两件事 |
| 客户端预测 | 允许——客户端可对自己那一个小人做乐观预测，与服务端权威值不符时平滑纠正。**预测值不是事实** |
| 第一版动作集合 | 走动、**一跳**（不带床号 = 回我的床；带床号 = 跳到那张**床脚前**，跨厅瞬移，见 `10-hall-runtime.md` §5.1）、躺下、起床、睡着、全局聊天、私聊（含 emoji 表情） |

**意图 vs 事实**（架构级纪律）：

- **客户端发意图**：我想去这个世界像素点、我要躺 3 号床
- **服务端定事实**：你在 (x,y)、3 号床被你占着

一旦让客户端上报坐标并当作事实，基于位置的规则全部失效（走到床边才能躺下、距离语义、治理取证），而且没有任何真值可以纠偏。

## 7. 视觉

| 项 | 决定 |
| :--- | :--- |
| 视角 | **正俯视带轻微俯角**（不做等距斜 45°）——后者需要 8 方向行走精灵与复杂遮挡排序，成本翻几倍 |
| 屏幕适配 | **移动优先的响应式**：先在竖屏窄幅下定稿，再向上适配桌面。基准设备 iPhone 16（393×852 / DPR 3） |
| 风格 | **单色线稿 + 明色调（低饱和冷灰，只有一套配色）**。素材来自 `WheatCloudSleep`（MIT, © 2022 WheatBox）：空床、两人躺姿、两个站立小人共 5 张母图；**构建期做两色渐变映射**（黑线 → 墨色三档、白填充 → 纸色），生成 8 张贴图。另有**自绘**的猫与篝火（同样入库、同样走构建期映射，但走饱和度双支：墨/白对齐令牌，橙火与腮粉原样保留） |
| 点睛色 | 只留**一个稳定的暖色**：**「这是我的床」的标记**；地板与墙是程序化的。唯一的额外暖色是**我自己的篝火（橙）与猫（腮粉）**：素材原色、只出现在我那一格里，面积占屏 ≈ 0.5%（口径见 `../ui/DESIGN.md`「配色纪律」） |
| 为什么不用像素风 | 高饱和像素风会让一个失眠大厅变得吵闹；线稿与「失眠、克制、安静」的气质同步 |
| **天气（雨）** | 一层**屏幕空间**的雨（并行 Phaser Scene，自带相机 `zoom = DPR`）：与相机缩放、可用视口、面板换位都无关，`全厅` 档下雨的疏密与 `1×` 相同。它是几百条低透明度细线（覆盖率约 1.2%），**不是第二层明暗**——全屏平均亮度只降不到 1%。雨画在世界之上，因此也压过聊天气泡（已知代价，见 `../ui/DESIGN.md` 的 `rain-layer`） |
| 世界渲染 | **Phaser 4.2.1**：地板是一块 `Graphics` 矩形（走道地板；**明暗不在这里做**，由整屏一层减光处理），房间地面与预留位是每间房两块贴片（与地板一起被减光）；床/床号/标记/贴片一律走**可视窗口 + 对象池**（同屏约 80 个对象，与厅规模无关），**不用 Tilemap**（地图是生成的） |
| 墙与厅外 | 地板与墙画在**地板区**（= 本级格网 + 四侧各一条走道）的矩形上（四侧相等；三个范围的分工见 `20-layout.md` §3.2）。墙是 `WALL_WIDTH = 3px` 的墙带，画在矩形**之外**；**厅外不铺地板**，用 `outside`（比地板暗一档的台面）与厅内区分。可走区再向内缩 `WALL_BODY = 26px`（依据见 `20-layout.md` §2），所以小人永远停在墙里侧（走到边缘时看得见墙，而不是「贴住屏幕边缘」） |
| **房间地面与预留位** | 每间房的地比走道亮一档（`room`），留给装饰物的预留位再亮一档（`rug`）——三层都是「地」，跟着三档**整体减光**（不为它们留第二套暗色值）。于是「一格一间」读得出来，新人也看得出哪块是留给装饰物的空地（色阶见 `../ui/DESIGN.md`「地面梯次」） |
| **我的预留位装饰** | 预留位沿床长方向**等分三块**：床头装饰 / 床中占位 / 床尾宠物（`20-layout.md` §2.1）；画面上**不分块、不分色**。第 1 阶段只在床头块放**篝火**、床尾块放**猫的窝**，两者**只有自己看得见**（纯客户端，不进协议与数据库）。猫跟在我身后 60px（走道 56 宽，并排放不下），**可点**：摸头 / 蹭手撒娇。行为规格见 `80-reserve-decor.md` |
| UI 渲染 | **DOM**。聊天、HUD、入场、错误提示全部走 DOM，canvas 只负责世界 |
| 场景数据 | **没有场景文件**：床号 ↔ 位置、区域、可走性全部由共享纯函数给出（`20-layout.md` §4） |
| 床位可见状态 | 由**归属**与**占用**两个正交维度派生，两个维度各走一条通道：**占用用颜色**（有人 → `line` 8.42:1 / 睡痕 → `trace` 4.13:1 / 空床 → `claimed` 3.12:1，均为衬地板；每一档还要衬床填充 ≥3:1）；**归属用填充**（无主空床 → 空芯透明，有主 → `paper`）；**「是我的」用一个独立的暖赭色小标记**。**床号常显**；名字画在**每个别人**身上（床上、走道上同一档样式），自己的名字一律不画 |
| **色调（三档）** | 我的显示态 → 整屏一层减光（`0` / `0.12` / `0.22`，约 0.9 秒过渡）：地板、房间、预留位、床、小人、界面**同比例变暗**（§5.4） |

**关键性能边界**：位置插值跑在渲染循环里，**不触发前端框架重渲染**。这条边界破了，几百个小人会把框架拖死。

**界面最小集**：说明面板（首次进厅前的产品介绍与更新说明，入口还有齿轮浮层里的「关于失眠云」；`90-about-panel.md`）、入场层（昵称 + 18 岁自述 + **形象**）、世界层、顶部 HUD（**只有显示性信息**：在线人数 / 无主空床数 / 延迟）、**常驻底部控制台**（**动作行**——我的床号 / 跳到指定床号 / 缩放档位 / 设置齿轮（浮层里：更换床位 + 天气 + 雨声 + 关于失眠云 + 版本号），两端对齐；**门控行**——`GO` 的床号输入 / 换床提示 / 缩放档位选项（三者互斥）；**输入行（含表情切换）**；**床上动作行**——核心动作不进二级菜单，表情与输入行共用一行、两步发出）、错误反馈层。**聊天消息不进面板**：它只在世界里以 8 秒气泡出现（同人后来的消息覆盖前一条）；不存历史（服务端不存，客户端也不留消息流）。没有「手机」隐喻、没有设置页、没有厅列表——那些是为了在游戏画面里塞 UI 而发明的容器，网页不需要。

## 8. 状态同步

| 决定 | 内容 |
| :--- | :--- |
| 模型 | **纯事件增量**：仅在进入/重连时发一次全量快照，之后只发变化事件 |
| 为什么不做周期性全量纠偏 | WebSocket 跑在 TCP 上，消息可靠且有序，不会静默丢包——需要纠偏的问题根本不存在 |
| 广播节拍 | 位置推进按节拍进行；每 100 ms 把这一周期内所有位置变化**合并成一条**消息广播 → 下行消息数与人数的平方无关 |
| 静止的人 | 不产生任何下行流量。**睡着的人零成本**——这是「睡眠大厅」在计费上的天生优势 |
| 消息格式 | JSON。消息量小（10 条/秒量级），可读性价值远大于节省的字节 |
| 心跳 | 协议层 ping/pong 由平台自动响应（不唤醒、不计费）。**不做常驻应用层心跳**（它会让对象整夜不醒）；只保留「可疑时才发」的探活 `ping`（见 `../api/20-api-ws.md` §5.1） |
| **断线自愈（客户端）** | 连接断了不会把页面卡死：三条触发点（回到前台 / 网络恢复 / 发了意图 1.5 秒没有任何关于自己的下行）→ 发一条探活 `ping` → 超时即重连；退避 **1→2→4→8→15 秒**、永不放弃，`hidden` 期间不重试。面板顶部一条**不自动消失**的提示条 + 「尝试连接」；**离线期间的上行丢弃不补发**（重连后的位置可能已经变了）。详见 `../api/20-api-ws.md` §5.1 |
| 上行限流 | 每连接 5 条/秒，超出丢弃。第一版唯一的治理措施 |
| **本地推导** | 色调档位（按自己的显示态）、位置插值（按 `pos.ts`）——两件都不需要服务端参与 |

## 9. 第一版范围

**做**：走动、**天气（雨天 / 无雨：雨层）与雨声开关（两者独立，缺键都是关）**、**拉远看全厅（相机 `0.175 ~ 1×`：双指捏合自由缩放，或从动作行那颗胶囊里选一个固定档；只缩不放）**、**一跳（`hop`：回我的床 / 跳到任意床号）**、躺下、起床、睡着、**换床（设置浮层里的「更换床位」模式内点无主空床即搬，10 秒冷却；模式外点空床只给提示）**、睡痕（跟着归属活 30 天，没有独立 TTL）、**全局聊天与私聊（世界内 8 秒气泡，无历史；emoji 就是聊天文本）**、**入场选形象**、**我的预留位装饰（自己床头的篝火 + 床尾的猫；只有自己可见：躺下时火烧旺、猫回窝睡，起身时火熄灭、猫跟到身后 60px；首次进厅猫会跑过来打一句招呼；点猫随机演摸头 / 蹭手撒娇）**、HUD（在线人数 / 无主空床数 / 延迟、回我的床、跳到指定床号、**缩放档位**、齿轮浮层里的更换床位与版本号）、内容过滤、上行限流、**床位自动伸缩（外圈生长 + 每日缩级）**。

**不做**（已记入 `backlog.md`）：聊天历史持久化、共处时长展示、用户自定义装饰（UGC）与床头留言、设置页、手机隐喻、地图编辑器、举报、禁言、渐进惩罚、三档色调之外的任何光照系统、多厅/串门/换厅、音量滑杆与独立静音、雷声与其它天气类型。

## 10. 内容安全（第一版底线）

| 项 | 决定 |
| :--- | :--- |
| 昵称过滤 | 敏感词命中 → 拒绝并提示改名（不粗暴断线） |
| 聊天过滤 | **打码而非拦截**：命中词循环替换为 `*` 后照常转发。硬拦截会让发送者意识到被审查并试探绕过；打码让对话继续，攻击者拿不到反馈 |
| 干扰字符 | 匹配前剥离 `·（）【】！？《》￥` 这类插入字符，防止 `傻·逼` 绕过 |
| 词表 | 静态文件随应用打包（平台包大小限制 64 MiB，词表远小于此） |
| 限流 | 上行 5 条/秒 |
| 错误码 | `5xxx` 段：**`5002`（封禁）已启用**，`5001`（禁言）/ `5003`（举报）继续预留，避免下次改协议 |
| **封禁** | 维度 = `user` 与 `ip`，命中任一即拒；默认永久、可填到期；**在线时被封立刻踢掉**；他的床**不释放**（走 30 天自然释放）；**提示必须可见且带到期时间，不给原因**。语义与边界见 `70-privacy-risk.md` §5 |
| 来源与留存 | 记 IP / 国家 / UA 哈希，**仅运维可见**；来源信息 90 天无访问后自动清空。告知入口在入场层的 18 岁自述行与齿轮浮层 |
| 后台 | 同 Worker 子路由（页面壳 `/admin` + 数据接口 `/api/admin/*`），单令牌 `ADMIN_TOKEN`。**未授权回 HTTP 401、不套用户面错误码**，见 `../api/30-api-admin.md` |
| 18 岁自述 | 入场一次点击。**必须承认：这不是核验，只是「不是裸奔」** |

## 11. 平台约束

完整清单与换算见 `architecture.md` §5。三条对设计影响最大的：

| 约束 | 对设计的影响 |
| :--- | :--- |
| 存在未完成的内存定时器时对象**无法休眠**，阻止期间持续计费 | 位置节拍只在有人走动时存在，最后一个移动者停下就清除；**没有常驻循环** |
| 内存定时器**不持久**、云端计时**不精确** | 「必须发生」的动作走持久唤醒；推进量按实际经过时间算，客户端按时间戳插值 |
| 出站 WebSocket 消息**不计费**，入站按 20:1 折算 | 「只发变化 + 批量合并」在计费上最省；睡着的人零成本 |
