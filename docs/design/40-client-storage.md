# 客户端本地存储规格

> **本文只管客户端本地持久化**，唯一工具是 `localStorage`。素材的 HTTP 缓存策略、身份与会话的权威、权威状态的复建都不在这里：
>
> | 不在本文范围 | 权威在哪 |
> | :--- | :--- |
> | 身份与会话（用户标识 / 昵称 / 形象 / 18 岁自述） | 服务端签名的 **HttpOnly cookie**（见 `../api/api-public.md` §2） |
> | 权威状态（谁在哪、哪张床属于谁、厅的床位数与在线数） | `hello` 快照与后续下行（见 `../api/20-api-ws.md`） |
> | 素材字节（图集 / 图片 / 音频）的取用与失效 | **浏览器 HTTP 缓存**（静态资源交付，见 `build.md`） |
> | 音频素材本身（不存在） | `backlog.md` 第 2 阶段 |

## 1. 边界

### 1.1 准入判据（**三条全满足才准进**）

| # | 判据 | 反例（会被挡下） |
| :--- | :--- | :--- |
| 1 | **丢了回到默认、功能完好**：不产生错误状态、不需要迁移、不需要告知用户 | 「上次的私聊对象」「未发送的草稿」丢了下场不同 |
| 2 | **权威不在服务端**：服务端不知道、也不需要知道它 | 昵称 / 形象（cookie 权威）、我的床、我的位置 |
| 3 | **小、少、读得少**：单值 ≲1KB、键数个位数、只在启动或模式切换时读写一次，**绝不进逐帧路径** | 素材字节、位置插值锚点 |

任何一条不满足 → 要么不做，要么换工具（§4.4）。

### 1.2 禁止清单

| 禁止 | 理由 |
| :--- | :--- |
| 身份与凭证（`userId`、任何 cookie / token 的本地副本） | 权威是服务端签名的 HttpOnly cookie。本地存一份 = **第二个事实源**，且脚本可读 |
| 权威状态镜像（我拥有哪些床、我的位置、床位占用、在线数、床位数） | 必须由 `hello` / 快照重建（见 `../../AGENTS.md` 硬纪律 1、10） |
| 易失渲染状态（插值锚点、自身外推折线、气泡、连接态、延迟样本） | 它们本来就是无状态推导的产物，持久化 = 制造第二个事实源 |
| 素材字节（图集 / 图片 / 音频，含 base64） | **不是装不下，是同一目标有更合适的工具**（§1.3） |
| 需要跨设备 / 跨标签页一致的值 | 没有需求方（见 §4.1） |

### 1.3 为什么素材字节不走 localStorage（即使它装得下）

| 理由 | 说明 |
| :--- | :--- |
| 表示错配 | 键值永远是 **UTF-16 字符串**：二进制必须 base64（4/3 膨胀 × 2 字节/字符 ≈ **2.67×**），取回来还得自己造 Blob URL / `ArrayBuffer`。HTTP 缓存给的是浏览器已解好的字节，JS 侧零成本 |
| 同步阻塞主线程 | `localStorage` 读写是同步的。本项目的渲染循环里是几百个小人与逐帧插值（硬纪律 17），MB 级字符串的同步读写就是掉帧 |
| 没有 HTTP 语义 | 无 ETag / 304、无过期、无 `Content-Encoding`（**HTTP 缓存存的是压缩体**）、无 Range。失效与清理要自己发明 = 手写一个更差的 HTTP 缓存，验证负担永久落在我们身上 |
| 双份副本、且不保命 | 素材本来就在浏览器 HTTP 缓存里。驱逐是**整站一起删**（`localStorage` 与 Cache / IndexedDB 同时没），两者默认都是 best-effort —— 本地存一份**没有更持久**这个优势 |

**为什么连「省服务器资源」也不成立**：静态资源由平台托管，**免费且不计入每日接口额度**。素材的取用成本不是问题，问题只在缓存声明（见 `build.md`）。

## 2. 键协议

每个键都遵循这套契约（**读的是不可信输入**，与协议上行同等对待）。

| 项 | 规则 |
| :--- | :--- |
| 键名 | `sc.<域>.<项>`（`sc` = **sleep-cloud**，与 cookie `sc_session` 同族）。前缀与键名**只有一个来源**（`prefs.ts` 的注册表），调用点不许手写字符串 |
| 值形状 | **单键 = 单个 JSON 字符串**：`{"v":1, …}`。版本号放在**值里**、不放键名里（键名带版本会让旧键残留，还得额外清理遍历） |
| 一个偏好一个键 | 原子性好、版本化简单、坏一个不牵连别的 |
| 默认值 | **代码里的常量**，不是 `localStorage` 里的另一份备份。**缺键 = 默认值** |
| 读 | 唯一入口 `readPref(key, isValid, fallback)`：`getItem` → `JSON.parse` → 查 `v` → 跑 `isValid`（**白名单枚举**，不允许「任意 JSON 都收」）→ 任一环失败返回 `fallback` |
| 读到坏值 | **顺手删该键**（`removeItem`，也裹 try/catch）。不删就永久循环判废；删只发生在启动读一次的时候。**不做启动扫描清理** |
| 写 | `try { setItem } catch { 丢弃这次写入 }` —— **不弹提示、不重试、不降级到 `sessionStorage`**。隐私模式 / 配额满时用户照常玩，只是下次不记得（静默类错误不弹提示，硬纪律 13 精神） |
| 环境无 storage | **Node 单测（`localStorage` 不存在）与浏览器禁用持久化**（用户禁掉站点数据时，**连读这个属性都会抛 `SecurityError`**）：读 → 一律默认，写 → 丢弃。**判定只写在 `prefs.ts` 一处**，不散落 `typeof localStorage !== 'undefined'` |
| 读时机 | 启动时读一次进 `store` 初值，之后**不再碰 `localStorage`**（不进逐帧路径；也让 `localStorage` 只出现在一个模块里） |
| 上限 | **单值 ≲1KB、键数 ≲10**，写成规则（不做运行时配额检测 —— 现在没有需求方） |
| 清理与迁移 | **不建框架**：唯一的失效动作是「读到坏值 / 版本不符 → 删该键 + 用默认」。不做 `sc.` 前缀扫描，不做多标签页 `storage` 事件订阅（§4.1） |

## 3. 键登记表

**这是键的唯一真源**，`src/client/prefs.ts` 的注册表是它的镜像。

| 键名 | 值形状 | 默认值 | 校验（白名单） | 引入版本 |
| :--- | :--- | :--- | :--- | :--- |
| `sc.zoom.mode` | `{"v":1,"mode": "free"｜0.175｜0.5｜0.75｜1}` | `free`（缺键即默认） | `mode` 等于 `"free"`，或**恰好等于 `ZOOM_TIERS` 里的某一个比例** | v1 |
| `sc.weather` | `{"v":1,"kind":"none"｜"rain"}` | `none`（缺键即默认，见下） | `kind` 必须在合法天气 id 表里（当前只有 `none` / `rain`） | v1 |
| `sc.sound` | `{"v":1,"kind":"none"｜"rain"}` | `none`（缺键即默认，见下） | `kind` 必须在合法声道 id 表里（当前只有 `none` / `rain`） | v1 |
| `sc.about.seen` | `{"v":1,"seen":"0.0.7"}` | 缺键 = 从未确认过任何公告（首访） | `seen` 是**非空字符串且 ≤ 32 字符**（不校验版本号格式——它不是事实，只是与 `ANNOUNCE.version` 比字面相等） | v1 |
| `sc.read.seen` | `{"v":1,"seen":{"joke":["j1","j7"]},"current":{"joke":"j7"}}` | 缺键 = 一条都没读过 | `seen` / `current` 都是「分类 id → 字符串数组 / 字符串」的扁平映射：分类 id 非空 ≤ 32 字符、每条 id ≤ 32 字符、每类 ≤ `TYPE_TEXTS_PER_CATEGORY` 条；多出来的字段不读 | v1 |

**两个通道各一个键，形状相同（`{v, kind}`）**：以后加一种天气只需要往 id 表里加一行（`snow`），**不开新键**；声道同理（`fan`、`stream`）。要同时播两种声音才需要换形状（多选），到那天再改。

**旧键（v0.0.6 及更早的 `sc.weather.rain` / `sc.audio.rain`）读到就删**：形状是布尔，与现行 id 无法互转；`prefs.ts` 把那两个名字集中在 `LEGACY_KEYS` 一处、在读取时 `removeItem`。不迁移是刻意选择——偏好丢了回默认、功能完好（判据 1），而兼容两条形状会让每个读取点都多一个分支。

**`sc.zoom.mode` 的语义**（为什么只有这一种值会落盘）：

- **只有「显式锁定的档」才叫偏好**：用户从齿轮浮层的「缩放」里选了一档（`全厅` / `0.5×` / `0.75×` / `1×`），那是他的选择，整页重载后应当还在（iOS Safari 内存吃紧会丢标签页，而本产品就是「躺一晚再回来看」）。
- **`自由缩放` 下的连续比例不持久化**：捏合是**当场操作**，不是偏好。重载后回到 `1×`（`free` 模式本就「不锁定」，它没有"初值"这回事）。
- 因此：`free` 与「缺键」等价，但用户切回 `自由缩放` 时**照写一条**（写入路径只一条，不做「free 就删键」的第二条路径）。

**镜像测试**：既有镜像测试（`src/shared/tests/doc.ts`）守的是**跨端 / 跨进程边界**（协议、错误码、schema 分歧会产生真 bug）；键名不一致的代价只是**文档陈旧**，不跨端出错。**升级触发点已到**：早先写下「第 2 个键时补一条」这条规则，已经兑现——`prefs.test.ts` 断言「**本文件 §3 登记表里的键集合 === `prefs.ts` 的 `PREFS` 键集合**」（解析文档表格，不维护第三份名单）。现在是第 5 个键（`sc.zoom.mode` + `sc.weather` + `sc.sound` + `sc.about.seen` + `sc.read.seen`），加键不再需要重新决策。

**`sc.weather` 的语义**：

- **天气是个人偏好**：权威不在服务端（判据 2 通过）；值只有两个 id、丢回默认功能完好（判据 1）；几十字节、只在启动与切换时读写（判据 3）
- **缺键 = 无雨（`none`）**：默认值是常量，与全表统一——**不读日期、不读时钟、不看时区**。没有人选择过的状态不该出现在屏上（公共场合外放的代价由用户承担，不能由日期替他决定）
- **没有「跟随日期」这个选项**：多一项就多一个用户要理解的选项，而它会让用户以为天气与真实天气同步
- 用户切过之后永久生效（切回 `none` 也照写一条，见下）
- 它**只驱动雨层画面**；声音是另一个键（见下），音频字节本身**不进本地存储**，走 HTTP 缓存（§1.3）

**`sc.sound` 的语义**：

- **声音是第二个独立开关**：判据三条与天气同（权威在客户端、丢回默认功能完好、几十字节只在启动与切换时读写）
- **缺键 = 静音（`none`）**：默认值是常量，与全表统一——第一次打开**不出声**。这条不是洁癖：外放场景下「一开站就有白噪音」的代价由用户承担，不能由日期或上游默认替他决定
- **与 `sc.weather` 解耦**：画面归画面、声音归声音。无雨也能开雨声（只听雨、不画雨），雨天也能静音（只看雨）。两态互不覆盖，也**不做联动**（如「开雨天就顺手开声」）——联动会让用户的一次选择改掉另一个偏好
- 关声音**不删键**：照写 `{"v":1,"kind":"none"}`，与天气同一套写法

**`sc.about.seen` 的语义**（说明面板的已读标记，设计见 `90-about-panel.md`）：

- **它记的是「这一版公告我见过了」，不是「我读完了」**：值与 `about.ts` 的 `ANNOUNCE.version` 逐字比较，不等就弹一次，相等就不再自动弹
- **缺键就是首访**：本功能上线那一刻，所有已有设备都没有这个键，于是与真首访**不可区分**——这是**接受**的行为（各自多读一次产品介绍），**不做种子重置、不碰 `PREFS_VERSION`**
- **`PREFS_VERSION` 递增会让它一起判废 → 面板再弹一次**：可接受，一版一重置本来就是「偏好回默认」，而再弹一次本身无害
- **不校验版本号格式**：坏值唯一后果是再弹一次（没有副作用），所以白名单只判「非空字符串 + 长度上限」

**`sc.read.seen` 的语义**（类型文本的阅读进度，设计见 `50-slot-panel.md` §附）：

- **一个键管全部阅读状态**：`seen`（每个分类抽到过的条目 id）+ `current`（每个分类的当前条）。两者一起读、一起写——拆成两个键就会出现「当前条写了、`seen` 没写」的中间态，而它们本来就是同一件事：读到哪了。
- **三条判据都过**：丢了回默认（当作一条都没读过、重抽一轮，功能完好）；权威不在服务端（服务端不知道内容文件，更不知道谁读了）；小且低频（每类 ≤ `TYPE_TEXTS_PER_CATEGORY` = 120 个 id，整值约 1KB 上限；只在抽签与重载时读写，**不进逐帧路径**）。
- **`current` 也落盘**：不落的话刷新页面就丢掉当前条，而它已经被记进 `seen`——没读完的那一条只能等这一轮全抽完才再见到。用户在「读完」之前不该失去它。
- **脏值靠规则自然消化，不做迁移**：数据换代后 `seen` 里可能有已不存在的 id（池 = items − seen 自然过滤）、`current` 可能指向不存在的条目（读时校验，不在就当无当前条）。**不递增 `PREFS_VERSION`**——那会让天气 / 缩放 / 公告一起判废。
- **不剪枝**：脏 id 留在值里无害（池过滤它、`current` 读时校验），而修剪需要多一条写入路径。值只在抽签 / 再看一遍 / 重置时才重写。

## 4. 非目标与候选项

| 项 | 状态 |
| :--- | :--- |
| **多标签页同步**（`storage` 事件、冲突策略） | 不做。没有需求方；真要做，先要定「两个标签页同时改一个值听谁的」 |
| **跨设备同步** | 不做。那需要账号（见 `backlog.md` 的风控节） |
| **离线可用 / 弱网可用**（SW + Cache Storage） | 不做。那是另一个量级的设计（缓存策略、版本淘汰、更新提示），本项目现在的目标是「打开即用」，不是「离线可用」 |
| **相机位置**（上次看的地方） | 候选，未落盘。判据 1、2 都过，判据 3 也过，但**现在没有需求方**：重载后相机对准我的床是确定性的正确行为 |
| **音量**（0…1 / 滑杆） | 不做。**开 / 关已经有了**（`sc.sound`），而「多响」现在没有需求方：文件电平已定死（`config.md` §4），加滑杆要配上「多大才是默认」的决策（`backlog.md`） |
| **会话草稿**（未提交的昵称 / 形象） | 不做。服务端 cookie 里已有权威值，草稿只在「提交失败」时有价值，而那条路径有提示条；加了就要定「本地 vs 服务端谁是初值」 |
| **`sessionStorage` / IndexedDB / Service Worker** | 不用。一个键一个字符串的规模，引入第二套存储工具只增加失效语义的分叉 |
| **升级路径** | 若将来出现 **>1KB 或需要二进制** 的本地需求（例如缓存音频）：**换工具（IndexedDB / Cache Storage），不放宽本文规则** |
| **换键名前缀** | 前缀一旦发布就是兼容性承诺：改前缀 = 老用户的偏好静默丢失并回默认。**所以现在定死在 `sc.`，别等有用户之后再改** |

## 5. 变更手续

- 加一个键 = ①判据三条过一遍 ②§3 键登记表加一行 ③`prefs.ts` 注册表加一条 ④一条单测（默认 / 坏值 / 非法值）。
- 改一个键的值形状 = **递增 `v`**（旧值自动判废，不需要迁移代码）。
- 删一个键 = 从登记表与注册表各删一行；**已写进用户设备的那条键不主动清**（读的人没了，它就只是几十字节的死数据，直到用户清站点数据）。
