# 日志与可观测性

> 本文只定义**我们写什么**与**平台能回答什么**。平台侧的数字（额度、保留期）是会变的**外部参数**，代码不得依赖它们。

## 1. 边界：日志不是数据源

| 属于日志 | 不属于日志 |
| :--- | :--- |
| 异常、被拒意图、静默降级的计数 | 聊天文本、昵称、IP、国家、UA 哈希（L3 只进台账，见 `70-privacy-risk.md` §2） |
| 「谁做了什么」的**结果**（躺下 / 睡着 / 起身 / 举报 / 封禁） | 位置坐标与每一帧上行的流水 |
| 厅的整体状态快照（在线、已用床位、级） | 任何会被业务逻辑回读的东西（日志是单向的写） |

**日志是诊断与统计的旁路，不参与任何判定。** 因此：写失败必须被吞掉、绝不能抛（`Hall` 的消息主路径上抛一次就打断整次广播）；日志量级不足时宁可少记，不能改业务行为。

## 2. 平台侧的事实与我们的用法

| 事实 | 我们的用法 |
| :--- | :--- |
| 每次 invocation 自动一条（含 method/URL/status/CPU） | **关掉**（`observability.logs.invocation_logs: false`）。WebSocket 每帧都是一次 invocation，开着会把额度打满，且我们真正要看的字段它都没有 |
| `console.log` 的对象会被**拆成字段并索引** | 所有事件写**对象**，不写拼接字符串（拼接后只能全文搜，不能 `Group By`） |
| 免费额度 200,000 事件/天（invocation + 自定义共用） | 预算见 §5，当前实测量级约 5,300/天 |
| 保留期：免费计划 3 天（平台公告 2026-12-01 起 7 天） | **不写进任何逻辑**。需要跨窗口的指标见 §7 |
| 单条日志 ≤ 256 KB，超出被截断 | 我们单条 ≤ 2 KB（字段都是短标量） |
| Query Builder 免开通，可聚合/分组/分位数/保存查询；平台另有自带的 REST API 可程序化跑同样的查询（**不用我们实现任何东西**） | 运营数据的唯一出口，配方见 §6 |

## 3. 事件契约

字段只有三种类型：`string`（短）、`number`、`boolean`。**不嵌套**（嵌套会变成可 `Group By` 的路径键，让查询难写）。

| `ev` | 字段 | 何时写 | 量级/天 |
| :--- | :--- | :--- | :--- |
| `enter` | `fresh`（是否新身份）、`online` | 握手 `hello` 成功 | 与入场人次同阶 |
| `lie` | `bed`、`from`（`empty` = 本次没有当场释放别的床 / `swap` = 当场释放了另一张床的归属） | 躺下（含换床） | 几百 |
| `sleep` | `bed`、`auto` | 睡着（手动 / 自动） | 几百 |
| `wake` | `bed`、`dwellMs`（躺下→起身，**含清醒躺着的那段**，不含离线那段：睡痕恢复会重算起点） | 起身**这一次**（即 `clearBed` 那一次）；`wakeUp`（说着话自动醒）与弃床离开不写——人没起身，写进去 dwellMs 就变成半程样本 | 几百 |
| `chat` | `len`（= **打码后实际下发**那份的字符数）、`dm` | 发出成功的聊天（**不含文本**）；对方不在厅的私聊没发出去，不记 | 千级 |
| `report` | `target`（被举报人的 `uid`）、`dup`（24h 内合并计数） | 举报 | 个位数 |
| `block` | `until`（0 = 永久）、`by`（`auto` = 入场判定命中 / `admin` = 后台写） | 封禁判定命中 / 后台动作 | 个位数 |
| `settle` | `wakes`、`traces`、`from`、`to`、`ms` | 每日唤醒结算：`wakes` = 本轮释放归属的床数、`traces` = 其中原本是睡痕的张数、`from`/`to` = 结算前后的**级容量**（床数，不是级下标）、`ms` = 本轮耗时 | 1~2 |
| `tick` | `online`、`used`（已用床数）、`beds`（本档床数）、`level`（级表下标，从 0 起） | 每 5 分钟（仅在厅里有连接时） | 288 |
| `snapshot` | `bytes`（= 那条已序列化 payload 的 `length`，**UTF-16 码元**不算字节）、`people`、`beds` | 每次下发快照 | 与入场人次同阶 |
| `reject` | `code`、`intent`（上行类型；入场前置校验用 `hello`） | 意图被拒（`3001`~`3008`/`4002`），以及 Worker 侧 `/api/ws` 的入场前置校验（`1001`/`1002`/`1003`） | 高，受 §4 闸门 |
| `censor` | `kind`（`word` = 词表 / `contact` = 联系方式与引流）、`n`（该类目打码的字符数） | 内容过滤打码命中；**跨类目重叠的字符两边各算**，所以 Σ`n` 可能大于真实打码字符数——算比值时按 `kind` 分开算 | 高，受 §4 闸门 |
| `drop` | `kind`（`send`/`skip`/`parse`/`limit`）、`n` | 静默降级：发送失败、广播跳过、解析失败、限流丢弃 | 高，受 §4 闸门 |
| `err` | `where`、`code` | 异常 | 应与 5xx 同阶 |
| `suppressed` | `n` | 闸门丢弃的条数汇总（每 5 分钟最多一条） | ≤288 |

`uid`（`userId`）是**唯一允许**的身份字段，挂在有「某个人」做主语的事件上（`enter`/`lie`/`sleep`/`wake`/`chat`/`report`/`block`）；**系统事件不挂**（`settle`/`tick`/`snapshot`/`drop`/`suppressed`）；`reject`/`censor`/`err` **能读到连接时才挂**——入场阶段被拒（`2003`/`2004`/`2002`/`5002`）时连接里还没有身份，那就不挂；后台写的 `block{by:'admin'}` **不挂**（那里的主语是 `kind`+`value`，`value` 可能是 IP，L3 不入日志）。`Count Distinct` 靠 `uid` 算「今天多少人」。除它之外不写任何可指向个人的东西。

`err` 的两个字段是**封闭词表**（新入口要加词先改这张表）：`where` ∈ `http` / `do-fetch` / `ws-message` / `ws-close` / `alarm` / `admin-request` / `admin-close`；`code` 用既有错误码，归不了类就用 `9001`（未知错误）。一次 DO 层的失败可能在 `do-fetch` 与 `http` 各记一条（前者记完继续抛，后者是 Worker 的 `onError`），算作两条不算重复。`reject` 记的是**被拒的意图**（`3001`~`3008` / `4002`）——`5003` 是举报成功的回执，不走 `sendError`，因此不会进 `reject`。此外 **`/api/ws` 的入场前置校验（`1001`/`1002`/`1003`）也记一条 `reject{intent:'hello'}`**：这是唯一能看出「浏览器没把会话留住」的服务端痕迹（客户端只看得到 `close(1006)`，见 `../api/10-api-http.md` §2.1）。它**不是常态流量**（入场层的复核会先拦下 cookie 不落地的浏览器），但可能是爆发式的（复核之后才丢会话、轮换 `SESSION_SECRET` 的那次部署）——几个人同时撞上就会把 §4 的 30 条/分钟打满，打满之后看 `suppressed{n}` 的溢出计数，不要得出「没有 `reject` 就是没事」的结论。

**没有 `db` 事件**：SQLite 行读/写与房间服务请求量平台用量面板已给（`build.md` §5），重复记一遍只花额度。

## 4. 出口契约（单一模块）

所有事件只能经由一个模块产出（与 `40-client-storage.md` 里 `prefs.ts` 的「单一模块」同理）：

1. **字段白名单**：`ev` 必须在 §3 的表里，字段名必须在它的列里；多出的键直接丢弃（拼错的字段名会静默变成上线才发现查不到数据）。
2. **永不抛**：整个出口包在 `try/catch` 里。丢日志可以，丢广播不行。
3. **闸门（按需聚合）**：`reject`/`censor`/`drop`/`err` 四类每分钟最多 **30 条**；超出只累加计数，每 5 分钟最多产出一条 `suppressed`。闸门计数只在内存里（对象被驱逐就归零）——它是安全网，不是账本。
4. **静默点必须带 `n`**：单次发送失败、单次广播跳过都不值得一条日志，攒到阈值（默认 20 次或 5 分钟）再写一条带 `n` 的。逐条写会在故障时**用日志把额度打穿**，而故障期间最需要额度留下的恰恰是别的证据。
5. **失败即静默**：出口自己不报错、不重试、不等待。

## 5. 额度预算

| 来源 | 估算/天 | 说明 |
| :--- | :--- | :--- |
| 结构事件（`enter`/`lie`/`sleep`/`wake`/`chat`/`report`/`block`/`settle`/`snapshot`） | ~4,000 | 随真实使用线性增长 |
| `tick` | 288 | 无人连接时不写（厅里没人在跑循环） |
| 受闸门事件（`reject`/`censor`/`drop`/`err`）+ `suppressed` | ≤43,200 | 上限 = 30/分钟 |
| **合计** | **≤5 万** | 额度 **20 万**，余量 4× |

打满额度的两个先兆（都在 Events 视图里按 `ev` 分组看得见）：`drop{kind:'limit'}` 突然出现、`tick` 条数远超 288（说明有第二个实例在跑）。

**采样不是第一手段**。`head_sampling_rate` 会**按请求**整份丢弃，包括那次请求里的异常——排障最需要的样本恰好最先被丢。先靠字段白名单与闸门控量，仍不够再采样。

## 6. 常用保存查询（Query Builder，账户级共享）

直接照着建，建完 **Save Query** 并打上 `sleep-cloud` 标签。**这十行只是控制台里的快捷方式**（账户级、可分享链接）：不建也一点都不影响功能，只是以后查要重输一遍过滤器；也不需要写任何代码——平台自带的 REST API 负责程序化查询，保存查询只是给人点的。

| 想看 | Filter | Visualization |
| :--- | :--- | :--- |
| 今晚多少人 | `ev = enter` | `Count Distinct uid` |
| 一小时在线峰值 | `ev = tick`，时间范围按小时 | Group By 时间桶 → `Max online` |
| 厅的利用率 | `ev = tick` | `Max used` / `Max beds` |
| 躺下 vs 睡着 | `ev = lie` / `ev = sleep` | `Count`（两个查询相除） |
| **一起睡了多久** | `ev = wake` | `Avg / P50 / P95 dwellMs` |
| 意图被拒都在哪 | `ev = reject` | `Count`，Group By `code`，Order By desc |
| 聊天与打码 | `ev = chat` / `ev = censor` | `Count`、Group By `kind` |
| 厅是不是在频繁升降级 | `ev = settle` | `Count`，Group By `to` |
| 入场快照有多大 | `ev = snapshot` | `Max bytes`、`P95 bytes` |
| 异常都在哪 | `ev = err` | `Count`，Group By `where` |

> `Count Distinct` 是「人数」的唯一正确算法（`Count` 数的是事件条数）。**次留答不了**：它要「昨天那些人 ∩ 今天那些人」，Query Builder 没有集合交集——见 `backlog.md`。

## 7. 已知代价与刻意不做

| 项 | 代价 / 理由 |
| :--- | :--- |
| 保留期 3 天（12-01 起 7 天） | 「上周五的故障」在周一已经查不到。要更长只有 Logpush → R2（付费） |
| 关掉 invocation log | HTTP 层不再自动留痕：method/URL/status 缺失。入口只写 5xx 与异常（`err`），其余请求不写 |
| 四个入口的异常只多一条日志 | `ws-message` / `ws-close` 的异常记一条 `err` 后**吞掉**（平台本来也吞，区别只是我们留下了证据）；`do-fetch` 与 `alarm` 记一条后**继续抛**——它们的失败形态（HTTP 500 文本 / 平台的退避重试）变了就是回归 |
| `dwellMs` 多一次行读 | 起身时读 `sleep_started_at`（+1 行读 / 次）。量级几百/天，可接受 |
| 闸门计数在内存 | 对象驱逐后归零，一天可能不止一次 30/分钟 的窗口。它只是安全网 |
| `tick` 是独立的一条内存循环 | 周期与位置拍子（100 ms）相差 3000 倍，无法复用一个循环；因此另起一条**连接作用域**的 `setInterval`：`hello` 起、最后一条连接关掉就 `clear`。代价：对象被驱逐重建后若只剩旧连接（没有新 `hello`），`tick` 暂停到下一次握手——**宁可没有 tick，也不许有永不清的循环** |
| **不做**客户端错误上报 | 新增公开上报接口 = 新增滥用面；且断网/白屏类问题本地复现更快。见 `backlog.md` |
| **不做**日志进 SQLite | 写入额度 10 万/天，日志是它的天然放大器；且会把「可丢弃的临时量」混进权威库 |

## 8. 升级路径（触发条件 → 动作）

| 触发条件 | 动作 |
| :--- | :--- |
| 需要跨保留期的趋势（月报、次留） | 厅内 SQLite 加一张按日聚合表 + 后台统计区块（不引 D1；数据形状已由 §3 定死） |
| 需要跨部署/换机器的历史 | 才引 D1 异步投影（`build.md` §6） |
| 事故后要留证超过保留期 | Logpush → R2 |
| 需要「错误自动归组 + 通知」 | 平台的 Issues（对 `console.error` 生效；不改本文契约） |
