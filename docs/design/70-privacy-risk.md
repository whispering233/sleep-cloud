# 隐私与风控

## 1. 这份文档管什么

| 管 | 不管 |
| :--- | :--- |
| 我们记录了什么关于**人**的东西、为什么记、存多久、谁能看、怎么删 | 与人不相关的几何与床位（`00-master-design.md`、`20-layout.md`） |
| 滥用发生时**能做什么**（封禁的语义与边界） | 时间常量与限额的**数值**（`config.md`，本文只说「有哪几个时钟」） |
| 三层身份的职责分工与禁令 | 数据模型字段全表（`../db/schema.md`） |

**一句话**：不要求注册，但必须能识别**来源**；识别来源的代价是承担**告知**与**留存**义务。这两件事必须同时成立，只做一半就是负债。

## 2. 三层身份：不要把三件事压进一个 cookie

第一版把「你是谁」「你凭什么证明」「你从哪来」全压在 `sc_session` 一个 cookie 上。这是「随机 userId 不是长期方案」的真正病灶——**不是随机性不够，是分层缺失**。

| 层 | 职责 | 今天是什么 | 谁决定 |
| :--- | :--- | :--- | :--- |
| **L1 身份** | 「你是谁」。持久、可封禁、可被绑定 | `u_` + **16 个十六进制字符（64 bit）**，服务端随机，**不派生自请求的任何属性** | 服务端 |
| **L2 凭据** | 「你凭什么证明你是 L1」 | `sc_session`（HMAC 签名 cookie，HttpOnly / SameSite=Lax / 400 天 / 每次响应重签）。**唯一一种凭据** | 服务端 |
| **L3 来源** | 「你从哪条网络、哪类客户端来」。用于关联与封禁 | IP、`country`、UA 哈希。**仅运维可见，永不下发给其它用户** | 平台给的头 |

### 2.1 为什么 L1 是随机而不是派生

派生式身份（`hash(ip + ua)`）被否决，三条理由：

1. 移动网络一换就换人；同一 NAT 下多人撞成同一身份。
2. 它把一个**假设**当事实——与「上行是意图、下行是事实」是同一条纪律。
3. 撞号（或推导一致）的失败形态是**静默的**，见 §2.2。

### 2.2 64 bit 不是安全参数，是撞号防护

`user_id` 不是秘密：猜中别人的 id 毫无用处（冒充需要 `SESSION_SECRET`，与 id 长度无关）。它的位数只决定**两个人被签成同一个身份的碰撞概率**（生日近似 `n² / 2^bits`）：

| 签发过的身份总数 n | 40 bit（旧） | 64 bit（现在） |
| :--- | :--- | :--- |
| 10⁴ | 0.0045% | 可忽略 |
| 10⁵ | **0.45%** | 2.7 × 10⁻⁸ % |
| 10⁶ | **45%** | 2.8 × 10⁻⁶ % |

**撞号的失败形态比报错更糟**：认领时会先执行「把该 `owner_user_id` 名下其它床让开」，所以两个撞号的人会**静默互相抢床**——没有错误码、没有提示，只是某天床没了。64 bit 之后这条永久不是问题。

### 2.3 禁令（写进 `AGENTS.md` 硬纪律）

1. **身份 ≠ 凭据**：凭据失效不等于换人。任何代码与文档不得假设「cookie 就是身份的全部」。
2. **任何新凭据接入时（passkey / 登录 / 找回码），L1 不变**：`user_id` 的取值语义不变，`bed.owner_user_id` 这个关联键不变，只加凭据到身份的映射。
3. **L3 永不下发**：IP、`country`、UA 哈希不进入任何面向用户的协议字段。

## 3. 数据清单

### 3.1 记录了什么

| 数据 | 从哪来 | 用途 | 在哪 | 留存 |
| :--- | :--- | :--- | :--- | :--- |
| `user_id` | 服务端随机签发 | 身份（L1）；床位归属的关联键 | cookie + `identity` + `bed` | 见各行 |
| 昵称 `nickname` | **用户自己输入**（入场层） | 显示；运维在台账里认人 | cookie + `bed.owner_name` 快照 + `identity.nickname`（最近一次） | 床位行随归属；`identity` 那份与来源信息一同 **90 天清空** |
| 形象 `appearance` | 用户选择，未选则按 `user_id` 派生 | 渲染 | cookie + `bed.owner_appearance` | 同上 |
| 18 岁自述位 `ageConfirmed` | 入场一次点击（**自述，不是核验**） | 法律免责表述 | cookie | 随 cookie |
| 床位归属与占用 | 行为派生 | 「我的床」、占用状态 | `bed` | 归属 30 天无访问释放；**睡痕没有独立期限，跟归属同寿**（因此也不存在「你多久前睡过哪张床」的更长期记录） |
| **举报**（对象 / 事由 / 证据） | 用户点「确认举报」时提交 | 让运维看见骚扰事件：一条信号 + 当时那几句话 | `report` | **两个时钟**：证据自首次举报（`created_at`）**90 天**清空；行（谁报了谁 / 事由 / 次数）自最后一次举报（`last_at`）**90 天**删除 |
| **反馈**（用户主动提交的文字） | 齿轮里的「反馈与建议」 | 让运维看见用户想说什么（bug / 功能 / 体验）；**不回复、不公开** | `feedback` | **90 天**（每日唤醒删除） |
| **发言缓冲** | 每个人**自己**发出的聊天与私聊（打码后的文本，最近 10 条） | 只在被举报那一刻当证据 | **厅的内存**（不落库、不进连接附加数据） | 驱逐即丢；每日唤醒整体清空 |
| **IP 全文** | 平台头 `CF-Connecting-IP` | **封禁与反查的唯一硬杠杆** | `identity.last_ip` | **90 天无访问后清空**（不删行） |
| **`country`** | `request.cf.country`（ISO-3166-1 α2；TOR 为 `T1`） | 识别跨国/匿名网络刷屏 | `identity.last_country` | 同上 |
| **UA 哈希** | 请求头，SHA-256 后取 16 hex | 区分客户端类型；辅助关联 | `identity.ua_hash` | 同上 |
| 首见 / 最近一见时刻 | 入场时推导 | 台账排序、留存判定 | `identity` | 行不删 |
| 封禁记录 | 运维动作 | 黑名单本体 | `block` | 永久封禁永久留；有到期的到期 + 30 天后删 |
| 审计记录 | 运维动作 | 「谁在何时封了谁」 | `admin_audit` | 1 年 |
| **日志事件**（`100-log.md` §3） | 服务端自己产出（`console` → 平台 Observability） | 排障与统计：入场 / 躺下 / 睡着 / 起身时长 / 举报 / 封禁命中 / 被拒意图 / 打码计数 | **平台的日志存储**，不进我们的库 | **平台保留期**：3 天（平台公告 12-01 起 7 天）。字段只有 `ev` 名与短标量，`uid` 是唯一身份字段；**不含文本、昵称、坐标、IP、国家、UA** |

### 3.2 明确不记录

| 不记 | 原因 |
| :--- | :--- |
| **聊天与私聊内容** | 服务端不存、客户端不留消息流。代价是事后无法取证（见 `backlog.md`） |
| 位置与移动路径 | 高频；**醒着的人一定有活着的连接**，放连接附加数据（内存）即可 |
| UA 原文、Referer、ASN、城市、经纬度、时区 | 没有需求方。UA 只留哈希 |
| 情绪/表情事件 | 瞬时，无持久意义 |

**UA 哈希是遮挡，不是匿名化**。UA 字符串本身熵很低（实际可枚举），所以「哈希后不可还原」这句话**不成立**。写进告知时不能说「已匿名化」，只能说「不保存原文」。这条必须诚实，否则告知本身就是误导。

## 4. 风控手段与边界

| 手段 | 状态 | 表现 |
| :--- | :--- | :--- |
| 昵称敏感词 | **已有** | 命中 → **拒绝**并提示改名（`1005`）。用**窄词集**（九类 + 手工表）：昵称命中即无法入场，误伤代价是用户进不来；分级见 `config.md` §6 |
| 聊天敏感词 | **已有** | 命中 → **打码**后照常转发（不拦截）。用**全量词集**（约 2.5 万条）并按联系方式模式补打码：误伤代价只是几个星号。硬拦截会让发送者意识到被审查并试探绕过 |
| 上行限流 | **已有** | 每条连接 5 条/秒，超出静默丢弃（`4002`） |
| **封禁** | **本次新增** | 拒绝入场（`5002`），见 §5 |
| 举报 | **本次新增** | 上行 `report`（对象只取当前选中，不要求在线）。落库一行并回 `5003`；**证据是被举报人最近 ≤10 条发言的快照**，只在举报那一刻拷（没有全量日志）。同一对 24 小时只占一行，90 天清空 |
| 禁言（`muted` / `5001`） | **继续预留** | 没有取证链时，禁言只会让用户看到「话发不出去」却解释不了 |
| 渐进惩罚 / 违规累计 / 投票踢人 | 不做 | 需要违规检测维度累计，现在没有任何检测信号 |
| 设备指纹、年龄分区 | 不做 | 前者是过度采集，后者只有「18 岁自述」一个字段 |

**判断原则**：任何「需要当事人配合」的手段对滥用无效——攻击者不会配合。所以风控的上限由 **L3 的环境信号** 决定，与 L1/L2 无关。

## 5. 封禁

### 5.1 语义

| 项 | 决定 | 理由 |
| :--- | :--- | :--- |
| 档位 | **只有 `banned`（拒绝入场）**；`muted` 继续预留 | 用户要的是「拉黑」，不是「禁言」 |
| 维度 | **`user` 与 `ip` 两个维度都真封，命中任一即拒** | 只封 user：清 cookie 即过。只封 ip：共享网络误伤。两条都留，由操作者选 |
| 时长 | `until_at` 为空 = **永久**；可填到期 | 「ip 永久封」误伤一整片网络且不可逆，得给操作者一把轻一点的锤子 |
| 到期 | **读取时推导**（`until_at > now`），不挂定时器、不写清理任务 | 同「状态是时间戳的函数」纪律（`10-hall-runtime.md` §4.3） |
| 他的床 | **不释放**，走既有的「30 天无访问自动释放」 | 归属与封禁是两个正交概念（`../db/schema.md` §2）。释放要广播 `bed(owned:false)`，且解封后会产生「我的床呢」这种无法解释的状态 |
| 封一个没有记录的 userId | 允许（`block` 行不依赖 `identity` 行存在） | 黑名单不能因为台账过期而失效 |

### 5.2 生效点：两处，一次调用

| 位置 | 做什么 | 为什么在这里 |
| :--- | :--- | :--- |
| **HTTP `/api/me`**（入场前） | 一次 `entryStatus(来源)` 同时拿「厅满」和「是否被封」 | 这是唯一天然的入场前判定点（厅满 `2002` 已经在这里）；浏览器的 WebSocket API **读不到升级失败时的响应体**，所以「拦在升级之后」等于没提示 |
| **`hello`**（厅内） | 再判一次，命中 → `5002` + 断开 | 兵底：直接对 `/api/ws` 发包可以绕过第一处 |

**不新增 RPC 方法**：`entryStatus()` 扩成 `entryStatus(来源)` → `{ bedCount, full, blocked }`，其中 `blocked` 带 `untilAt`。多开一个方法就是多一条唤醒路径，也会随时间漂移成两个判定。

### 5.3 在线时被封：立刻踢，且客户端必须停手

| 步骤 | 谁做 |
| :--- | :--- |
| 后台点「封禁」 | Worker → 厅对象（同 `/api/ws` 的转发范式） |
| 厅写 `block` + 写审计 + **遍历该 userId / 该 IP 的在线连接并关闭** | 厅（连接集合在厅里；`close(1008, 'blocked')`） |
| 客户端按 `close` 语义分支：`blocked` → **停止自动重连** + 常驻提示；`replaced` / `2003` / `2002` → 同样停住（文案见 `../api/20-api-ws.md` §5.1.1） | 客户端 |

**为什么必须改客户端**：现在客户端只看 close code，`1000` 属正常关闭 → 按退避自动重连、**永不放弃**。若封禁也用正常关闭，被封的人会每 15 秒撞一次 `/api/me`（一晚约 5760 次唤醒 + 行读）——正是项目最怕的成本放大器。这与 `backlog.md` 里「多标签页互相顶掉、各自不停重连」是同一处、同一修法，一并解决。

### 5.4 提示：封禁不许静默

| 时机 | 表现 | 契约 |
| :--- | :--- | :--- |
| 入场前 | 入场层一条明确说明：`你暂时无法进入 · 还有 8 分钟`；永久封禁不显示倒计时 | `5002` 的响应带 `data.untilAt`（`null` = 永久） |
| 厅内被封（踢） | 断开后**常驻提示**（同连接态提示条的形态，不是浮层） | `close(1008, 'blocked')` |

**给到期时间，不给原因**：`8 分钟` 无法被用来绕过；`因为刷屏` 会告诉他下次怎么绕。内部 `reason` 只进审计，不下发给用户。

`5002` **明确不属于静默类**（`../api/error-code.md` §3 的静默列表本来就没有它）。这条与「静默类错误不弹提示」的纪律不冲突：那条针对的是**无意义的操作失败**（点了墙上、发太快），不是**有意义的拒绝**。

## 6. 存放位置与成本

**所有风控数据放在厅的 SQLite 里**（`identity` / `block` / `admin_audit` / `report` / `feedback`，见 `../db/schema.md`）。被否决的两个方案：

| 方案 | 否决理由 |
| :--- | :--- |
| 独立的有状态对象（`Risk` 类，自己一份 SQLite） | 多一个新类、新 migration、每处 schema 各自维护版本；且「IP 是否被封」与「能不能躺」不在同一次调用里。只有一个厅时，分离买不到任何一致性或隔离上的实益 |
| KV / D1 | 架构已定「不引入」（`architecture.md` §1）。KV 最终一致 → 封禁生效有窗口；D1 = 第二个真相源 + 新绑定 |

**成本增量**（并入 `architecture.md` §5 的口径）：

| 事件 | 增量 |
| :--- | :--- |
| 一次页面加载（`/api/me`） | +2 行读（封禁判定最多两个索引命中） |
| 一次成功入场（`hello`） | +1 行写（`identity` UPSERT，与既有的 `last_seen_at` 写并列）+1~2 行读 |
| 每日唤醒 | +6 条清理语句（见 §7） |

## 7. 留存清理，全部挂在每日唤醒

**不新开唤醒**：六个清理动作并入既有的每日唤醒（UTC 20:00，与归属释放、缩级评估同一批次）——这是「三种时间机制职责不重叠」的正确用法：能算的算，必须发生的合在一处发生。

| 动作 | 规则 | 形态 |
| :--- | :--- | :--- |
| 来源信息与昵称过期 | `last_seen_at` 超过 90 天的行，把 `last_ip` / `last_country` / `ua_hash` / `nickname` 置空 | `UPDATE`。**不删行**：行本身（id + 首见/最近一见）不指向具体的人，删它没有隐私收益，却会让「这个 id 曾经存在」无法解释 |
| 到期封禁清理 | `until_at` 非空且 `until_at + 30 天 < now` 的行删除 | `DELETE`。**永久封禁（`until_at` 为空）永不清理**——它就是黑名单本体 |
| 审计清理 | `at` 超过 1 年的行删除 | `DELETE` |
| 举报证据过期 | `created_at` 超过 90 天的行，把 `evidence` 置 `'[]'`（**行与 `count` 保留**） | `UPDATE`。证据是「他当时这么说了」，只该活到首次举报起 90 天。**不能只靠整行删除**：同一对每 24 小时被重复举报会刷新 `last_at`，只按 `last_at` 删就会让**第 0 天**的那几句原话无限期留在库里，告知里那句「90 天」就不成立 |
| 举报行清理 | `last_at` 超过 90 天的行删除 | `DELETE`。行是「谁报了谁 + 事由 + 次数」，不含聊天正文；它从最后一次举报起算，所以一直被反复举报的对可以一直留着——这是刻意的，运维正需要这个信号 |
| 反馈清理 | `created_at` 超过 90 天的行删除 | `DELETE`。用户主动写的文字，只给运维看；没有证据、没有关联行 |

**`block` 行不依赖 `identity` 行**：台账被清空（或来源被置空）之后，黑名单照样生效。这是两件事，别耦合。

## 8. 告知与删除

### 8.1 露出位置

| 位置 | 内容 |
| :--- | :--- |
| 入场层「18 岁自述」那一行 | 一行 12px 灰字「使用须知与隐私说明」，点开静态页 |
| 齿轮浮层 | 同名入口（一致性） |
| 静态页 | `public/privacy.html`，**零接口、零数据**，由平台静态资源直接托管 |

**不新增第四个入场区块**：入场层只有三项（昵称 / 18 岁自述 / 形象，见 `00-master-design.md` §7）。隐私告知与 18 岁自述同源——两者都是**入场前的同意面**，所以放在同一处。

**两处入口的两个坑（都踩过，别再踩）**：

| 坑 | 症状 | 做法 |
| :--- | :--- | :--- |
| 链接写 `/privacy`（省略扩展名） | 生产上平台资产会 307 到它、看起来没问题；但 `npm run dev:web`（Vite）**没有** `html_handling`，`/privacy` 落进 SPA 回退、打开的是大厅首页——**看起来就是「点了没反应」** | 链接一律写 **`/privacy.html`**：生产 307 到 `/privacy`（多一跳但一定到），Vite 直接命中 |
| 只靠 `target="_blank"` | 新标签被拦下时**什么都不发生**，没有任何反馈 | `<a>` 上不写 `target`；点击时 `window.open`，成功就 `preventDefault`（避免开两次）、返回 `null` 就退回同标签导航。实现在 `src/client/privacy-link.ts`（两处入口共用一份） |

### 8.2 告知里必须说清的七条

1. **不要求注册**，所以服务端**从未拥有过你的真实身份**。你的身份是一个随机标识，存在你浏览器的 cookie 里——清掉它就等于换了身份，**床位也随之丢失**。
2. 我们记录什么：访问来源 IP、所在国家、浏览器类型的哈希、首次/最近访问时间、你的昵称与所选形象、你的床位，以及你主动提交的反馈内容。
3. 为什么记：**只用于防止滥用（刷屏、恶意骚扰）与排查故障**。不做画像、不做广告、不提供给任何人。
4. 留多久：我们**每天定时清理一次**（UTC 20:00，约北京时间次日 04:00），所以下面每个期限到期后最多再留一天。
   - 来源信息（IP / 国家 / UA 哈希）与昵称：**90 天**（自你最后一次进厅起），之后这三个字段与昵称被清空，只留一个不再指向任何人的编号。
   - 床位：**30 天**无访问即释放（床上的昵称与形象快照随同一天消失）。
   - 反馈内容：**90 天**。
   - 举报：**谁报了谁、事由、次数**自最后一次举报起 **90 天**；**被举报人当时的最近 ≤10 条发言**自首次举报起 **90 天**清空。聊天**不逐条保存**——没有人举报就没有任何聊天内容被写下。
   - 封禁：限时封禁在到期后再 **30 天**删除；**永久封禁不自动删除**；每一条封禁 / 解封动作的审计留 **1 年**。
5. **日志事件**：为了排查故障与统计大致多少人用过，服务端会写一些事件记录（例如「谁在什么时候进了厅 / 躺下 / 起身 / 被拒」这类事件名与数字）。保留 3 天，**不含聊天内容、昵称、位置坐标或 IP**。
6. 谁能看：只有运维者。封禁决定会记一条审计。
7. **删除**：需要写信/联系，人工处理。而这里有个前提必须说清——**服务端不知道你是谁**。

### 8.3 第 7 条的成稿口径（照抄）

> 服务端**不知道你是谁**。我们没有你的姓名、邮箱、手机号、账号，从来没有过；**唯一能把这份数据与一个活人联系起来的线索，是你浏览器里的那个随机标识**。
>
> 所以「删除我的数据」只能人工处理：**需要写信/联系，人工处理**。
>
> - 你如果**还保留着**那个标识，我们就能定位到它，按你的要求删除。
> - 你如果**已经清掉**了，服务端那份记录与人的联系就已经断了，**也不需要你另行申请**：来源信息 90 天后自动清空，床位 30 天无访问后自动释放，聊天本来就不逐条保存。

最后一段不是修辞，是 §7 那条留存的直接推论：**「不申请也会被清掉」是成立的**。这比「没有自助入口」诚实，也比「支持删除」诚实。

## 9. 已知上限

| 上限 | 说明 | 什么时候回头 |
| :--- | :--- | :--- |
| **封禁只能延缓** | 清 cookie 换身份是零成本的。IP 是唯一硬杠杆，而共享 NAT（校园/公司/CGNAT）会误伤，手机切流量即绕过。**匿名身份下这是天花板**，不是缺陷清单里的一项 | 出现「必须真实拦截」的运营压力时，唯一的路是 L2 扩出用户持有型凭据（见 `backlog.md`） |
| 扩 L2 对封禁**几乎无用** | 任何需要当事人配合的凭据，攻击者都不出示 | 不要为了风控去上 passkey / 登录 |
| **重名在走动时分不出来** | 昵称不唯一、且可改（改名只发生在上连接之前，代价 = 一次刷新）。床上的人靠床号分辨，**正在走动的人没有编号**——同名的两个小人在走动时确实分不出，冒充成本为零。**处置不靠名字**：举报落 `target_user_id`、封禁按 user/ip、台账 `identity` 按身份反查，事后一定分得开（`../api/10-api-http.md` §3.3） | 出现「用名字冒充他人骚扰」的真实投诉时。届时唯一的路是给在场者一个可见的稳定标识，而床号只覆盖躺着/睡着的人 |
| UA 哈希不是匿名化 | §3.2 | — |
| 没有自助删除 | §8.3。DO 的 SQLite 没有面向用户的自助删除路径 | 出现真实请求且量大到人力扛不住时 |
| **反馈不会回复** | 没有工单状态、通知渠道与「谁来回」的承诺；面板上明说「不回复」。它能收、能看、能删，但不能答 | 出现「写了没人理」的真实抱怨且量大到需要回复时；届时要先定回复走哪里（公告 / 私信 / 邮件） |
| 前台与后台同域 | 后台页面壳是公开 HTML（无数据），数据接口靠 `sc_admin` cookie + 常量时间比较 | 出现第二个操作者或权限分级需求时（见 `../api/30-api-admin.md`） |
