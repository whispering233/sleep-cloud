# 插槽面板（slot panel）

**一句话**：一块**常驻的、可被内容占用的区**，挂在聊天面板下沿、铺满到屏底。由**输入会话状态**打开（`60-interaction-shell.md` §2），内容可插拔（快捷用语 / 类型文本 → 以后的统计 / 天气 / 日历）。

**几何、开关、动画、指针时序归 `60-interaction-shell.md`。** 本文只管**它是什么、里面放什么、内容有哪些红线**——这两件事变了才需要改这个文件。

## 1. 定位与边界

| | |
| :--- | :--- |
| **是** | 页面框架里的一格（`.app-shell` 网格的一行）：位置、尺寸、层叠顺序全由框架给定；一次只有一个占用者 |
| **不是** | 浮层 / 模态 / 遮罩 / 消息列表 / 世界的一部分。没有背景变暗、没有 `Esc` 语义、不做焦点陷阱、不做「点外面」的通用关闭 |
| **术语** | 中文一律写**插槽面板**；**禁用**「浮层 / 遮罩 / overlay / 浮动面板」 |

**几何上它确实挡住世界，这是职责不是修辞**：打字态世界不可见（§2），所以它盖住的那一块里**每一次点按都必须落在面板上**——不许漏进看不见的世界（漏法、以及为什么漏，见 `60-interaction-shell.md` §4）。别和上面禁用的「遮罩」混：这里说的是它自己占的那块要接住指针，不是背景变暗 + 焦点陷阱那一套。

## 2. 两种悬挂态

整个底部组合只有两种位置，由 **`composer` 状态**切换：`idle` 贴底；**非 idle**（`typing` / `report` / `reading`）贴到 HUD 下沿并让出下方整块给插槽面板。**焦点只是进入那个状态的入口之一**，不是状态本身（为什么不能拿焦点当状态：`60-interaction-shell.md` §2）。

**为什么不抬到键盘上沿**：那要求界面知道键盘多高，而键盘高在部分内核里根本测不出来（既不缩布局视口也不缩视觉视口，或两者一起缩导致差值归零）。挪到顶部后两边天然不重叠，**整条键盘高度链路消失**，包括「逐帧缩宿主 → 重建绘制缓冲 → 画布黑闪」那一族。

## 3. 区域与几何

- **位置**：`.app-shell` 网格的一行（打字态是 `1fr`，铺满到屏底）。
- **尺寸由 CSS 给**，不由 JS 量：两种态的 `grid-template-rows` 一换，面板与插槽各就各位。
- **不参与可用视口计算**：相机只扣 HUD 与聊天面板的实占（`60-interaction-shell.md` §1），插槽只是盖住世界。
- **层叠**：世界层之上、减光层（`tone-layer`，`z-index: 4`）之下 —— 三档明暗照旧整屏连续。
- **边框接缝**：两块拼成一整块，**谁在最上面谁拥有上圆角，下面的那块上沿不画边、只画下沿**。两块都画完整 1px 描边时，交界处会有两道线与两个圆角凹口。

## 4. 开关模型：输入会话状态

面板显隐 = `composer !== 'idle'`（`typing` 放输入辅助，`report` 放举报表单，`reading` 放类型文本）。**没有第二个触发源列表**——将来要加第二个内容源，加的是「另一个能让 `composer` 进非 idle 的入口」或新增一个状态值，而不是再挂一个旁路布尔。

| 动作 | 结果 | 说明 |
| :--- | :--- | :--- |
| 点输入行 / `GO` 床号 | 面板打开、组合贴顶 | 入口统一（任何可编辑控件聚焦） |
| 点面板空白 | 退场 | 画布被盖住时点不到世界，所以出口由面板自己给。**抬手（`click`）才退场，按下只 `preventDefault()`**（理由见 §5） |
| 点发送 | 退场 | 发出去的内容只在世界里以气泡出现（`../../AGENTS.md` 硬纪律 24）→ 必须让世界回来才看得见 |
| 点「收起」胶囊（动作行右端，typing 态才出现） | 退场 | **常驻可见出口**（`60-interaction-shell.md` I4） |
| 点 😀 切换键 | **退场** | emoji 与输入行共用同一行、原地替换；输入框被卸载 → 焦点对账判定「活跃元素不在面板内」→ 自动退场。**这是对的**：emoji 行不需要键盘，且发出去的气泡只在世界里可见 |
| 点快捷用语条目 | **不退场** | 只改草稿，不在世界里产生可见结果；同样 `preventDefault()` |
| 点私聊行尾的「举报」 | 进 `report` 态，内容换成举报表单 | 只在该行存在时可点（= 已选中某人）；`report` 下**快捷用语不可用**（同一时刻只有一个占用者） |
| 点动作行右端那颗阅读入口胶囊（书本图标，只在空闲态存在） | 进 `reading` 态，内容换成类型文本 | **唯一不由焦点进入的会话**：它不拉起键盘，所以状态由这一次点击自己写进去（§附「类型文本」）。非空闲态右端那一组被「收起」胶囊占住 → 与其它入口天然互斥 |
| 断线 | 退场 | 那一刻没有可发的东西，先把世界还给人 |

**开关不走键盘判定**，理由见 §2。系统的「收起键盘」手势不改变 `composer`：面板留着，出口仍是「收起」胶囊或面板空白——这正是状态机的好处（焦点没了也不影响状态可达）。

## 5. 动画与闪烁

- **两态瞬切，不做位移动画**（`60-interaction-shell.md` §3）：面板位置由网格行决定，没有位移、没有量高度、也没有任何逐帧布局。
- **退场是瞬切的；那 160ms 淡出画的是一块空盒子**（实测逐帧）：撤下 `data-open` 的那一帧，盒子就从 typing 的 `155..852 h=697` 换成 idle 的 `731..852 h=121`，内容同时卸掉（`children` 归 0）；之后 `opacity` 1.00 → 0.54 → 0.19 → 0 的渐变作用在这块空盒子上，而它与聊天面板几乎重合（同一网格行、只差 `translateY(-8px)`）、底色相同（都是 `secondary`），DOM 上又排在聊天面板之后 → 用户感知是「面板瞬消、世界立刻露出」。**所以「退场期间它还挡着」不成立**：那段底部是聊天面板在挡（命中拿到的是 `chat-panel`）。
- **`inert` 不是「还看得见就还吃点击」的保证**：`inert` 会让命中**跳过整棵子树**（实测 `elementFromPoint` 直接返回 `<canvas>`）。它只负责「不可 Tab、不被读屏读到」，而这两件事在关闭态本来就被 `visibility: hidden` 管住（内容也已卸掉）——可点性别指望它。
- **点面板空白：`pointerdown` 只 `preventDefault()`，退场挂在 `click`。** 按下就退场会把手指底下的盒子当场换成画布，而浏览器在手势收尾补发的兼容鼠标事件是**按抬手那一刻**做命中的——于是那一下变成一次从画布起手的 tap（`60-interaction-shell.md` §4 的红线）。`preventDefault()` 顺带保住输入框焦点（否则焦点先丢、对账先退场）。
- **没有任何 JS 定时器参与**：不需要监听 `transitionend` 做收尾（隐藏后内容留在那里，没有「拨掉」这一步）。
- 不用 `hidden` 做开关：`display: none` 过渡不了。用 `data-open` 切 `opacity` / `visibility`（`transition-behavior: allow-discrete`）。

**键盘仍有一件事**：iOS 聚焦时浏览器会平移视觉视口，`.app-shell` 需 `transform: translateY(offsetTop)` 把自己拉回屏幕。**只动 transform、不改尺寸**，不引起重建。

## 6. 内容契约

| 项 | 规则 |
| :--- | :--- |
| 形态 | React children，由**聊天面板**提供（因此内容天然拿得到写草稿的回调） |
| 尺寸 | 内容**不设**自己的高 / 宽 / 定位；撑满面板、自己滚动（`overscroll-behavior: contain`，别拖到宿主） |
| 层叠 | 内容不开第二层浮层，不盖 HUD 与聊天面板 |
| 互斥 | 同一时刻**只有一个占用者**（与门控行同一套心智） |
| 能力 | 只给窄接口：写草稿、请求关闭。不给世界句柄、不给相机、不给发送 |

## 7. 交互红线

1. **插槽内按钮必须 `pointerdown` 里 `preventDefault()`** —— 否则焦点被按钮拿走 → 焦点对账判定「活跃元素不在面板内」→ 退场 + 键盘收起 + 动作没发生。
2. **退场必须走 `exitComposer()`**，不要自己 `blur`：它是唯一出口（幂等、不看 `activeElement`）。
3. **面板不抢焦点**：出现时焦点必须还在输入行。
4. **`z-index` 不得 ≥ 4**（`tone-layer` 在上）。
5. **不许为关闭面板挂内存定时器**（`../../AGENTS.md` 硬纪律 6）。
6. **内容不许写死高度**：面板高度由网格给。
7. **可滚内容里的按钮钉在底部**：正文区自己滚（`overscroll-behavior: contain`），操作按钮排在它之后——不让按钮跟着正文滚出视野，也不许给按钮单独开浮层。

## 8. 可移除性

**删掉内容 → 面板变成一块空的深色区域**，其余行为不变（入口、状态机、世界取景都不依赖内容）。面板是长期方案，但不能变成拆不掉的地基。

## 9. 已知代价

- **打字时看不见世界与小人**（已确认接受：打字时不需要看世界）。
- **打字时输入框在屏幕顶部**：眼睛要在顶部与键盘之间移动。
- **面板高度受聊天面板高度影响**：提示条 / 私聊行出现或消失时插槽区重排一次（网格自己处理，无 JS）。
- **点了快捷用语再点发送 = 两次点击**：换来的是「填进去的内容看得见、可改」。
- **两态瞬切**：从屏底跳到 HUD 下沿没有过渡动画。
- **读类型文本时也看不见世界**：`reading` 沿用非空闲态几何，与打字是同一笔代价。

## 10. 本期不做

统计 / 天气 / 日历等第三个内容；第二个入口；插槽之间切换的过渡；面板内搜索 / 分页；**类型文本的多分类切换**（一期只取数据里的第一个分类，见 §附与 `backlog.md`）。

## 附：快捷用语（本期唯一内容）

**两列网格**、每条 44px 触摸目标、**上限 8 条**（第 9 条起要重新设计排布）。为什么是两列：贴顶后插槽面板能拿到约 370px，而单列 8 条要 432px（gap 8）/ 460px（gap 12）——放不下；两列在同样 gap 下只要 224px。

点一条 = **文本填进输入框**（替换当前草稿），不直接发送。

## 附：类型文本（第二个内容）

**是什么**：按「类型」分组的一组短文本（首期类型 = 冷笑话），抽一条读。它不是消息、不进协议、不发任何上行——纯本地阅读。**「冷笑话」只是第一个类型**：分类 id 不进 `composer`（那是会话，不是内容），一期取数据里的第一个分类；加分类只改数据与一个切换控件（§10）。

### 入口

动作行右端那一组里的**第四颗**（最右是齿轮，它左边是两颗「还没做」的占位入口：睡不着留言板 / 游戏，再左边是求签）：44×44 描边胶囊，**内联 SVG 书本图标**（`currentColor` 描边 1.5px、20×20 绘制区，与齿轮同一套画法——只写一个 `!` 会让按钮显得空）、`aria-label="随机阅读"`、外观同 `hud-settings` 家族。**只在空闲态出现**——非空闲态那一整组是「收起」胶囊，两者天然互斥，不需要额外判断。

### 状态与退出

| | |
| :--- | :--- |
| 状态 | `composer = 'reading'`（`60-interaction-shell.md` §2）。它**不拉起键盘**，所以是唯一不由 `focusin` 进入的会话：点胶囊自己写进去 |
| 几何 | 与非空闲态完全一致（面板贴 HUD、插槽铺满到屏底）。**读文本时看不见世界**，与打字是同一笔代价（§9） |
| 退出 | 收起胶囊 / 点面板空白 / 断线 / 焦点进输入框 → `idle`。**当前那一条保留**（回来还是它），重开面板**不自动抽签** |

### 版面

```text
┌─────────────────────────────┐
│ 　第一行首行缩进两字……        │ ← 正文：reading 档 16px / 行高 1.7
│ 　第二行……                  │
│                             │
│                       [ ⟳ ] │ ← 右下角；池抽干后同一位置换成「再看一遍」
└─────────────────────────────┘
```

| 项 | 规则 |
| :--- | :--- |
| 标签行 | **没有**。分类的显示名不出现在版面，只作插槽内容的 `aria-label`（读屏念得出、视觉不占位） |
| 正文 | **顶对齐**（不垂直居中：每条长短不一，居中会让文字每次跳一个位置）、**自己滚动**、`reading` 档 = **16px / 行高 1.7**（与输入框同号：读者的字不该比他自己打字的字还小）；**每行首行缩进 `2em`**，行间空一行（= 一个行高） |
| 按钮 | **钉在面板底部、右对齐**：正文区在它之前，长文本滚动时按钮不跑；先读完、再决定要不要下一条 |
| 随机按钮 | 44×44 描边胶囊 + 内联 SVG 循环箭头（**不写 `⟳` 字形**：Android / Windows 会把它回落成彩色 emoji，理由同齿轮），`aria-label="随机一条"` |
| 再看一遍按钮 | `hud-action` 文字胶囊。**与随机按钮互斥渲染**，不会同屏（池还在就有得抽） |

### 文本解析（纯函数，可单测）

| # | 规则 |
| :--- | :--- |
| 1 | **任何换行都只分一次行**：`\n` 与 `\n\n` 等价（数据包里两种混用，作者不该记「空几行才算分段」）；连续多个换行也只分一次 |
| 2 | 每行 trim、行尾空格去掉；trim 后为空的段落**丢弃** |
| 3 | **每行一个 `<p>`、每行都首行缩进** `2em`（CSS `text-indent`；**不塞全角空格**——塞字符会跟着复制走，字号一变缩进也不跟） |
| 4 | 行内空白折叠（默认行为）：行尾不留空格、也不为了对齐塞空格 |
| 5 | **不解析 Markdown / HTML / 链接**：文本一律作 React 文本节点渲染（不用 `dangerouslySetInnerHTML`，因而没有 XSS 面） |
| 6 | 读入校验：`text` 非空、≤ `TYPE_TEXT_MAX_LEN`、段落 ≤ `TYPE_TEXT_MAX_PARAS`；坏条目**只丢那一条**，不让一条脏数据打死整个面板 |

### 抽签

池 = 该分类里**不在 `seen`** 的条目。**所有抽签都排除当前条**（池里还有别的时）：否则「再看一遍」有 1/N 概率抽回正在看的那条，而那颗按钮的全部意义就是「给我换一篇」。

| 事件 | 结果 |
| :--- | :--- |
| 点阅读入口 | 面板当场打开（不等网络）。**有当前条 → 原样显示，不抽**；无当前条 → 抽一条（全流程唯一一次隐式抽签：首次总得显示点什么）；数据不在内存 → `loading` |
| 「随机」 | 抽一条 → 记进 `seen` → 写 `sc.read.seen` → 再判池空 |
| 「再看一遍」 | 清空**该分类**的 `seen` → 写回 → 立即抽一条（**排除当前条**）→ 回 `ready` |
| 「重试」 | 回 `loading`，重新取一次 |
| 退出 | `idle`；当前条留在 store |
| 页面重载 | 当前条从本地恢复（`sc.read.seen` 的 `current`），`seen` 不变 |

面板内部的四个态：

| 态 | 何时 | 正文 | 右下角 |
| :--- | :--- | :--- | :--- |
| `loading` | 打开时数据还不在内存 | 「取内容…」（弱提示） | 无 |
| `ready` | 池里还有没抽过的 | 当前条 | 随机 |
| `exhausted` | 池空（刚抽到最后一条 / 打开时已被 `seen` 覆盖完） | 当前条 | 再看一遍 |
| `error` | 取数失败（含 SPA 回退给了 HTML 那种） | 「内容没取到」（`alert` 墨色） | 重试 |

**数据只有 1 条时按钮显示「再看一遍」不用特判**：唯一那条一被抽到池就空了，是「池空」规则的自然结果。

### 数据与缓存

| 项 | 决定 |
| :--- | :--- |
| 文件 | `public/fun/type-texts.v1.json`——**静态资源直接给**（免费且不限量），不进 Worker 代码、不进任何接口 |
| 版本 | **版本号只在文件名里**（常量 `TEXT_PACK_VERSION` 是唯一来源），换内容必须改名；JSON 内的 `schema` 字段只表**形状**版本，与文件名是两回事 |
| 缓存 | `public/_headers` 给 `/fun/*` 加 `immutable`（同 `/audio/*`）；字节由浏览器 HTTP 缓存持有，**不进 `localStorage`**（`40-client-storage.md` §1.3） |
| 懒加载 | 第一次点阅读入口才 `fetch`，**模块级 promise 去重**；**成功结果缓存、失败不缓存**——否则「重试」永远失败 |
| 形状 | `{"schema":1,"categories":[{"id":"joke","label":"冷笑话","items":[{"id":"j1","text":"…"}]}]}`。`id` 手工编号、**改内容不改号**（改了 `seen` 就认不出同一条） |
| 自检 | 构建期单测直接校验这份文件自己合规（非空、每类条目 ≤ `TYPE_TEXTS_PER_CATEGORY`、每条长度与段数在限内）——不靠运行时兜底去兜我们自己的数据 |

### 已知代价

- **读文本时看不见世界**（同打字）。
- **首屏要等一次网络请求**：`loading` 只有一行弱提示，不做骨架屏（没有需求方）。
- **一轮之内不会重复**：想随手翻回上一条，只能等这轮抽完或按「再看一遍」。
- **换内容要发版**：`immutable` 下浏览器不会来问，所以文件名必须换版本号；后台管理是后期的事（`backlog.md`）。
- **一期只有一个分类**：多分类切换要有 UI 与「当前分类」记忆，现在没有需求方。
