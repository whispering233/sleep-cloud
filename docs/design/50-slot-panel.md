# 插槽面板（slot panel）

**一句话**：一块**常驻的、可被内容占用的区**，挂在聊天面板下沿、铺满到屏底。由**输入会话状态**打开（`60-interaction-shell.md` §2），内容可插拔（快捷用语 → 以后的统计 / 天气 / 日历）。

**几何、开关、动画、指针时序归 `60-interaction-shell.md`。** 本文只管**它是什么、里面放什么、内容有哪些红线**——这两件事变了才需要改这个文件。

## 1. 定位与边界

| | |
| :--- | :--- |
| **是** | 页面框架里的一格（`.app-shell` 网格的一行）：位置、尺寸、层叠顺序全由框架给定；一次只有一个占用者 |
| **不是** | 浮层 / 模态 / 遮罩 / 消息列表 / 世界的一部分。没有背景变暗、没有 `Esc` 语义、不做焦点陷阱、不做「点外面」的通用关闭 |
| **术语** | 中文一律写**插槽面板**；**禁用**「浮层 / 遮罩 / overlay / 浮动面板」 |

## 2. 两种悬挂态

整个底部组合只有两种位置，由 **`composer` 状态**切换：`idle` 贴底、`typing` 贴到 HUD 下沿并让出下方整块给插槽面板。**焦点只是进入那个状态的入口之一**，不是状态本身（为什么不能拿焦点当状态：`60-interaction-shell.md` §2）。

**为什么不抬到键盘上沿**：那要求界面知道键盘多高，而键盘高在部分内核里根本测不出来（既不缩布局视口也不缩视觉视口，或两者一起缩导致差值归零）。挪到顶部后两边天然不重叠，**整条键盘高度链路消失**，包括「逐帧缩宿主 → 重建绘制缓冲 → 画布黑闪」那一族。

## 3. 区域与几何

- **位置**：`.app-shell` 网格的一行（打字态是 `1fr`，铺满到屏底）。
- **尺寸由 CSS 给**，不由 JS 量：两种态的 `grid-template-rows` 一换，面板与插槽各就各位。
- **不参与可用视口计算**：相机只扣 HUD 与聊天面板的实占（`60-interaction-shell.md` §1），插槽只是盖住世界。
- **层叠**：世界层之上、减光层（`tone-layer`，`z-index: 4`）之下 —— 三档明暗照旧整屏连续。
- **边框接缝**：两块拼成一整块，**谁在最上面谁拥有上圆角，下面的那块上沿不画边、只画下沿**。两块都画完整 1px 描边时，交界处会有两道线与两个圆角凹口。

## 4. 开关模型：输入会话状态

面板显隐 = `composer === 'typing'`。**没有第二个触发源列表**——将来要加第二个内容源，加的是「另一个能让 `composer` 进 typing 的入口」或新增一个状态值，而不是再挂一个旁路布尔。

| 动作 | 结果 | 说明 |
| :--- | :--- | :--- |
| 点输入行 / `GO` 床号 | 面板打开、组合贴顶 | 入口统一（任何可编辑控件聚焦） |
| 点面板空白 | 退场 | 画布被盖住时点不到世界，所以出口由面板自己给 |
| 点发送 | 退场 | 发出去的内容只在世界里以气泡出现（`../../AGENTS.md` 硬纪律 24）→ 必须让世界回来才看得见 |
| 点「收起」胶囊（动作行右端，typing 态才出现） | 退场 | **常驻可见出口**（`60-interaction-shell.md` I4） |
| 点 😀 切换键 | **不退场** | emoji 与输入行共用同一行、原地替换；切换键在 `pointerdown` 里 `preventDefault()` 保住焦点 |
| 点快捷用语条目 | **不退场** | 只改草稿，不在世界里产生可见结果；同样 `preventDefault()` |
| 断线 | 退场 | 那一刻没有可发的东西，先把世界还给人 |

**开关不走键盘判定**，理由见 §2。系统的「收起键盘」手势不改变 `composer`：面板留着，出口仍是「收起」胶囊或面板空白——这正是状态机的好处（焦点没了也不影响状态可达）。

## 5. 动画与闪烁

- **两态瞬切，不做位移动画**（`60-interaction-shell.md` §3）：没有 `--dock-y`、没有 `translateY`、没有量高度。
- **退场用 `visibility` 离散过渡**（`transition-behavior: allow-discrete`），让「可点性」跟着视觉走完：面板还看得见的时候，点它绝不会穿到世界层（`60-interaction-shell.md` §4）。
- **没有任何 JS 定时器参与**：不需要监听 `transitionend` 做收尾（隐藏后内容留在那里，没有「拨掉」这一步）。
- 不用 `hidden` 做开关：`display: none` 过渡不了。用 `data-open` + `inert`（关的时候不可点、不可 Tab、不被读屏读到）。

**键盘仍有一件事**：iOS 聚焦时浏览器会平移视觉视口，`.app-shell` 需 `transform: translateY(offsetTop)` 把自己拉回屏幕。**只动 transform、不改尺寸**，不引起重建。

## 6. 内容契约

| 项 | 规则 |
| :--- | :--- |
| 形态 | React children，由**聊天面板**提供（因此内容天然拿得到写草稿的回调） |
| 尺寸 | 内容**不设**自己的高 / 宽 / 定位；撑满面板、自己滚动（`overscroll-behavior: contain`，别拖到宿主） |
| 层叠 | 内容不开第二层浮层，不盖 HUD 与聊天面板 |
| 互斥 | 同一时刻**只有一个占用者**（与门控行同一套心智） |
| 能力 | 只给窄接口：写草稿、请求关闭。不给世界句柄、不给相机、不给发送 |

## 7. 交互红线

1. **插槽内按钮必须 `pointerdown` 里 `preventDefault()`** —— 否则焦点被按钮拿走 → 焦点对账判定「活跃元素不在面板内」→ 退场 + 键盘收起 + 动作没发生。
2. **退场必须走 `exitComposer()`**，不要自己 `blur`：它是唯一出口（幂等、不看 `activeElement`）。
3. **面板不抢焦点**：出现时焦点必须还在输入行。
4. **`z-index` 不得 ≥ 4**（`tone-layer` 在上）。
5. **不许为关闭面板挂内存定时器**（`../../AGENTS.md` 硬纪律 6）。
6. **内容不许写死高度**：面板高度由网格给。

## 8. 可移除性

**删掉内容 → 面板变成一块空的深色区域**，其余行为不变（入口、状态机、世界取景都不依赖内容）。面板是长期方案，但不能变成拆不掉的地基。

## 9. 已知代价

- **打字时看不见世界与小人**（已确认接受：打字时不需要看世界）。
- **打字时输入框在屏幕顶部**：眼睛要在顶部与键盘之间移动。
- **面板高度受聊天面板高度影响**：提示条 / 私聊行出现或消失时插槽区重排一次（网格自己处理，无 JS）。
- **点了快捷用语再点发送 = 两次点击**：换来的是「填进去的内容看得见、可改」。
- **两态瞬切**：从屏底跳到 HUD 下沿没有过渡动画。

## 附：快捷用语（本期唯一内容）

**两列网格**、每条 44px 触摸目标、**上限 8 条**（第 9 条起要重新设计排布）。为什么是两列：贴顶后插槽面板能拿到约 370px，而单列 8 条要 432px（gap 8）/ 460px（gap 12）——放不下；两列在同样 gap 下只要 224px。

点一条 = **文本填进输入框**（替换当前草稿），不直接发送。
