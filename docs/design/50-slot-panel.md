# 插槽面板（slot panel）

**一句话**：一块**常驻的、可被内容占用的区**。由触发源打开，内容可插拔（快捷用语 → 以后的统计 / 天气 / 日历）。它**挂在聊天面板的下沿**：聊天面板留在屏幕底部时，插槽面板就是底部那一块的上半；聊天面板因打字挪到顶部时，插槽面板跟着跑到它下面。

## 1. 定位与边界

| | |
| :--- | :--- |
| **是** | 页面框架里的一格：位置、尺寸、层叠顺序全由框架给定；一次只有一个占用者 |
| **不是** | 浮层 / 模态 / 遮罩 / 消息列表 / 世界的一部分。没有背景变暗、没有 `Esc` 语义、不做焦点陷阱、不做「点外面」的通用关闭 |
| **术语** | 中文一律写**插槽面板**；**禁用**「浮层 / 遮罩 / overlay / 浮动面板」。它盖住画布只是布局结果，不是名字也不是目的 |

## 2. 两种悬挂态

整个底部组合（聊天面板 + 插槽面板）只有两种位置，**由输入行有没有焦点切换**：

```text
空闲（无焦点）                打字（有意点）
┌──────────────┐            ┌──────────────┐
│    HUD       │            │    HUD       │
├──────────────┤            ├──────────────┤
│              │            │  聊天面板     │  ← 挪到 HUD 下沿
│    世界      │            ├──────────────┤
│              │            │  插槽面板     │  ← 挂在聊天面板下沿
├──────────────┤            │              │
│  聊天面板     │            │   世界       │
└──────────────┘            └──────────────┘
                            ░░░░ 键盘 ░░░░
```

**为什么把整个组合挪到顶部**：初版是「聊天面板贴底并抬到键盘上沿」，那要求界面**知道键盘多高**——而键盘高在部分内核里根本测不出来（布局视口与视觉视口都不缩，或两者一起缩导致差值归零），输了键盘高度就是猜。挪到顶部后**两边天然不重叠**，界面**完全不再需要读键盘高度**。

## 3. 区域与几何

- **位置**：`.chat-panel` 的**绝对定位子元素**，`inset-inline: 0; inset-block-start: 100%` —— 贴在聊天面板**整块**下沿（不是输入行下沿：连接提示条 / 私聊目标行 / 床上动作行 / 动作行 / 门控行 / 输入行全在聊天面板里面，它们一起被让出去）。
- **高度** = 从聊天面板下沿到**可用视口下沿**。两个盒子都可能变（提示条只在断连时占位、私聊行只在有目标时出现），所以随变化重算。
- **不参与父容器的高度计算**（绝对定位、且不撑开 `.chat-panel`）→ **可用视口、世界取景、夹取一概不受影响**。
- **层叠**：世界层之上（DOM 里在 `.world-layer` 之后、且 `.chat-panel` 不是层叠上下文），`tone-layer`（`z-index: 4`）之下 —— 三档明暗照旧整屏连续，面板也会跟着变暗。
- **边框接缝**：两块拼成一整块，所以**谁在最上面谁拥有上圆角，下面的那块上沿不画边、只画下沿**。两块都同时画完整 1px 描边时，交界处会有两道线与两个圆角凹口，视觉上就割裂了。

## 4. 开关模型：触发源

**契约**：每个触发源提供一个 `active` 状态；**面板显示 = 任一触发源 `active`**；关掉 = 该源自己清 `active`。
**开和关必须由同一个源负责**，不写全局的「失焦即退场」——否则第二个触发源（统计按钮之类）打开时，用户点空白没有焦点可失，面板就关不掉。

**首版只有一个触发源：聊天输入行的焦点。**

| 动作 | 焦点 | 面板 | 依据 |
| :--- | :--- | :--- | :--- |
| 点输入行 | 得到 | **打开** | 唯一入口 |
| 点插槽面板空白 | **显式 `blurFocusedEditable()`** | 退场 | 画布被面板盖住 → 点不到画布，「点画布收键盘」那条通路在这一态不可达，所以出口必须由面板自己给 |
| 点发送 | **显式 `blurFocusedEditable()`** | 退场 | 发出去的内容只在世界里以气泡出现（`../../AGENTS.md` 硬纪律 24：不做消息列表、不做本地历史）→ 必须让世界回来才看得见自己说了什么。**不能靠「按钮抢焦点」这个浏览器差异**（Chromium 抢、Safari 可能不抢），必须显式 |
| 点 😀 切换键 | 不保焦点（自然失焦） | 退场 | emoji 行在输入行**原地**替换（`../../docs/ui/DESIGN.md` 的 `emote-panel`），不需要插槽面板；退了世界可见、气泡可见 |
| 点床号 / `GO` / 缩放档位 / 齿轮 | 自然失焦 | 退场 | 这些都是「看世界」的动作 |
| 点插槽内的**快捷用语**条目 | **保住**（`pointerdown` 里 `preventDefault()`） | **不退场** | 它只把文本填进输入框，不在世界里产生任何可见结果 |

一句话：**会在世界里产生可见结果的动作 → 退场；只改输入框内容的动作 → 不退。**

### 为什么是焦点驱动，不用键盘判定

键盘「弹没弹」在部分内核里根本测不出来（自研内核可能既不缩布局视口也不缩视觉视口），而焦点三个内核都可靠。焦点驱动的代价是「用户按系统手势收了键盘、焦点还在 → 面板留着」，出口由上一张表的「点空白」给出。

**连带收益**：整条链路上**不需要知道键盘高度**。面板的几何全部来自 HUD 与聊天面板的实占高度。

## 5. 动画与闪烁

**闪烁的根已随改造消失**：初版面板贴底、必须跟着键盘逐帧抬高，于是 `.app-shell` 的 `inset-block-end` 每帧变 → 宿主矩形每帧变 → `Scale.NONE` 下 `ResizeObserver` 每帧调一次 `scale.resize(宽×高×DPR)`（DPR 上限 3，393×852 约 3M 像素）→ 绘制缓冲被重建、内容被清空、下一帧才重画。

改造后：`.app-shell` 是 `position: fixed; inset: 0`，靠**布局视口**定位；实测（宿主模拟器，真 Chrome，见 `test.md`）键盘弹起前后布局视口只因为地址栏变化缩了 24px，**并不因键盘而缩**。界面不再写 `inset-block-end`，画布尺寸就与键盘无关。

| 时刻 | 做什么 |
| :--- | :--- |
| 打开 | 聊天面板从贴底挪到 HUD 下方，插槽面板跟着出现在它下面；`bottom` 占位大小保持与空闲态一致（只是从屏幕底挪到面板下沿），所以**夹取与 `follow` 都不需要重算** |
| 关闭 | 反方向同一条过渡 |
| 旋屏 / 真实尺寸变化 | 按当时的宿主尺寸重建 |

**动画用 CSS，不引动画库。** 两处过渡（聊天面板位移、插槽面板淡入淡出）只动 `transform` 与 `opacity`，不触发布局；中断（键盘连续开合、焦点来回）由 CSS 自然重定向，比 JS 动画自己写打断简单。**没有任何 JS 定时器参与**：不需要监听 `transitionend` 去做收尾，因为隐藏后内容只是留在那里、没有「拨掉」这一步要做（不像 `Toast` 需要自己卸下）。

**不再用 `hidden` 做开关**：`hidden` 走 Tailwind preflight 的 `display:none !important`，过渡不了。改用 `inert`（关的时候不可点、不可 Tab、不被读屏读到，Chromium 102+ / Safari 15.5+）+ `opacity` / `transform`。

**键盘仍有一件事**：iOS 聚焦时浏览器会平移视觉视口（`visualViewport.offsetTop > 0`），`.app-shell` 仍需 `transform: translateY(offsetTop)` 把它拉回屏幕。这条**只动 transform、不改尺寸**，不会引起重建。

## 6. 内容契约

| 项 | 规则 |
| :--- | :--- |
| 形态 | React children，由**聊天面板**提供（因此内容天然拿得到写草稿的回调） |
| 尺寸 | 内容**不设**自己的高 / 宽 / 定位；撑满面板、自己滚动（`overscroll-behavior: contain`，别拖到宿主） |
| 层叠 | 内容不开第二层浮层，不盖 HUD 与聊天面板 |
| 互斥 | 同一时刻**只有一个占用者**（与门控行同一套心智） |
| 能力 | 只给窄接口：写草稿、请求关闭。不给世界句柄、不给相机、不给发送 |

## 7. 交互红线

1. **插槽内按钮必须 `pointerdown` 里 `preventDefault()`** —— 否则焦点被按钮拿走 → 面板退场 + 键盘收起 + 动作没发生。
2. **发送与点空白用显式 `blurFocusedEditable()`**，不依赖「点别处 = 失焦」的浏览器默认（那个默认在画布上被 Phaser `preventDefault()` 掐掉了，在 iOS 上也一向不可靠）。
3. **面板不抢焦点**：出现时焦点必须还在输入行。
4. **`z-index` 不得 ≥ 4**（`tone-layer` 在上）。
5. **不许为关闭面板挂内存定时器**（`../../AGENTS.md` 硬纪律 6）。
6. **内容不许写死高度**：面板高度由框架算。

## 8. 可移除性

**删掉触发源 → 面板永不出现**，应用退回「没有插槽面板」的行为（键盘那条路照旧）。这条是刻意的：面板是长期方案，但不能变成拆不掉的地基。

## 9. 已知代价

- **面板开着时看不见世界与小人**（已确认接受：打字时不需要看世界）。
- **打字时输入框在屏幕顶部**：这是「界面不再读键盘高度」的代价——眼睛要在顶部与键盘之间移动。
- **面板高度受聊天面板高度影响**：提示条 / 私聊行出现或消失时面板重排一次。
- **点了快捷用语再点发送 = 两次点击**：换来的是「填进去的内容看得见、可改」。
- **开关那一下相机可能微调**：占位大小不变，但位置变了（屏幕底 → 面板下沿）。真机观感待确认。

## 10. 本期不做

统计 / 天气 / 日历等第二个内容；第二个触发源；插槽之间切换的过渡；面板内搜索 / 分页。

## 11. 验收判据

#### 本地可验（手机视口 + 生产代码）

| # | 判据 |
| :--- | :--- |
| 1 | 点输入行 → 聊天面板挪到 HUD 下方、插槽面板出现在它下面；输入行、动作行、HUD 仍可见可点 |
| 2 | 整段开合过程中画布 `canvas.width` / `canvas.height` 与可用视口**不受键盘影响**（键盘弹起时不去读键盘高度） |
| 3 | 点快捷用语 → 文本进输入框；`document.activeElement` 仍是输入框；面板与键盘都不动 |
| 4 | 点发送 → 组合退回底部；退场动画通过 `transitionend` 收尾，全程无定时器 |
| 5 | 点面板空白 → 焦点离开输入框、面板退场 |
| 6 | 两块面板交界处**只有一条线、无圆角凹口**（上圆角归上面那块、下圆角归下面那块） |
| 7 | 拖动 / 捏合在面板内不改变世界（事件到不了画布） |

**只能在真机得结论**：真手指点按节奏、键盘动画期间观感、iOS 的视觉视口 pan。
