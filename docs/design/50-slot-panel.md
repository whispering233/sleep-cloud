# 插槽面板（slot panel）

**一句话**：顶部 HUD 与底部聊天面板之间那一块区域，是一块**常驻的、可被内容占用的区**。由触发源打开，内容可插拔（快捷用语 → 以后的统计 / 天气 / 日历）。

## 1. 定位与边界

| | |
| :--- | :--- |
| **是** | 页面框架里的一格：位置、尺寸、层叠顺序全由框架给定；一次只有一个占用者 |
| **不是** | 浮层 / 模态 / 遮罩 / 消息列表 / 世界的一部分。没有背景变暗、没有 `Esc` 语义、不做焦点陷阱、不做「点外面」的通用关闭 |
| **术语** | 中文一律写**插槽面板**；**禁用**「浮层 / 遮罩 / overlay / 浮动面板」。「面板盖住画布」只是副作用描述（§4），不是名字也不是目的 |

## 2. 区域与几何

- **位置**：`.chat-panel` 的**绝对定位子元素**，`inset-inline: 0; inset-block-end: 100%` —— 贴在聊天面板**整块**上沿（不是输入行上沿：连接提示条 / 私聊目标行 / 床上动作行 / 动作行 / 门控行 / 输入行全在聊天面板里面，它们一起被让出来）。
- **高度** = `shell 高 − HUD 高 − 聊天面板高`，由面板自己测量后写成一个 inline px。三个盒子都随内容变化（提示条只在断连时占位、私聊行只在有目标时出现、键盘弹起时 shell 变矮），所以随变化重算。
- **不参与父容器的高度计算**（绝对定位、且不撑开 `.chat-panel`）→ **可用视口、世界取景、夹取一概不受影响**。
- **层叠**：世界层之上（DOM 里在 `.world-layer` 之后、且 `.chat-panel` 不是层叠上下文），`tone-layer`（`z-index: 4`）之下 —— 三档明暗照旧整屏连续，面板也会跟着变暗。

## 3. 开关模型：触发源

**契约**：每个触发源提供一个 `active` 状态；**面板显示 = 任一触发源 `active`**；关掉 = 该源自己清 `active`。
**开和关必须由同一个源负责**，不写全局的「失焦即退场」——否则第二个触发源（统计按钮之类）打开时，用户点空白没有焦点可失，面板就关不掉。

**首版只有一个触发源：聊天输入行的焦点。**

| 动作 | 焦点 | 面板 | 依据 |
| :--- | :--- | :--- | :--- |
| 点输入行 | 得到 | **打开** | 唯一入口 |
| 点插槽面板空白 | **显式 `blurFocusedEditable()`** | 退场 | 画布被面板盖住 → 点不到画布，「点画布收键盘」那条通路在这一态不可达，所以出口必须由面板自己给 |
| 点发送 | **显式 `blurFocusedEditable()`** | 退场 | 发出去的内容只在世界里以气泡出现（`../../AGENTS.md` 硬纪律 24：不做消息列表、不做本地历史）→ 必须让世界回来才看得见自己说了什么。**不能靠「按钮抢焦点」这个浏览器差异**（Chromium 抢、Safari 可能不抢），必须显式 |
| 点 😀 切换键 | 不保焦点（自然失焦） | 退场 | emoji 行在输入行**原地**替换（`../../docs/ui/DESIGN.md` 的 `emote-panel`），不需要插槽面板；退了世界可见、气泡可见 |
| 点床号 / `GO` / 缩放档位 / 齿轮 | 自然失焦 | 退场 | 这些都是「看世界」的动作 |
| 点插槽内的**快捷用语**条目 | **保住**（`pointerdown` 里 `preventDefault()`） | **不退场** | 它只把文本填进输入框，不在世界里产生任何可见结果 |

一句话：**会在世界里产生可见结果的动作 → 退场；只改输入框内容的动作 → 不退。**

### 为什么是焦点驱动，不用键盘判定

键盘「弹没弹」在部分内核里根本测不出来（自研内核可能既不缩布局视口也不缩视觉视口），而焦点三个内核都可靠。焦点驱动的代价是「用户按系统手势收了键盘、焦点还在 → 面板留着」，出口由上一张表的「点空白」给出。

**连带收益**：整条链路上**不需要知道键盘高度**。面板的几何全部来自 HUD 与聊天面板的实占高度。

## 4. 打开期间的世界：冻结

**闪烁的根**是画布尺寸变化：`Scale.NONE` 下每帧 `ResizeObserver` 都调一次 `scale.resize(宽×高×DPR)`（DPR 上限 3，393×852 约 3M 像素）——绘制缓冲被重建、内容被清空，下一帧才重画。键盘动画逐帧触发，就是逐帧重建。

所以：

| 时机 | 做什么 |
| :--- | :--- |
| 打开 | `WorldHandle.setSlotOpen(true)`：**画布尺寸冻结**（`resizeToHost` 早退，保留打开前的像素尺寸，只被 `.app-shell` 裁掉底部）、**相机冻结**（夹取与 `follow` 都不跑，用户在打开前的滚屏值就是最终值） |
| 关闭 | `setSlotOpen(false)` → **立刻** `resizeToHost()` 一次（一次全屏缓冲重建）→ **然后**才淡出面板。顺序不能倒：那一次重建必须落在面板仍然不透明的时刻 |
| 旋转屏幕 / 真实尺寸变化 | 冻结期间的变化**丢弃**；解冻时按当时的尺寸重建 |

因此**进 / 退场动画不承担任何遮挡责任**，时长按观感定即可，不许用定时器去猜键盘动画长度。代价与收益分开看：重建次数从「每帧一次」降为「每次退场一次」，面板只是顺便把它盖住。

**软键盘那一层不变**：`.app-shell` 的 `inset-block-end` 仍由 `visualViewport` 写成（`../ui/DESIGN.md`「软键盘」），输入行照样抬到键盘上沿；插槽面板跟着缩。

## 5. 内容契约

| 项 | 规则 |
| :--- | :--- |
| 形态 | React children，由**聊天面板**提供（因此内容天然拿得到写草稿的回调） |
| 尺寸 | 内容**不设**自己的高 / 宽 / 定位；撑满面板、自己滚动（`overscroll-behavior: contain`，别拖到宿主） |
| 层叠 | 内容不开第二层浮层，不盖 HUD 与聊天面板 |
| 互斥 | 同一时刻**只有一个占用者**（与门控行同一套心智） |
| 能力 | 只给窄接口：写草稿、请求关闭。不给世界句柄、不给相机、不给发送 |

## 6. 交互红线

1. **插槽内按钮必须 `pointerdown` 里 `preventDefault()`** —— 否则焦点被按钮拿走 → 面板退场 + 键盘收起 + 动作没发生。
2. **发送与点空白用显式 `blurFocusedEditable()`**，不依赖「点别处 = 失焦」的浏览器默认（那个默认在画布上被 Phaser `preventDefault()` 掐掉了，在 iOS 上也一向不可靠）。
3. **面板不抢焦点**：出现时焦点必须还在输入行。
4. **`z-index` 不得 ≥ 4**（`tone-layer` 在上）。
5. **不许为关闭面板挂内存定时器**（`../../AGENTS.md` 硬纪律 6）。
6. **内容不许写死高度**：面板高度由框架算。

## 7. 可移除性

**删掉触发源 → 面板永不出现**，应用退回「没有插槽面板」的行为（键盘那条路照旧）。这条是刻意的：面板是长期方案，但不能变成拆不掉的地基。

## 8. 已知代价

- **面板开着时看不见世界与小人**（已确认接受：打字时不需要看世界）。
- **退场那一次重建目前看得见（未修）**。§4 规定「先重建、再淡出」，实现里只有两个动作：`setSlotOpen(false)` 里直接 `resizeToHost()`，以及 `SlotPanel` 的 `hidden` 同一帧 `display:none`——**没有做时序**。宿主模拟器（章节与配方见 `build.md` §7）实测：键盘收起时画布**连重建 2 次**、且 **2 次都发生在面板 `hidden` 之后**（探头：`MutationObserver` 盯 `canvas.width/height` 与 `.slot-panel.hidden`）。可见后果是键盘滑出去那几十毫秒里，世界被压成一条、下面露出厅外底色（`screenrecord` 逐帧可重现）。修法见 `backlog.md`「退场时画布重建早于面板遮挡」。
- **键盘高度在部分内核里仍旧测不出来**（Via 走 CSS 抬升、自研内核可能毫无信号）。焦点驱动让这条链路不依赖它；键盘在界面侧现在只剩一件事（把外壳抬到键盘上沿），原来那套「按键盘高度做相机补偿」的规则已随实现一起删除。
- **面板高度随提示条 / 私聊行变化**：那几行出现或消失时面板重排一次（不动画布）。
- **点了快捷用语再点发送 = 两次点击**：换来的是「填进去的内容看得见、可改」。

## 9. 本期不做

统计 / 天气 / 日历等第二个内容；第二个触发源；插槽之间切换的过渡；面板内搜索 / 分页。

## 10. 验收判据

#### 本地可验（手机视口 + 生产代码）

| # | 判据 |
| :--- | :--- |
| 1 | 点输入行 → 面板出现；输入行、动作行、HUD 仍可见可点 |
| 2 | 面板打开期间画布 `canvas.width` / `canvas.height` **一次都不变**（冻结的直接证据） |
| 3 | 点快捷用语 → 文本进输入框；`document.activeElement` 仍是输入框；面板与键盘都不动 |
| 4 | 点发送 → 面板退场；退场前那一次画布尺寸变化发生在面板不透明度为 1 的帧 |
| 5 | 点面板空白 → 焦点离开输入框、面板退场 |
| 6 | 退场后相机滚屏值**精确等于**打开前的值 |
| 7 | 拖动 / 捏合在面板内不改变世界（世界被盖住，且事件到不了画布） |

**只能在真机得结论**：真手指点按节奏、键盘动画期间观感、低端机一次重建的可见时长。
