# 接口设计：HTTP

## 1. 接口清单

| 方法 | 路径 | 用途 | 幂等 |
| :--- | :--- | :--- | :--- |
| GET | `/api/me` | 读取当前会话（无会话则签发匿名会话）；**厅满时返回 `2002`** | 是 |
| POST | `/api/age-confirm` | 提交 18 岁自述确认 | 是 |
| POST | `/api/nickname` | 设置昵称 | 是 |
| GET | `/api/ws` | WebSocket 升级（进入大厅） | — |
| GET | `/api/health` | 部署冒烟检查 | 本节 |

`GET /api/health` 不返回任何业务数据，前端不调用：它只用来确认「静态资源之外的路由确实落到了 Worker」。

**没有的接口**：注册、登录、退出、找回床位、删除账号；以及**厅列表与切换厅**（只有一个厅，见 §4）。
**位置服务**：路径里**不带厅标识**——厅的标识是服务端常量（`HALL_ID`），不是 URL 的一部分。

## 2. 匿名会话的建立

| 时机 | 行为 |
| :--- | :--- |
| 无 cookie | 签发新的匿名会话（昵称为空、自述位为假） |
| cookie 验签失败 | 视为无 cookie，静默签发新的（返回 `1001`，前端无需处理） |
| cookie 有效 | 直接返回会话内容（含昵称、自述位） |

会话内容只有三项：**用户标识、昵称、18 岁自述位**（见 `api-public.md` §2.2）。**没有任何时区信息、没有厅标识**：厅时区概念整体删除，厅只有一个所以路由用常量。

### 2.1 入场时序（昵称从哪来）

**昵称由用户在入场层自己输入**，没有其他来源（没有登录、没有第三方资料、没有默认名）。

| 步 | 谁 | 做什么 | 会话 cookie 的变化 |
| :--- | :--- | :--- | :--- |
| 1 | 浏览器 | 打开页面，`GET /api/me` | 无 cookie → 服务端**签发新会话**（昵称为空） |
| 2 | 浏览器 | 入场层展示：昵称输入框、18 岁自述勾选（**只有这两项**） | — |
| 3 | 浏览器 | `POST /api/age-confirm` | 把自述位写进会话，**重签并回写 cookie** |
| 4 | 浏览器 | `POST /api/nickname` | 校验通过后把**昵称写进会话**，重签并回写 cookie |
| 5 | 浏览器 | `GET /api/ws` 升级 | **握手时从 cookie 读出昵称**，写入连接附加数据，入厅广播带名字 |

**厅满（`2002`）在第 1 步就能知道**：`/api/me` 会去问一次厅（对象还没被唤醒就顺带唤醒它），触顶且没有可认领的床时返回 `2002`，入场层直接显示「这个大厅满了」——**不让人先建连再被踢**（浏览器的 WebSocket API 读不到升级失败时的响应体）。

**布局版本也在第 1 步下发**：客户端拿它与自己编译时的 `LAYOUT_VERSION` 比对，不一致就提示刷新页面（几何是程序化生成的，见 `config.md` §1）。

### 2.2 昵称只在建连前设置或修改

入场层**每次进入大厅前都出现**；会话已完善时它呈现为「预填 + 一键继续」，用户不重新输入也能过。

这条不是交互洁癖，而是协议简化：**因为改名永远发生在建立连接之前，协议里就不需要「名字变更」的下行消息**（`join` 携带名字，`state` 不携带名字）。代价是：

| 影响面 | 表现 |
| :--- | :--- |
| 改名者自己 | 下次进入即为新名字（握手时从 cookie 读出） |
| 在本厅已连接的其他客户端 | 名字要等到他们自己下一次重新进入（拉新快照）才刷新 |
| 他若已认领床位且当前是睡痕 | 服务端已同步更新床位上的昵称快照，但**别人屏幕上那条睡痕的名字仍是旧的**，直到对方刷新快照 |

**这是一个已知且故意接受的延迟**：改名是低频动作，被影响的是「别人屏幕上一条睡痕的名字」，代价远低于为此增加一种协议消息类型。

## 3. 接口详情

### 3.1 GET /api/me

| 响应字段 | 是否必选 | 数据类型 | 取值范围 | 备注 |
| :--- | :--- | :--- | :--- | :--- |
| userId | 是 | string | — | 不透明标识，供前端区分「自己」 |
| nickname | 是 | string | 0~16 字符 | 未设置时为空串 |
| ageConfirmed | 是 | boolean | — | 是否已完成 18 岁自述 |
| needsNickname | 是 | boolean | — | 是否需要先设昵称才能进入 |
| layoutVersion | 是 | string | 如 `dorm-1` | 布局版本号；与前端编译期常量不一致时应提示刷新 |

| code | 场景 |
| :--- | :--- |
| `"0"` | 成功（首次访问没有 cookie 时也是这个：直接签发新会话） |
| `"1001"` | cookie 存在但验签失败：已静默签发新会话，**`data` 里就是那个新会话**，前端可以直接用 |
| `"2002"` | **厅满**：已到最后一档且没有可认领的床。`data` 仍带会话内容（入场层显示提示） |

```json
{
    "code": "0",
    "msg": "success",
    "data": {
        "userId": "u_7f3a91",
        "nickname": "小明",
        "ageConfirmed": true,
        "needsNickname": false,
        "layoutVersion": "dorm-1"
    }
}
```

### 3.2 POST /api/age-confirm

| 请求字段 | 是否必选 | 数据类型 | 取值范围 | 备注 |
| :--- | :--- | :--- | :--- | :--- |
| confirmed | 是 | boolean | 必须为 true | 必须显式为 true 才记录 |

| code | 场景 |
| :--- | :--- |
| `"0"` | 成功 |
| `"1002"` | 没有显式传 `confirmed: true` |
| `"1001"` | 会话失效（前端重新拉取 `/api/me` 即可） |

**注意**：这是**自述**，不是核验。服务端只记录布尔值，不收集任何身份材料。

### 3.3 POST /api/nickname

| 请求字段 | 是否必选 | 数据类型 | 取值范围 | 备注 |
| :--- | :--- | :--- | :--- | :--- |
| nickname | 是 | string | 1~16 字符 | 首尾空白会被去除；剥离控制字符；经内容过滤的**检测**入口（命中即拒绝，不写入会话） |

| code | 场景 |
| :--- | :--- |
| `"0"` | 成功 |
| `"1004"` | 昵称长度不在 1~16 之间（去空白后为空也算） |
| `"1005"` | 昵称命中敏感词 |
| `"1001"` | 会话失效 |

**不再接收时区**：旧版本允许在设置昵称时上报本地时区并返回 `1006`，随厅时区概念一起删除（`1006` 已从错误码表移除）。

**允许重名。** 界面上以「床号 + 昵称」区分，不做唯一性检查。前端**不要用 `maxlength` 自己藏起越界**：长度由服务端判定，界面上给可恢复提示，用户能立刻改正。

**改名不需要跨对象调用**：新昵称写入会话 cookie（供在场广播）；已认领的床位上那个 `owner_name` 快照**在下一次上床时刷新**（首次认领、再次躺下、从睡痕恢复都会刷新）。空床不显示名字，所以滞后无害。

### 3.4 GET /api/ws

WebSocket 升级入口，详见 `20-api-ws.md` §1。**升级前的前置校验**（任一不通过就不升级、直接返回 JSON）：

| code | 场景 |
| :--- | :--- |
| `"1001"` | 没有会话或验签失败 |
| `"1002"` | 未完成 18 岁自述 |
| `"1003"` | 未设置昵称 |

### 3.5 GET /api/health

返回 `{ "code": "0", "msg": "success", "data": { "status": "ok" } }`。用于部署冒烟与本地探活（例如后台起服务后用 `curl` 轮询它，避免前台阻塞）。

## 4. 不需要接口的部分

| 项 | 为什么不需要 HTTP 接口 |
| :--- | :--- |
| 在线人数、床位数、厅内现状 | 由 WebSocket 快照与增量事件下发（`bedCount`、`online`、`resize`） |
| 床位占用情况 | 同上（快照里带归属位图与人列表） |
| 认领/释放床位 | 由 WebSocket 的「躺下」「起身」意图隐式完成 |
| 聊天、私聊、表情 | 全部走 WebSocket |
| **厅列表 / 切换厅** | **只有一个厅**：连「选哪个厅」这个概念都不存在，接口与入口一起删除（见 `00-api-index.md`） |
