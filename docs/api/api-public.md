# 公共约定

## 1. 传输

| 项 | 约定 |
| :--- | :--- |
| 协议 | HTTPS（含 WSS）。平台默认提供，无需自建证书 |
| 同源 | 前端与接口同源。**因此会话 cookie 自动随 WebSocket 握手发送，不需要令牌交换、不需要跨域头** |
| 编码 | 请求与响应体均为 JSON（`Content-Type: application/json`）；WebSocket 消息体为 JSON 文本帧 |

## 2. 会话

| 项 | 约定 |
| :--- | :--- |
| 形式 | 服务端签发的**签名 cookie**（HMAC SHA-256），HttpOnly |
| 签发时机 | 首次访问时自动签发，不需要注册流程 |
| 内容 | 用户标识 + 所属厅标识 + **昵称** + 本地时区 + 18 岁自述位 + 该厅中的床位号（可为空） |
| 有效期 | 长期有效（会话持续刷新）；密钥轮换会使现有会话失效 |
| 客户端职责 | 不需要读取或解析 cookie；不需要在请求里带任何身份信息 |

**服务端不接受任何客户端自报的身份。** 用户标识、厅归属、床位归属全部来自签名 cookie 或服务端状态。

### 2.1 为什么昵称必须放在会话里

入场的顺序是「先入场、后认领床位」（见 `../design/00-master-design.md`）。这意味着：

- 一个刚进厅、还没躺下的人，**数据库里没有任何属于他的行**
- 但其他人必须能立即看到他的名字（入口处站着一个小人）

所以昵称必须在会话里（服务端签发、防篡改、不保密）。等他在某张床上躺下、完成认领后，昵称同时写入那张床的 `owner_name` 快照——这样做不是为了当前在线的他，而是为了**他离线后留下的睡痕仍然显示名字**（离线者没有连接可以读出昵称）。

同一个昵称会存在两处，职责不同：

| 位置 | 服务于 | 生命周期 |
| :--- | :--- | :--- |
| 会话 cookie | 在场者的入厅广播（包括还没躺下的人） | 随会话 |
| `bed.owner_name` | 离线者（睡痕）的名字显示 | 随床位归属 |

## 3. 公共请求头

| 头 | 是否必选 | 说明 |
| :--- | :--- | :--- |
| `Content-Type` | 是（有请求体时） | `application/json` |
| `Cookie` | 自动 | 由浏览器同源策略自动携带，前端无需手工设置 |
| `Accept-Language` | 否 | 仅用于文案语言，不影响业务 |

第一版不做接口版本号（没有外部调用方）。

## 4. 公共响应体结构

| 字段 | 是否必选 | 数据类型 | 取值范围 | 备注 |
| :--- | :--- | :--- | :--- | :--- |
| code | 是 | string | 见 `error-code.md` | 错误码，默认: `"0"` |
| msg | 是 | string | 见 `error-code.md` | 错误码对应说明信息，默认: `"success"` |
| data | 否 | object | — | 响应数据。成功时按各接口定义；失败时通常为空 |

```json
{
    "code": "0",
    "msg": "success",
    "data": {}
}
```

**HTTP 状态码约定**：业务错误统一返回 HTTP 200，错误语义由 `code` 承载。仅当请求本身不合法（格式错误、方法不允许、路由不存在）时使用非 200 状态码。

## 5. WebSocket 消息公共结构

所有 WebSocket 消息都是 JSON 对象，**必须带 `t` 字段表示消息类型**。

| 方向 | 形态 |
| :--- | :--- |
| 上行（客户端 → 服务端） | `{ "t": "...", ... }` —— **只允许表达意图** |
| 下行（服务端 → 客户端） | `{ "t": "...", ... }` —— 表达服务端认定的事实 |

**上行消息中的任何坐标、床位号、身份都只是「意图声明」，服务端有权校验并拒绝。** 下行消息中的状态是唯一事实。

## 6. 时间

| 项 | 约定 |
| :--- | :--- |
| 服务端内部 | 一律使用 UTC 时间戳 |
| 下发给客户端的时间 | epoch 毫秒 |
| 客户端本地时区 | 建立连接时上报一次（IANA 时区名），仅用于与个人有关的时间；**不参与厅的昼夜计算** |
| 客户端上报时间 | 一律不信任 |

## 7. 限制

| 项 | 值 | 说明 |
| :--- | :--- | :--- |
| 上行消息频率 | 5 条/秒/连接 | 超出丢弃并返回限流错误 |
| 昵称长度 | 1~16 字符 | 超长拒绝 |
| 聊天消息长度 | 1~200 字符 | 超长截断或拒绝，见接口文档 |
| 占位符 | — | — |
